Ancestry-specific single-step SNPBLUP

The general capability is ancestry-aware genomic prediction. Its native single-step model is ancestry-specific ssSNPBLUP, with ANCESTRY_UNCOR and ANCESTRY_COR covariance modes and optional reference-ancestry local ancestry proportion (LAP). Livestock breed origin is one application.

This is a naming update to the existing implementation. Covariance definitions, centering, parameter order, fixed pedigree scale, numerical defaults, score/MCSE checks and both prediction/PEV equation gates are unchanged. R fitting remains deferred. Existing BOA/LBP names, examples, native symbols and report fields remain supported as compatibility aliases.

YAML names and compatibility

Primary name Accepted legacy alias
type: ancestry type: boa
mode: ANCESTRY_UNCOR mode: BOA_UNCOR
mode: ANCESTRY_COR mode: BOA_COR
formulation: ss_snp_ancestry formulation: ss_snp_boa
lap: lbp:
reference_ancestry: inside LAP reference_breed: inside LBP
ancestry: in a selected PEV contrast breed:
component: lap component: lbp
Founder CSV individual,ancestry Founder CSV individual,breed

Primary and legacy spellings may be mixed across settings, but two aliases for the same setting must not both be supplied. Such duplicates fail explicitly; there is no precedence rule that could silently select a different model. Reference population names are user-defined identities and are never rewritten.

The following fragment shows the naming; use the complete linked examples for all inputs and covariance declarations:

model:
  random:
    genetic:
      type: ancestry
      mode: ANCESTRY_COR
      group: individual
      pedigree: A
      ancestry: phase
      partial_pedigree:
        founders: founders.csv
        covariances: {populationA: KA, populationB: KB}
      genomic_residual: {diagonal: 0.05}
      components:
        snp: {markers: all, covariance: Sigma}
      lap:
        reference_ancestry: populationB
        covariance: Omega
execution:
  formulation: ss_snp_ancestry
  solver: pcg
  sparse_backend: cholmod
  preconditioner: qnn_reuse

Complete runnable examples:

  • Ancestry COR, fixed covariance (source-checkout reference: ../tools/examples/model_yaml/ancestry-cor-fixed.yml).
  • Partial ancestry UNCOR with reference LAP (source-checkout reference: ../tools/examples/model_yaml/ancestry-partial-lap.yml).

The examples reuse the existing small livestock fixtures. Those population labels and values are preserved; the naming update does not invent human or plant data. The original boa-*.yml examples remain executable compatibility references.

Native API and standalone contract

Include greml/single_step_ancestry.hpp, or its multitrait, longitudinal, partial pedigree and REML forwarding headers. Primary names include SingleStepAncestryMode, SingleStepAncestryMultitraitDesign, SingleStepPartialAncestryModel, PartialAncestryOptions, ReferenceLapOptions, fit_single_step_partial_ancestry and fit_single_step_partial_ancestry_reml.

Types are aliases of the original native types. Functions forward to the same BOA implementations with the same defaults. The original symbols and data-member layouts are retained for ABI and source compatibility. Ancestry accessors expose existing storage without additional state:

#include <greml/single_step_ancestry.hpp>
greml::PartialAncestryOptions options;
options.founder_ancestries() = {0, 1, greml::unknown_parent};
greml::ReferenceLapOptions lap;
lap.reference_ancestry() = "populationB";
lap.covariance = {0.2};
options.lap() = lap;

The standalone driver accepts GREML_ANCESTRY 1 and GREML_BOA 1. Ancestry mode/formulation names, lap.reference_ancestry and partial_pedigree.founder_ancestries lower to the same validated native input. The driver advertises ancestry capability names alongside the BOA capabilities. Newly named prepared inputs require a driver with ancestry_naming_version: 1; an older driver is rejected with a rebuild diagnostic.

Reports and unchanged uncertainty

Primary reports include partial_genetic_values.csv with an ancestry column, lap_values.csv, lap_model.json and ancestry-prefixed covariance/history/score reports when those results are requested. Legacy partial_breeding_values.csv, lbp_* and boa_* reports remain available. Native telemetry adds ancestry_* and lap_* keys alongside the corresponding legacy measures and counters. The labelled input metadata retains its legacy boa backend record and adds an ancestry_model naming summary; this does not duplicate or reorder the model.

Selected PEV is conditional on supplied/fitted covariance. The renaming adds no variance-component, phase or ancestry-assignment uncertainty. Exact/stochastic REML, identifiability diagnostics and their existing qualification limits remain as documented in model coverage (source-checkout reference: boa-model-coverage.md).

Species scope and interpretation

Ancestry labels can describe livestock breeds, human source populations or plant populations. The current input/model restrictions still apply: complete diploid phased alleles, known hard ancestry labels, supplied reference frequencies and compatible covariance bases. The partial-pedigree route requires labelled single-ancestry roots and two known parents per non-founder. Renaming does not add phasing, local-ancestry inference, probabilistic origins, polyploid inheritance, metafounders or new incomplete-pedigree handling, and does not establish human/plant scientific qualification.

The legacy gsim BOA simulation functions, historical benchmark model IDs, source filenames and the v50 bundle remain reproducible under their original names. New local-ancestry inference methods are a separate planned capability.
