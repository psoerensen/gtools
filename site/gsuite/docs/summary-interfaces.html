Preparing summaries, fitting Bayesian models and scoring

These interfaces connect existing native components. Preparation is explicit; estimators do not silently align alleles or change the marker universe. Download the runnable example.

Prepare once, then choose the analysis

For already aligned input, no preparation call is necessary. Otherwise, gprep_stat() returns data plus a decision record:

prepared <- gprep_stat(raw, LD, task = "standardize")
stat <- prepared$stat
prepared$decisions

Here raw contains marker, allele1 (effect allele), allele2, chromosome, position_bp, beta, se, n and p_value. The native gscore preparation matches the complete reference, flips swapped alleles and uses \(\beta_{std}=\beta/\sqrt{n\,SE^2+\beta^2}\). This is the declared continuous-trait summary conversion; it is not a general transformation for logistic or adjusted mixed-model effects. Both phenotype and genotype units of downstream weights are standardized. The supplied p-values are retained, not recomputed.

task="align" instead accepts marker/allele columns, signed z and n, delegating orientation and shared-trait masks to gcorr. A named list represents multiple traits. control=list(missing="drop") permits the native missing-row policy; the default rejects missing inputs. Optional strand complements require allow_strand_complement=TRUE. Palindromic alleles remain ambiguous.

complete_reference reports whether every reference marker remains. Dropping markers does not produce a new LDlist; fitting routines that require complete reference coverage still reject a subset. Assembly compatibility is the caller’s responsibility. standardize requires complete coverage and does not enable strand inference. Save/reload preserves the stat tables and decision record.

Construct and apply genomic scores

fit <- gscore(stat, LD, method = "ridge", control = list(penalty = 0.1))
summary(fit)
fit$weights

scores <- gscore(task = "apply", Glist = Glist, weights = fit,
                 allele_frequencies = frequencies)
scores$scores

Fit input contains marker, allele1, allele2, beta_std, n and p_value in exact LDlist order. frequencies is a numeric vector named in weight order, for the counted allele. It is explicit because the scoring population and reference population need not share frequencies. Multiple named numeric weight columns can be applied together. Weight rows must exactly match selected Glist markers and alleles; use preparation before fitting, not implicit flipping here.

Fit method Native operation Controls beyond storage
marginal Apply standardized marginal effects None
threshold Keep p-values at or below threshold p_threshold=1
clump Greedy LD clumping and p-value threshold p_threshold=1, r2=.1, window_bp=250000
ridge Solve \((R+\lambda I)w=\beta_{std}\) penalty=1, tolerance=1e-8, maximum_iterations=1000
l1 L1 plus quadratic-penalty coordinate descent lambda=.01, delta=.1, tolerance=1e-8, maximum_iterations=1000

Storage is "memory" by default, with max_ld_entries=1e7 limiting retained sparse entries. "disk" reuses the native reader for supported algorithms; clumping requires materialized LD. Native LD construction requirements still apply: clumping cannot recover correlations omitted from the reference.

Application currently uses one BED file and returns the selected Glist sample order, plus family/individual identifiers. The native scorer processes all physical samples before R selects rows. coding="standardized" uses \((g-2p)/\sqrt{2p(1-p)}\); "raw_mean_imputed" uses raw dosage and replaces missing values by \(2p\). Weights must be on that coding’s scale. Defaults are threads=1, marker_tile_size=64, sample_tile_size=1024, score_tile_size=32 and memory_limit_bytes=256*1024^2. The latter bounds result payload copies, not total process memory. This is not a biobank-throughput qualification.

Select on independent summaries and refit

selected <- gscore(full, LD, task = "select",
  training = training, validation = validation, validation_LDlist = validation_LD,
  positions_cm = positions_cm,
  candidates = list(
    ridge = list(method="ridge", penalty=.1),
    sparse = list(method="l1", lambda=.01, delta=.1),
    mixture = list(method="mixture", variances=c(0,.01), weights=c(.9,.1))),
  control = list(independent=TRUE))
selected$diagnostics$ranking
selected$weights

All summaries/references must share marker coding, coordinates and assembly. Training and validation samples must be independent; the assertion records that assumption, rather than verifying it. The full summary is supplied separately for refitting. Positions are cM values named in marker order. Native windows use width_cm=1, step_cm=.125, maximum_iterations=200 and tolerance=1e-8. The native criterion is \(\beta_{validation}'w/\sqrt{w'R_{validation}w}\). It selects a model; it is not an unbiased post-selection performance estimate. Pseudo-summary generation is not exposed in this initial interface; selection here uses caller-supplied independent summaries. Native Bayesian score fitting is available separately through the inference interfaces below.

Additional Bayesian inference engines

vb <- gbayes(stat, LD, method="variational", prior=list(p=.01, h2=.4))
mixture <- gbayes(stat, LD, method="mixture_variational",
                  prior=list(variances=c(0,.01), weights=c(.9,.1)))
gibbs <- gbayes(stat, LD, method="point_normal", prior=list(p=.01, h2=.4),
                control=list(seed=17, burnin=500, sampling_sweeps=1000))
summary(vb)

These additional routes accept one trait, one reference and common N. They reuse gbayes engines directly and return gbayes_engine_fit, with labelled estimates, diagnostics, prior, control and reference provenance. Existing BayesC/BayesR workflows retain their existing classes and capabilities.

  • Point-normal Gibbs: p and h2 determine the initial prior. Controls include burnin=500, sampling_sweeps=200, seed=1, sparse=FALSE and auto_update=FALSE. Native parameter paths remain visible. Marker variances are not supplied by this engine and remain unavailable.
  • Point-normal / mixture variational: fixed priors, maximum_iterations=200 and tolerance=1e-8. Optional windows is a two-column matrix of one-based inclusive ranges. Windows may overlap; a single ordered window pass does not establish whole-panel convergence. Objective/drift/window diagnostics remain available; posterior variances are variational approximations.
  • Continuous shrinkage: prior=list(global_scale=1); controls burnin=500, sampling_sweeps=500, thinning=5, seed=1, learn_global_scale=FALSE, maximum_block_dimension=2048 and required block_offsets=c(0,...,M). This is an explicitly zero-based boundary vector, not marker IDs. Native checks reject retained cross-block LD. LD must be materialized. Local/global/residual-scale summaries are returned; this continuous prior has no inclusion PIP, and marker variances remain unavailable.

These bindings use one chain/fit (threads=1). They do not inherit BayesC/BayesR multitrait, annotation, parameter-learning or posterior-summary controls. They do not manufacture ESS, R-hat or uncertainty absent from the native result. Independent reruns and appropriate statistical qualification remain necessary.

Reuse GNOVA annotations for conditional analysis

source <- gcorr(traits, LD, method="gnova", task="cov", annotation=annotation,
                 control=list(overlap_intercept=0))
conditional <- gcorr(source, method="gnova", task="partial_rg",
                       targets=c("A","B"), conditioned_on="C")
regression <- gcorr(source, method="gnova", task="regression",
                      outcome="A", predictors=c("B","C"))
summary(regression)

The source is a coordinated continuous-trait GNOVA fit with annotation categories and one reference. Block labels in the original trait tables retain paired deletions. Source fits saved before full joint estimates were retained must be refitted if jackknife uncertainty is requested. No LD reading or covariance refitting occurs in the conditional call.

Results include coefficients, standardized coefficients, explained/residual genetic variance, proportions or partial correlations, with available paired-delete SEs and joint covariance. Invalid deletions and matrix-conditioning failures remain explicit. No p-values or intervals are supplied: numerical availability does not resolve the recorded nonlinear/weak-signal calibration limits. Overlapping categories remain marginal category quantities, not uniquely attributable contributions. Annotation SEM/GGM and regional LAVA conditional analysis remain separate existing workflows.

Controls expose native minimum_relative_eigenvalue=1e-4, residual_variance_tolerance=1e-8, symmetry_tolerance=1e-10 and maximum_traits=32. They do not silently repair a covariance matrix.
