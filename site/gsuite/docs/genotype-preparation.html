gs_genotypes preparation contract

Bounded scope and ownership

gs_gprep() implements the bounded "prepare" and "sparseld" tasks. For preparation, gsuite owns argument validation, orchestration, and the returned R descriptor; gmat owns strict BIM/FAM parsing and exact ordered multi-file identity; gbits owns BED header, size, offset, packed-code, and threaded count logic. The existing SNP-major PLINK BED files remain the sole persistent genotype representation. qgg is a read-only behavioural and scientific reference and is not a runtime dependency.

Sparse-LD orchestration is specified separately in sparse-LD preparation. Separate LD-score tasks, genetic-map import, GRMs, association, scoring, and other qgg tasks are not implemented by gs_gprep(). Marker filtering is provided separately by gs_gfilter(). Unknown preparation tasks fail explicitly.

Files and identities

Every BED/BIM/FAM vector is nonempty and has identical length. Omitted companions are derived by replacing only a final case-insensitive .bed suffix. Every path is normalized and must name an existing regular file. gbits requires the exact header 6c 1b 01 and exact size \(3+M\lceil N/4\rceil\); individual-major, truncated, and trailing-byte inputs fail.

The first FAM supplies ids and the complete physical sample order. Individual IDs are nonempty and globally unique. gmat requires every component to have the same exact ordered (family_id, individual_id) sequence; no set-only check or positional permutation is used. With ids = NULL, all samples contribute and study_ids is NULL. A supplied vector is nonempty, unique, nonmissing, fully resolved, retained in caller order, and used only as the summary sample set; ids remains complete.

Every BIM row has six fields, a nonempty chromosome and marker ID, finite nonnegative map position, positive physical position, and distinct nonempty alleles. Source marker IDs are globally unique across every supplied BIM, including unselected rows. BIM order is canonical. A supplied rsids vector is validated completely, then filtered in file/BIM order; caller order is intentionally not retained because the public descriptor remains a file-partitioned physical view. source_marker_indices_0based records every original BIM/BED index, including noncontiguous selections. BED is never rewritten.

Alleles and summaries

a1 is BIM field 5 and a2 BIM field 6. Counts and frequencies always refer to copies of a1:

PLINK code Copies of a1 Count
00 2 n2
10 1 n1
11 0 n0
01 missing nmiss

For \(N_{\mathrm{obs}}=n_0+n_1+n_2\), the returned values are \(\mathrm{af}=\frac{2n_2+n_1}{2N_{\mathrm{obs}}}\), \(\mathrm{af}_1=\mathrm{af}\), \(\mathrm{af}_2=1-\mathrm{af}\), \(\mathrm{maf}=\min(\mathrm{af},1-\mathrm{af})\), \(\mathrm{hom}=(n_0+n_2)/N_{\mathrm{obs}}\), and \(\mathrm{het}=n_1/N_{\mathrm{obs}}\). All-missing selected markers fail with their marker ID. Empirical frequencies are not clipped: monomorphic values are exactly zero or one. This deliberately differs from the tested qgg 1.1.6 reference, whose summaryBED() clips frequencies to [0.00001, 0.99999] and substitutes 0.5 for all-missing markers.

Object schema and persistence

The result is a plain list with class c("gs_genotypes", "Glist"). It carries study, normalized bedfiles/bimfiles/famfiles, complete ids, optional study_ids, n, nchr, m, chromosome/file-wise rsids, mchr, chr, pos, map, a1, a2, cpra, af, af1, af2, maf, nmiss, hom, het, n0, n1, n2, assembly = NULL, physical sample/marker mappings, format and ordering labels, and provenance. It contains neither dense genotypes nor a mandatory external pointer and therefore survives an exact saveRDS()/readRDS() round trip.

The gsim 0.16.0 development source has a native bounded BED reader for Glist-backed simulation; qgg’s getG is no longer its default. It resolves selected sample and marker IDs against FAM/BIM files, checks allele orientation, and reads selected BED blocks. A custom deterministic getG_fun remains an explicit alternative. This removes the previously described need for a new gsuite decoder, but does not imply full qgg compatibility or qualification of every cross-package combination. Check the installed gsim version before use.

Complexity and execution

gbits scans packed marker records directly. Selected original offsets are checked with 64-bit arithmetic. Threaded execution assigns deterministic static marker partitions and never calls R from workers. Temporary native storage is \(O(T\lceil N/4\rceil)\) packed bytes for T workers plus \(O(M)\) counts and selection mappings; no \(O(NM)\) decoded matrix exists.

gsuite is in private development. gsim and gact are public.
