Marker-QC contract

Scope and ownership

gs_gfilter() is gsuite’s summary-only marker-selection operation. It accepts the strict serializable c("gs_genotypes", "Glist") descriptor produced by gs_gprep(task = "prepare") and returns a plain marker-ID vector. It does not mutate the descriptor, read packed BED genotype bytes, write BED or CSR files, decode a genotype matrix, or construct sparse LD. gmat and gbits remain unchanged owners of metadata/LD and packed-genotype operations respectively.

Marker identity is canonical chromosome/file/BIM order. Every required chromosome-wise field is checked for the same shape, and IDs must be complete and globally unique. The existing preparation validator also reopens the BIM/FAM/BED descriptors and verifies source mappings. Genotype counts must be nonnegative integers whose sum equals the exact summary population recorded by sample_source_indices_0based and provenance$summary_samples. MAF must agree with n0, n1, and n2. Thus a study-sample preparation uses that selected population rather than the complete FAM count.

Boundary rules

Each enabled rule creates a full-length exclusion mask; the final mask is their union. NULL disables a numeric rule and FALSE disables a logical rule.

  • MAF excludes \(\mathrm{maf}_j\leq\texttt{maf}\); equality is excluded.
  • Missingness is \(\frac{n_{\mathrm{miss}}}{n_0+n_1+n_2+n_{\mathrm{miss}}}\) and excludes values strictly greater than missing; equality is retained.
  • HWE excludes exact-test p-values strictly less than hwe; equality is retained.
  • INFO excludes values strictly less than info; equality is retained.
  • Ambiguity excludes the exact allele pairs A/T, T/A, C/G, and G/C.
  • The indel/non-SNP rule retains only exact uppercase single-base A, C, G, or T for both alleles. It therefore rejects multi-base, symbolic, and lowercase encodings without silently normalizing alleles.
  • MHC excludes a closed interval, including both endpoints, on stored chromosome labels 6 and chr6: GRCh37 [28,477,797, 33,448,397], or GRCh38 [28,510,120, 33,480,577]. The assembly must be explicitly GRCh37 or GRCh38, supplied as an argument or in Glist$assembly; it is never guessed.

All numeric thresholds are finite scalars in [0,1]. Logical controls are nonmissing scalars. A marker-aligned INFO field is required only when INFO filtering is enabled. It may be a named numeric vector or list, but its names must be a duplicate-free exact set of prepared marker IDs. Values are reordered by identity into canonical order before the mask is calculated.

Exact HWE definition

For each biallelic marker, gsuite conditions on the observed sample count and minor-allele copy count and enumerates every feasible heterozygote count with the same allele total. The two-sided p-value is the sum of conditional genotype probabilities no greater than the observed genotype probability. Probabilities within relative tolerance 1e-12 are treated as ties. This is the conventional probability-ordering exact test. Monomorphic markers receive p-value 1. All-missing or structurally invalid counts are descriptor errors; any otherwise nonfinite HWE result is conservatively excluded when HWE filtering is enabled.

qgg 1.1.6 instead uses a one-degree-of-freedom Pearson chi-square calculation. The tested version’s gfilter() also has disabled-mask hazards, relies on incomplete positional/name alignment, and subsets its combined mask incorrectly during INFO filtering. gsuite deliberately uses the exact test, complete identity validation, independent full-length masks, and an explicit default HWE threshold of 1e-12. It also freezes the documented inclusive MAF boundary.

Workflow

Glist <- gs_gprep(
  study = "Reference",
  bedfiles = bedfiles,
  task = "prepare",
  nthreads = 4
)

rsids <- gs_gfilter(
  Glist,
  maf = 0.01,
  missing = 0.05,
  hwe = 1e-12,
  ambiguous = TRUE,
  indels = TRUE
)

Glist <- gs_gprep(
  Glist = Glist,
  task = "sparseld",
  rsids = rsids,
  out_prefix = "reference_ld",
  nthreads = 4
)

Preparation computes reusable summaries once. The same unchanged descriptor can be filtered under several policies, and sparse LD is subsequently built only for the selected markers.
