Bayesian genomic regression

Bayesian regression with checked summaries, Glist genotypes, posterior quantities and scoring.

The authoritative R interface contract defines the bayes, sbayes, blr, mbayes, msbayes and mblr interfaces. The initial bayes/mbayes packed and sbayes/msbayes marginal-summary BayesC/BayesR routes are implemented, along with blr/mblr exact common-design cross-products. All six C/R fitters support exact same-build continuation and optional posterior quantities within their route-specific contracts. All 24 initial method/interface combinations are implemented within documented native limits. The common result boundary validates schema and scientific axes, preserves logical chains, records software versions and supplies availability reasons for unsupported quantities. Separate method formats retain their scientific meanings. Optional native extensions and broad qualification remain separate work.

For individual BayesC/BayesR, use the new familiar entry points:

fit <- gbayes::bayes(data=phenotypes, Glist=g, trait="height",
                     method="bayesR", nit=1000, nburn=500, nthin=2,
                     nchains=2, ncores=1, seed=1)
effects <- coef(fit)                       # marker by trait, including T=1
chain1 <- gbayes::extract(fit, "effects", chain=1)
summary(fit)
gbayes::diagnostics(fit)
scores <- predict(fit, list(Glist=targets, ids=target_ids))

joint <- gbayes::mbayes(data=phenotypes, Glist=g, trait=c("height", "yield"),
                        method="bayesR", vb=Vb, ve=Ve, pi=pattern_weights,
                        nit=1000, nburn=500, nchains=2, seed=1)

Both require prepared packed Glist genotypes and complete finite outcomes. The joint matrices must be labelled in trait order; pi is aligned to the declared activity-pattern set. Initial joint learning is off; enable updateB, updateE or updatePi with the corresponding proper priors. Scalar defaults use h2=.5, BayesC pi=.001 or BayesR weights (.95,.02,.02,.01), df=4 learning priors and learned variances/weights. Trait centering preserves original response units; the likelihood dimension defaults to n-1. Existing HWE genotype coding is retained. Dense X and annotation requests are explicitly unavailable in this slice.

Retained indices are multiples of nthin; all nit post-burn transitions run, including a remainder. This is implemented by an exact native retention-phase translation for these ordinary models. Final seeded states are unchanged by the translation. Diagnostics identify their actual native checkpoint schedule; they do not claim unthinned all-marker capture. Full effect draws are unavailable. Scalar total-memory estimation and actual worker counts are unavailable; joint native reports are retained. Prediction uses saved training frequencies/scales and pooled effect means by default; chain selects one chain. Phenotype prediction adds the fitting-sample intercept and uses no target outcomes.

Individual C/R also supports native posterior-quantity capture:

captured <- gbayes::bayes(phenotypes, Glist=g, trait="height", method="bayesR",
  posterior=list(reference=reference_ld, partition=marker_groups,
    phenotypeVariance=c(height=phenotype_variance),
    prediction=list(Glist=targets, ids=target_ids, retainDraws=TRUE)))
gbayes::extract(captured, "genetic")
gbayes::extract(captured, "partition")
gbayes::extract(captured, "prediction")
gbayes::extract(captured, "prediction", state="retained")
summary(captured, quantity="quantities")

Use mbayes with the same posterior keys and trait-named phenotype variances. Reference must be aligned sparse LD; genetic covariance is B’ R B on that declared standardized reference, separate from latent vb or training covariance. Partition labels are mutually exclusive and named in fitted marker order. Full group/trait covariance includes cross-group LD. Genetic correlations retain their positive-variance conditioning counts; h2 ratios need compatible explicit phenotypeVariance. Neither summing marginal effect variances nor applying the quadratic to posterior mean effects substitutes for these draw-wise quantities.

Selected score moments use saved fitting HWE coding, including when target frequencies differ. Partial marker targets report coverage and selected marker domain. Their uncertainty omits phenotype residual noise, cross-person covariance and reference uncertainty. Ordinary predict() remains mean-effect projection; availability\(prediction refers to stored capture moments. Capture requests apply to each call separately, including continuation. Genetic/partition traces follow retainDiagnostics; score traces use prediction\)retainDraws independently. No full effect draws are enabled. Resources are fingerprinted before/after capture, and managed memory guards include reference loading, targets and output copies. See the capture contract.

Individual C/R fits support exact continuation from native checkpoints:

saveRDS(fit, "individual-fit.rds")
more <- gbayes::bayes(phenotypes, Glist=g, nit=500,
                       continuation=readRDS("individual-fit.rds"))
gbayes::diagnostics(more)$execution$continuation

Use mbayes for a saved joint fit. Nit adds transitions; omitted method, traits, priors, learning settings, thinning and chain seeds inherit the saved model. Nburn must be omitted or zero. The original global thinning phase is preserved, and diagnostics record absolute retained transitions. A segment with no scheduled draw fails. Workers and diagnostic capture may change. The resumed fit reports only the added segment’s summaries, and can itself be resumed; earlier intervals are not automatically pooled. Checkpoints require unchanged outcomes, ordered selections, genotype resource bytes and the same qualified bundled build, R and platform. Full active BED/BIM/FAM hashing adds streaming I/O on fit/resume. Current qualification is Windows; other runtime layouts report restartState unavailable. Other methods/interfaces do not acquire continuation from this change. See the exact continuation contract.

For marginal-summary BayesC/BayesR, use the corresponding summary interfaces:

fit <- gbayes::sbayes(stat, Glist=g, method="bayesR", nit=1000,
                      nburn=500, nthin=2, nchains=2, seed=1)
joint <- gbayes::msbayes(list(height=height_stat, yield=yield_stat), Glist=g,
                         method="bayesR", vb=Vb, pi=pattern_weights,
                         sampling=list(dependence="independent",
                                       residual_variance=c(height=1, yield=1)))
coef(fit)
gbayes::extract(joint, "effects", chain=1)

Each table has rsids, chr, pos, ea, nea, b, seb and n, covering its reference exactly. The adapter aligns markers/coordinates/alleles and uses standardized marginal effects b/sqrt(nseb2+b2). Scalar defaults initialize vb=h2/(pmass) and ve=1-h2, with h2=.5. Sparse residual learning uses the existing reference-LD approximation and adjustment .9; this is recorded in input$nativeControl. For fixed residuals set updateE=FALSE. Explicit exact in-sample normalization retains the native same-sample, complete-LD checks.

Sbayes also accepts representation=“block_eigen” with verified Glist blocks; its residual learning uses the retained likelihood. Algorithm stays “mcmc”. Msbayes currently accepts sparse LD only. Independent providers can use a named Glist list and different marker sets, with trait mapping named in study order. Their residual variances are named by study. Shared-LD correlated summaries require sampling=list(dependence=“shared_ld”, covariance=Ve), or supply ve=Ve with that dependence and omit covariance. Shared-LD N must match across traits and markers. Joint learning defaults off; covariance learning requires exact response_crossproduct, likelihood_dimension, nue and prior$veScale. Genetic covariance, sampling covariance and sample overlap are distinct quantities.

Both summary interfaces return the common bayesfit, preserve all chains and record the same retention schedule as the individual adapters. Scalar global memory estimates/actual workers and full effect draws remain unavailable. Summary prediction fails explicitly because training coding and intercepts are not identified. Annotation remains unavailable in these C/R adapters.

Summary C/R also supports posterior quantities:

captured <- gbayes::sbayes(stat, Glist=g, trait="height", method="bayesR",
  posterior=list(reference=reference_ld, partition=marker_groups,
    phenotypeVariance=c(height=1)))
gbayes::extract(captured, "genetic")
gbayes::extract(captured, "partition")
gbayes::extract(captured, "geneticCovariance", state="retained")
summary(captured, quantity="quantities")

Use msbayes with the same posterior keys. Reference is an explicit sparse-LD Glist aligned to every fitted marker, including the ordered union for different study references. It is not chosen from the fitting providers automatically. The reported draw-wise B’ R B uses this declared standardized reference, separately from latent vb, sampling covariance, fitting LD approximations or eigen truncation. A denominator of one applies only to compatible standardized phenotypes; provide compatible trait-named phenotypeVariance explicitly for h2. No reference uncertainty or automatic raw-unit conversion is included.

Partition-only requests report activity without inventing a genetic reference. With reference, partition covariance includes cross-group LD and is not a set of additive heritability contributions. Genetic correlations retain their positive-variance conditioning counts. Genetic/partition/h2 traces follow control$retainDiagnostics; moments remain available with traces disabled. Quantity summaries preserve native interval/diagnostic availability separately from parameter summaries. Singleton axes and per-chain moments are preserved; full effect draws and per-chain quantity intervals remain unavailable.

Capture is per call, including continuation, and summarizes only that call’s retained segment. Requests can change while states/RNG and parameter traces remain unchanged. Reference fingerprints and managed allocation guards apply; disk LD still requires one worker. Summary prediction requests remain rejected. See the summary capture contract.

Summary C/R fits can be continued from full native checkpoints:

saveRDS(fit, "summary-fit.rds")
more <- gbayes::sbayes(stat, Glist=g, nit=500,
                        continuation=readRDS("summary-fit.rds"))
# Use msbayes for a saved joint summary fit; omitted sampling is inherited.
gbayes::diagnostics(more)$execution$continuation

Nit adds transitions, with no repeated burn-in. Omitted model settings, representation, provider mapping, scientific controls, thinning and chain seeds inherit the original fit. Retained indices preserve the global thinning phase. Resumed summaries and intervals cover only the added segment; the new fit can itself be resumed. Storage mode, residual/normalization/eigen policies, sampling dependence/covariance/scatter and study sample sizes remain fixed. Worker count, diagnostic capture, interval probability and memory/entry budgets may change within existing backend limits; disk LD still requires one worker. Checkpoints bind harmonized summaries, full prepared LD bytes, reference descriptors and eigen block definitions, with the same bundled-Windows runtime qualification as individual C/R. Hashing adds streaming I/O. Specialized engines and other methods remain outside this contract. See the summary continuation contract.

For fixed-prior variational summaries:

vbfit <- gbayes::sbayes(stat, Glist=reference, method="variational",
                        algorithm="vbayes", pi=.01, h2=.5, nit=1000)
mix <- gbayes::sbayes(stat, Glist=reference, method="mixture_variational",
                      algorithm="vbayes", vb=c(0,.001,.01), pi=c(.9,.05,.05))
gbayes::extract(mix, "effectVariance")
gbayes::diagnostics(mix)$variational

Both reuse existing native mean-field optimizers on common-N sparse-LD inputs. Variational fixes pi/h2 (defaults .01/.5), slab variance h2/(p*pi), and unit likelihood residual variance. Mixture_variational requires absolute component variances through vb; pi supplies strictly positive normalized weights or defaults to uniform. At most one zero spike is allowed, in any component position. Pure Gaussian mixtures and an all-zero point mass retain their native meanings. Without a spike, PIPs equal one by definition. No h2/gamma calibration is applied to explicit mixture variances. All learning flags default FALSE; TRUE fails. Prior is empty, with no duplicate nested variance/weight spellings.

Nit defaults 1000 and limits sweeps per window. Control tolerance defaults 1e-8; windows defaults to one whole-panel range. Supply an ordered two-column matrix of one-based inclusive ranges, covering all markers without gaps or duplicates; overlaps are permitted. Each window is optimized once with the global residual and cross-window LD retained. Nonconvergent windows raise an error. A completed multi-window fit is labelled windowed_approximation, not whole-panel convergence. The native whole-panel flag identifies a coordinate fixed point, not a global optimum or exact joint posterior.

Means, variational marginal variances and PIPs use the common bayesfit accessors. Under correlated LD, mean-field variances differ from exact joint posterior marginal variances. Native objective endpoints omit the fixed log p(Y|b=0) baseline; they are relative bounds, not absolute ELBOs or full histories. Responsibilities, parameter posterior estimates, sampled draws and chains are unavailable. Final effects are the optimizer mean matrix. Explicit MCMC-only arguments fail, and ncores=1 is required. No prediction from unknown training coding, annotations, generic posterior capture or continuation is added.

Memory or disk storage uses controls memoryLimit (256 MiB) and maxLdEntries (1e7). Managed preflight counts LD/cache payloads, replicated native mixture priors/states and R/native copies. Native disk page/window limits still apply; these estimates do not measure process RSS or qualify routine genome-wide use. See ?gbayes::variational for the exact argument and window contracts.

For the specialized summary MCMC engines:

pn <- gbayes::sbayes(stat, Glist=reference, method="point_normal",
                     algorithm="mcmc", pi=.01, h2=.5)
cs <- gbayes::sbayes(stat, Glist=reference, method="continuous_shrinkage",
                     algorithm="mcmc", prior=list(globalScale=1), updateB=FALSE)
gbayes::extract(pn, "parameters", state="retained")
gbayes::extract(cs, "localScales")

Both require common-N summaries and sparse LD. Consecutive seeded logical chains share one prepared reference and run serially; ncores>1 fails. Defaults are 1000 postburn transitions, 500 burnin, thinning one, two chains and seed one. No native RNG checkpoints, prediction from unknown coding, generic posterior capture or annotation composition are exposed by these adapters.

Point-normal defaults to pi=.01, h2=.5, slab variance h2/(p*pi) and unit residual variance. Its means/PIPs average conditional expectations at every postburn sweep, so nthin must equal one. UpdateB and updatePi both default FALSE; both TRUE select the existing coupled pi sampling/h2 quadratic-form update. This is the 2020-style auto policy, not the expanded later LDpred2-auto algorithm, independent variance learning or posterior heritability inference. Control sparseEffects enables the existing threshold approximation and cannot accompany auto updates. Memory or disk LD is supported. Vb/ve/gamma/nub/nue/updateE and nested prior settings are unsupported. Native p/h2 paths support scoped diagnostics; effect variances are unavailable.

Continuous shrinkage requires memory LD and verified Glist LD blocks; no duplicate offsets are accepted. Prior globalScale defaults one. UpdateB controls global-scale learning (default FALSE); local scales and residual scale always update, so updateE=FALSE fails. Other scalar scale/probability arguments are unsupported. Native a=1,b=.5, the local-scale cap and update order remain unchanged. Completed-multiple thinning preserves all transitions and final effects. Local/global/residual means are available; PIPs, effect second moments, parameter/effect traces and trace convergence diagnostics remain unavailable. Common effect summaries mark unavailable moments with NA.

Control retainDiagnostics, memoryLimit, storage and maxLdEntries apply, with maximumBlockDimension and denseWorkspaceLimit for shrinkage. Managed memory preflight includes shared resources, chain outputs, PN’s mandatory full paths and native dense workspace reservations. These estimates are not process-RSS measurements or large-data qualification. See the installed method help ?gbayes::point_normal for the full crosswalk.

For annotation-dependent scalar mixtures, use bayesRC:

fit <- gbayes::bayes(phenotypes, Glist=g, trait="height", method="bayesRC",
                      algorithm="mcmc",
                      annotation=list(component=list(design=A)))
sfit <- gbayes::sbayes(stat, Glist=reference, method="bayesRC",
                       representation="block_eigen", algorithm="mcmc",
                       annotation=list(component=list(design=A)),
                       control=list(blockResidual=list(mode="sample")))
gbayes::extract(fit, "componentProbabilities")     # posterior allocations
gbayes::extract(fit, "annotationProbabilities")    # mean marker prior probabilities
gbayes::extract(fit, "annotationCoefficients", state="retained", chain=1)

A is a finite numeric matrix with exact fitted marker row names and unique non-intercept columns. The native sampler centers columns without rescaling; annotations may overlap. Only the component role is enabled. Pi defaults to BayesR weights (.95,.02,.02,.01), is normalized and initializes zero-slope continuation-probit coefficients. It does not define their priors. Gaussian intercept prior means default to zero and intercept/slope SDs default to one. Supply native component keys initial, intercept_means, intercept_prior_sd, coefficient_prior_sd or update_every for explicit choices. Initial is a labelled coefficient-by-stick matrix; explicit initial and explicit pi conflict. With explicit starts and omitted pi, mean initial marker class probabilities supply nominal slab-scale calibration.

UpdatePi defaults TRUE and learns annotation intercepts/slopes, with no global Dirichlet update. Use the direct flag rather than component\(learn. Individual vb/ve, updateB/updateE and nub/nue retain the scalar C/R rules. Summary global updateE defaults FALSE and TRUE fails. Its separate control\)blockResidual has native mode all_mix by default; sample, mix and fixed are explicit alternatives. Ve initializes every block; nue (default four) and prior$veScale (default (nue-2)/nue*ve) set learned block priors, and are rejected with fixed blocks. Block scatters/dimensions use retained eigen coordinates. The native all_mix/mix threshold and selection policies remain unchanged; sample updates every block. Sbayes requires one common N and verified Glist LD blocks.

Defaults are nit=1000, nburn=500, nthin=1, nchains=2, ncores=1 and seed=1. The native total-sweep annotation cadence is unchanged by completed-multiple retention, including remainder schedules. Coefficient arrays preserve retained draw/chain/coefficient/stick axes, and final states remain chain-specific. Prior probabilities, allocations and PIPs are different quantities. Native coefficient diagnostics have their original scope. Optional posterior capture, continuation, joint/cross-product RC, annotation hypervariance learning and complete sblr algorithm/output parity remain unavailable. No new sampler or general mixing/calibration qualification is introduced.

For covariance-mixture regression, use the common fitters:

fit <- gbayes::mbayes(data=phenotypes, Glist=genotypes,
                      trait=c("height", "yield"), method="bayesCM")
# algorithm="vbayes" is the default for bayesCM.
scores <- predict(fit, list(Glist=target_genotypes))

The phenotype table contains unique character id and numeric trait columns. Missing outcomes select the existing published mr.mash missing-data route. Defaults use training variances v and p fitted markers: with h2=.5, the dictionary contains zero, independent diag(h2v/p), and a shared rank-one pattern, with uniformly initialized learned weights. The default fixed residual covariance is diag((1-h2)v). These are working scale assumptions, not estimated heritability or learned covariance matrices; supply explicit prior$covariance and ve when appropriate. nit caps VI sweeps (default 1000), updatePi controls weight learning and updateE=TRUE enables diagonal residual EB with diagonal initial ve; use control=list(residualLearning=“full”) for full EB with correlated residuals. Prior contains covariance only; pi supplies weights. Explicit updateB/gamma/vb/nub/nue and MCMC-only arguments nburn/nthin/nchains/seed fail. Only one worker is supported.

Use bayes for one trait, mbayes for at least two, or blr/mblr for explicit XX/Xy/yy. Cross-products require dictionary and residual covariance on declared units. Exact EB requires yy; likelihood=“reference_ld” keeps residuals fixed. Without yy, fixed-residual inference exposes a relative objective rather than an absolute ELBO. Saved coding enables cross-product prediction; missing coding is not inferred. No marginal-GWAS conversion is added.

Individual CM uses native sample-count normalization n. Exact cross-product CM defaults to n and accepts an explicit effective likelihoodDimension >2 and <=n for a common projected design. This is separate from C/R’s n-1 default. Complete scalar packed CM prepares a bounded dense Gram from the HWE operator; joint CM keeps the native observation-space route. Scalar packed missing outcomes and dense X remain unqualified. All traits need observed outcomes, and dictionary/ residual defaults need at least two varying observed outcomes per trait.

Variational bayesfit reports optimization/EB diagnostics and dictionary responsibilities, without chains, sampled draws or R-hat/ESS. Global nonzero probability is anyPip; multivariate trait PIPs remain unavailable and summary shows NA. Missing-outcome augmented bounds and observed likelihood at fitted means have separate labels. Hitting nit is not convergence. The existing gbayes dispatcher and historical native helpers retain their separate scope.

For factor models, use mbayes with genotype-backed Glist:

fa <- gbayes::mbayes(phenotypes, Glist=genotypes, trait=c("height", "yield"),
                      method="bayesFA", algorithm="mcmc", nit=1000, nburn=1000)
fr <- gbayes::mbayes(phenotypes, Glist=genotypes, trait=c("height", "yield"),
                      method="bayesFR", algorithm="mcmc", nit=1000, nburn=1000)
gbayes::extract(fa, "geneticCovariance")
gbayes::extract(fr, "effects", chain=1)
scores <- predict(fr, list(Glist=target_genotypes))

BayesFA uses the existing one-kernel MegaLMM sampler. The adapter constructs an additive relationship internally using selected training genotypes, excludes and reports estimated monomorphic markers, mean-imputes missing calls in centered coordinates, and normalizes the mean diagonal to one. All-missing markers fail. No ridge, supplied K, Glist$K or second decoded genotype panel is introduced. Frequency/sample/marker selections and construction accounting are recorded; control=list(retainKernel=TRUE) optionally saves the bounded kernel for inspection. The kernel is constructed once and shared across chains.

BayesFR uses the native MegaBayesC marker-factor and direct-effect sampler with selected-training sample-SD coding. Total effects are reconstructed per native draw before averaging; marker-factor, direct and loading activity remain separate. Trait-total PIPs are unavailable. Both methods allow missing outcomes and require all selected Glist samples exactly once, at least two traits and some observed outcomes in every trait. Arbitrary fixed-effect estimation is not added.

Defaults are two factors, nit=1000 post-burn transitions, nburn=1000, nthin=1, nchains=2, ncores=1 and seed=1. Chains use consecutive uint32 seeds and remain separate. The existing factor runner is serial; ncores>1 fails. Nit must be divisible by nthin; retained indices are completed post-burn multiples without a retention-phase shift. No execution aliases in control are accepted.

BayesFR updateB/updatePi map to slab/inclusion learning in marker-factor, direct and loading groups; updateE maps to trait and factor noise. Defaults retain native learning. Loading-order shrinkage still updates with updateB=FALSE. BayesFA rejects those generic switches in favor of explicit factor/grid priors. H2/pi/gamma/vb/ve/nub/nue, dense X, annotation, optional posterior capture and continuation remain unsupported here.

Common bayesfit results preserve invariant posterior means, retained arrays, per-chain access and native final states. G/R traces use the existing native R-hat/ESS/MCSE engine; they are not an all-marker mixing certificate. Final factor states lack RNG state and are not continuation checkpoints. Set control=list(retainDraws=FALSE) to omit invariant capture without changing the seeded trajectories or posterior means. Memory guards include transient draw copies and native estimates, not measured process-RSS ceilings.

BayesFA has no marker coefficients. Predict accepts NULL or stored training IDs for native genetic/phenotype fitted summaries; new-kernel prediction is unavailable. BayesFR uses pooled or selected-chain total effects and saved coding for genotype prediction, adding the corresponding intercept means for phenotype scores. Training phenotypeFitted includes latent residual-factor contributions and is separate from genotype-only prediction. No target outcomes are consumed.

Bounds remain n<=256, traits<=128, factors<=16 and bayesFR markers<=4096. Dense relationship storage is quadratic. Multiple kernels, general covariates and genome-wide factor performance remain unqualified. Full-model MegaBayesC mixing failures remain unresolved and paused. Existing native/dispatcher routes keep their separate documented contracts.

Development adaptive multivariate and factor models

gbayes_multitrait(data, method, prior, control) exposes mr_mash, mr_mash_missing, mr_mash_rss, mega_lmm and mega_bayesc through the standalone gbayes R package. These method names also work with gbayes(data=..., method=..., prior=..., control=...) without Glist. They are development interfaces absent from the public 0.1.1 archive. Method names refer to our native implementations; upstream software is a pinned test reference and is not called during fitting.

Individual marker routes use numeric counted-dosage X and outcome Y matrices, unique sample row names, marker/trait column names, counted alleles in marker order and nonempty provenance. mr.mash also requires trait residual covariance V and a named PSD covariance dictionary with mixture weights:

# X and Y have matching sample row labels; alleles follow X column order.
fit <- gbayes::gbayes_multitrait(
  data=list(X=X, Y=Y, V=diag(ncol(Y)), alleles=alleles,
            provenance="training panel"), method="mr_mash",
  prior=list(covariance=list(zero=0*diag(ncol(Y)),
                            independent=diag(ncol(Y))), weights=c(.5,.5)),
  control=list(maximum_sweeps=1000, residual_learning="fixed"))
scores <- predict(fit, X_target, alleles)

The missing-outcome route accepts NA/NaN in Y and returns observed masks and conditional imputation summaries. Complete mr.mash rejects missing outcomes. Optional full/diagonal residual EB is explicit. The RSS adapter takes C=X’X, S=X’Y, V, training centers/scales, common sample size and an explicit exact or reference_ld likelihood; absolute ELBO and residual learning need exact H=Y’Y. It does not reinterpret marginal GWAS coefficients as S. Predictions reuse training coding and validate marker/allele order.

For individual mr.mash and MegaBayesC, replace X with Glist=panel inside data, or pass Glist=panel to gbayes(). Y row labels select and order the training samples; data$markers optionally selects/orders markers across files. Alleles default to Glist A1 and supplied alleles must match. Direct PLINK inputs use bed=list(bedfiles=..., bimfiles=..., famfiles=...), with ordinary sidecar defaults. These adapters call installed gbase preparation and reuse native packed operations, without constructing decoded genotype or Gram matrices. Missing genotypes are imputed from selected-training frequencies. mr.mash BED retains HWE standardization; MegaBayesC retains its sample-SD or centered-raw coding. These scales define different effect priors.

predict(fit, list(Glist=target_panel, ids=target_ids)) uses saved training frequencies/scales, including imputation, rather than estimating target coding. Packed fits additionally check both alleles and coordinates. Singleton targets and zero-variance target columns are supported. Optional control$packed_memory_limit_bytes tightens packed storage preflight; the total native estimate also includes effects, factors and retained traces.

MegaLMM takes Y and one labelled sample relationship K. MegaBayesC takes X/Y and learns marker-to-factor effects, direct effects and sparse loadings. Factor controls include burnin, retained draws, thin, distinct uint32 seeds and memory limits. Results retain separate chains, invariant traces, final states and explicit update/solve accounting. Direct, marker-factor and loading PIPs remain distinct activity summaries. Raw loading means have sign and ordering ambiguity. MegaBayesC G is realized training-design genetic covariance. Genotype-only predictions differ from training phenotype fits conditioned on observed outcomes. New-kernel MegaLMM prediction is unavailable.

gbayes::gbayes_yaml("model.yml", output="new-fit.rds") uses the same dispatcher. Its gbayes.model/v1 schema has method, data, prior and control mappings. Matrix declarations such as X: {file: dosage.csv} refer to labelled numeric CSVs relative to the YAML file; the first column contains row IDs. Dictionary matrices use the same declarations. Inline matrices need numeric values rows and explicit rows/columns labels. Unknown fields, duplicate keys, tags, anchors and aliases are rejected; expressions are never evaluated. The standalone mixed-model gsuite.model/v1-draft schema remains a separate solve/REML interface. PLINK paths resolve relative to the YAML document; a saved Glist retains its physical paths. The runner records input hashes for the referenced resources.

See installed ?gbayes_multitrait, ?gbayes_yaml and the development package README for all controls. These adapters retain the bounded native scope, memory limits and scientific qualification of each inference route. They do not establish packed streaming, arbitrary fixed covariates, multiple kernels, genome-wide performance or broad calibration. Existing published methods and source archives are unchanged.

Fixed-variance single-effect summaries

gbayes::gbayes_single_effect(stat) fits a deterministic single-effect model from an ordinary data frame with unique rsids and either b/seb or score/information. It accepts fixed positive residual_variance and effect_variance, optional nonnegative marker_weights, and output labels trait and response_units. No Glist or prepared LD resource is required by this focused interface.

The per-marker result contains posterior assignment probabilities and moments. The model assumes exactly one active marker; assignment probabilities sum to one even when the evidence is weak. They are not unconditional association probabilities. This interface does not expose native single-effect variance learning or the wider BayesC/BayesR control set. For regional multi-effect fitting and posterior interpretation, use the mapping guide.

Prepare genotypes and summaries

Single-trait summary BayesC/BayesR also accepts familiar iteration and prior arguments:

fit <- gbayes::gbayes(Glist=Glist, stat=stat, method="bayesC",
  algorithm="mcmc", nit=100, nburn=0, seed=10)
head(fit$stat)       # bm: native posterior mean; dm: PIP
head(fit$post)      # ve, vg, vb, pi, pip on the fitted likelihood scale
head(fit$conv)      # native R-hat, ESS, MCSE and diagnostic statuses

Familiar calls default to one chain, 100 sweeps, zero burn-in, h2=.5, BayesC active probability .001, and learned slab/residual variances and mixture weights. nit/nburn/nthin/nrun/seed, pi/gamma/vb/ve, and updateB/updateE/updatePi adapt to native settings. Explicit conflicting aliases and nested settings are rejected; existing advanced calls retain their defaults. Familiar adaptation is limited to single-trait summaries.

Summary bm remains in standardized native genotype/phenotype units. The standalone reference-LD residual policy defaults to adjustment .9; it differs from qgg’s marker-specific adjustment. No independent genetic-variance draw is recreated. post$vg instead averages the joint-effect quadratic b' C b / n from retained draws, reusing the fitted residual. It is unavailable with variable sample sizes or a distinct explicit posterior reference. pi is total non-null mixture probability and pip is summed marker PIP (expected active count); pi0, pi1, … retain component weights. conv exposes rhat_*, ess_*, mcse_* and status_* columns, rather than qgg Geweke z scores. Original native posterior and diagnostic fields remain available. Single-chain output does not establish convergence or posterior equivalence. Use gmap::getCredibleSets(Glist, fit, sets) to interpret saved marginal PIPs with full BED LD without refitting.

Scalar summary BayesC/BayesR support optional LD swaps on sparse-LD and block-eigen routes, with the same controls as regional gmap():

fit <- gbayes::gbayes(Glist=Glist, stat=stat, method="bayesC",
  algorithm="mcmc", nit=1000, nburn=100, nrun=4, seed=10,
  control=list(ld_swap=list(probability=.05, minimum_r2=.8,
    maximum_friends=50L, moves=1L)))
fit$ld_swap

Native Metropolis-Hastings proposals relocate an active effect to an inactive LD neighbour. probability selects sweeps for up to moves proposals; minimum_r2 and maximum_friends bound candidate neighbours. Neighbours use the fitted cross-products, including retained eigen truncation. fit$ld_swap reports pooled attempted/accepted counts and the acceptance rate; fit$chains retains per-chain counts. Counts include burn-in and no attempts gives an NA rate. They measure proposal activity, not convergence. Individual BED fits do not support these swaps. For sparse LD, neighbour preparation scans the existing stored correlations once and shares the list across chains. It does not recompute LD from genotypes or rebuild the list at every sweep.

Probability defaults to zero; zero moves also disables swaps and neighbour preparation. Finding neighbours adds preparation cost, especially with eigen operators. Existing manuscript timings used swaps disabled and remain unchanged; improved mixing or elapsed time has not been established by those timings.

BayesC and BayesR also accept algorithm="mcmc-eigen". Declare exhaustive contiguous LD blocks using gbase::define_ld_blocks(Glist, blocks); block edges must have no retained cross-block LD. The verified decomposition is prepared once per block and reused by every chain. This route uses the retained block-diagonal summary likelihood, defaults to positive eigenvalue mass .995, and learns a global residual variance in the retained response/rank space:

eigen_fit <- gbayes::gbayes(stat, Glist, method="bayesR",
  algorithm="mcmc-eigen", nit=1000, nburn=100, nrun=4, seed=10,
  control=list(eigen_control=list(retained_positive_mass=.995)))
eigen_fit$diagnostics$block_eigen

Use updateE=FALSE for fixed residual variance. Reference-LD adjustment and caller-supplied full-space normalization cannot be combined with this route. SBayesRC remains a separate annotated model with block-specific residual scales. The eigen option is not a promise of lower elapsed time: preparation and retained rank affect the cost. The existing manuscript timings describe the earlier dense/sparse MCMC version and have not been replaced by these interface changes.

Scheduled scalar BED fits and variance decomposition

With gbayes 0.1.2 or later, scalar individual BayesC and BayesR accept control$marker_schedule=list(enabled=TRUE). Defaults are full_sweep_every=10, base_interval=50, maximum_interval=200, candidate_threshold=.001, candidate_lifetime=20, and burnin_only=FALSE. A zero full-sweep interval requests full sweeps. Active and recent candidate markers are revisited; low-probability null markers can be skipped between full sweeps. Scheduling is an explicit approximation to ordinary full-sweep sampling. It is opt-in, scalar-BED-only in R, and its queue/counters are serialized for continuation.

For a posterior-analysis example, prefer scheduling only during burn-in:

control <- list(burnin = 1000, sampling_sweeps = 2000,
  seeds = c(17, 29), retain_diagnostics = TRUE,
  marker_schedule = list(enabled = TRUE, burnin_only = TRUE))

These counts are starting settings, not a convergence guarantee. With burnin_only=TRUE, every sampling sweep is full, including continuation batches with zero burn-in. With scheduling during sampling, learned global mixture weights update on periodic full sweeps and, in corrected scalar native builds, whenever the scheduled visit includes every marker. Visits that skip markers hold weights between full sweeps; an interval of ten can therefore give ten times fewer weight updates. Earlier native builds also held weights on nonperiodic visits that included every marker, needlessly slowing learning in the all-hot case. A low candidate threshold can keep all markers hot, providing no marker-visit saving. The all-hot correction changes scheduled draw sequences; continue a study with a consistent native build.

Check posterior quantities separately: similar held-out accuracy and highly correlated posterior-mean predictions can coexist with poor variance or mixture-weight mixing. Inspect parameter-level R-hat, ESS, Monte Carlo error and chain traces; a single worst-parameter statistic does not describe every output. Starting weights or inclusion_probability are distinct from the Dirichlet/Beta weight_prior used when learning is enabled. Continuing a saved fit keeps its model and transition settings; changing a prior or scheduler requires a fresh fit. An extra continuation batch can be discarded as further warm-up before summarizing a subsequent batch. Full sweeps establish the baseline before studying approximate scheduling during sampling.

fit$individual_bed$variance exposes native final and post-burnin means:

[ V_g=|Xb|^2/n, V_{}=j(x_jx_j)b_j2/n, V{}=V_g-V_{}. ]

The LD term can be negative. Empirical diagonal variances need not be one under the native allele-frequency/HWE coding. These quantities differ from the slab variance parameter Vb; BayesR component variances are its multiplier-scaled values. Residual variance Ve is a separate model parameter. Compute h2 = Vg/(Vg+Ve) at each posterior draw when reporting model-scale heritability. The variance of posterior mean predictions differs from mean posterior Vg.

Each fit$chains[[k]]$individual_bed contains vb_trace, ve_trace, vg_trace, vle_trace, vld_trace, weight_trace, and log-CPO. BED traces include burn-in and every sweep; variance means average all post-burnin sweeps independently of effect thinning. Top-level traces average chains at corresponding sweeps; use per-chain traces for posterior uncertainty and diagnostics. Top-level final_* values average endpoints, not posterior draws. Per-chain scheduling counters are scheduled_marker_updates and scheduled_full_sweeps. Log-CPO uses retained training draws and is distinct from held-out prediction accuracy.

The gact individual-level example shows sparse-trait BayesC/BayesR with training-only preparation and held-out scoring. Its advanced study preserves the original short-run sparse/polygenic comparison and records quantity-specific prediction, variance and mixture diagnostics.

Annotation-informed block-eigen regression

method = "sbayesrc" fits a single checked summary trait with an annotation-informed BayesR prior. The Glist must contain a verified independent block partition. Each LD block is loaded and decomposed once per fit, and the prepared immutable factors are shared by all chains.

Glist <- gbase::define_ld_blocks(
  Glist,
  data.frame(
    block_id = block_table$block_id,
    first_marker = block_table$first_marker,
    last_marker = block_table$last_marker
  )
)

component_design <- as.matrix(annotation_table[fitted_markers, , drop = FALSE])

fit <- gbayes::gbayes(
  stat,
  Glist,
  method = "sbayesrc",
  annotation = list(component = list(design = component_design)),
  control = list(
    eigen_control = list(retained_positive_mass = 0.995),
    block_eigen_residual = list(mode = "all_mix")
  )
)

The block residual update is defined on retained response coordinates: each block uses the squared retained response norm and retained rank. This is an explicit reduced-space likelihood and is not an assertion of identical normalization to GCTB or another SBayesRC implementation. Set retained_positive_mass = 1 to retain every positive eigenvalue. On a full-rank block-diagonal reference with fixed block residuals, this route reduces to the ordinary bayesr sufficient-statistic fit.

fit$diagnostics$block_eigen records block loads, eigensystem decompositions, retained ranks, discarded positive mass and peak dense-block memory. The factors remain native working state; the returned fit is serializable and continuation restores sampler state without serializing dense eigenvectors.

When genotype coding is identified, fit$weights is directly consumable by gscore(). This includes block-eigen SBayesRC fits; scoring uses the portable posterior mean weights and does not need the fitted eigensystems:

For pathway or other marker-set scores, pass a uniquely named list of marker IDs. The target Glist resolves their BED locations and the native scorer handles overlapping or cross-file sets in one pass:

  sets = marker_sets,

Simple individual-level defaults

Scalar individual BED fits can omit prior: gbayes initializes half the observed phenotype variance as residual variance and half as nominal genetic variance. BayesC starts with inclusion probability .001; BayesR starts with weights (.95,.02,.02,.01) and multipliers (0,.01,.1,1). The marker-scale variance is VG/(m times mixture variance mass), using standardized genotype coding. This is a starting heuristic, not an empirical estimate of heritability or causal count. Variance learning uses df=4 and scale=initial variance/2; mixture learning uses unit Beta/Dirichlet concentrations. These learning priors are separate from initial mixture probabilities. Automatic runs use 1000 burn-in and 2000 sampling sweeps, thinning 5, seeds 1 and 2, one thread, retained diagnostics and full sweeps. Control overrides remain available. Explicit nonempty priors retain the existing opt-in learning controls and require proper learning priors when enabled. Scalar BED responses are centred internally without rescaling; the default likelihood dimension is n-1. The phenotype mean is recorded in provenance. An omitted prior during continuation reuses the saved prior and transition controls. Inspect $prior, $control and $posterior; default sweep counts and the R-hat/ESS screening message do not guarantee convergence.

Exact cross-product BayesC and BayesR
