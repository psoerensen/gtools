Bayesian regression from summary statistics

Fit BayesC and BayesR, inspect parameter learning and reuse marker effects.

Start with aligned statistics and LD

gbayes() exposes the native Bayesian regression library through gsuite. Use gmap() for regional fine-mapping and colocalisation; use gbayes() when the main result is a regression fit, parameter learning and marker effects. Both interfaces reuse the same native samplers.

For one continuous trait, stat is a data frame with marker, allele1, allele2, beta_std and n, in exactly the marker and allele order of an LDlist prepared by ldprep(). allele1 is the counted allele. Alignment is a separate task: no markers are flipped or removed here.

beta_std means the marginal effect on a standardized phenotype per standardized dosage. A raw per-allele GWAS beta must be converted using compatible genotype and phenotype scales before it is passed here. Do not rename a raw beta or z-score column to beta_std. The native preparation uses

\[ C = D_N^{1/2} R D_N^{1/2}, \qquad s_j = N_j\widehat\beta_{j,\mathrm{std}}. \]

Here \(R\) is the supplied LD correlation matrix. With common sample size \(N\), \(C=NR\). Different sample sizes require explicit control=list(sample_size="variable"); this is an approximate Gaussian summary likelihood, not reconstruction of an unknown sample-overlap matrix.

Fit and inspect

Specify variances on this standardized scale. They remain fixed unless learning is requested; the values below illustrate a choice, not a universal default.

library(gsuite)
fit <- gbayes(stat, LD, method="bayesr", trait="height",
  prior=list(residual_variance=1, effect_variance=.04,
             weights=c(.9,.04,.04,.02)),
  control=list(burnin=1000, sampling_sweeps=4000,
               seeds=c(31,97), threads=1))
fit
summary(fit)
head(fit$estimates)
fit$parameter_mean
fit$posterior

BayesR uses a null component and effect-variance multipliers c(0,.01,.1,1) by default. BayesC instead uses a single nonzero component and an inclusion_probability. The returned marker means, variances and PIPs pool the retained draws across chains. They are labelled by marker and alleles. These marginal PIPs are not component credible sets.

fit$posterior reports native parameter means, intervals, HPD intervals, R-hat, bulk effective sample sizes and Monte Carlo standard errors, with availability and estimation status. Fixed quantities are labelled as fixed; they do not provide evidence of convergence. fit$chains retains each chain’s marker means/PIPs and compact parameter traces. Marker draws are not retained. retain_diagnostics=FALSE disables these traces and reports their summaries as unavailable. Review diagnostics and sensitivity to prior choices before interpreting results; completing the requested sweeps does not certify convergence.

Learn effect variance and mixture weights

learned <- gbayes(stat, LD, method="bayesc", trait="height",
  prior=list(residual_variance=1, effect_variance=.04,
    inclusion_probability=.05,
    effect_variance_prior=list(df=4, scale=.04),
    weight_prior=c(38,2)),
  control=list(burnin=1000, sampling_sweeps=4000, seeds=c(31,97),
    estimate_effect_variance=TRUE, estimate_weights=TRUE))
summary(learned)

The variance hyperprior is scaled inverse chi-square; scale is not its mean. The weight hyperprior contains positive Dirichlet concentrations, null component first. The supplied effect variance and weights initialize learning. All updates and posterior summaries run in native gbayes. Residual variance remains fixed: its learning needs additional sufficient statistics and is not exposed here.

A complete example and reusable effects

Download the R example. It uses gsim to simulate one trait for 10,000 individuals and 40 markers, prepares a full LD reference, fits fixed-parameter BayesR and learning BayesC, then applies posterior-mean effects to another dosage matrix. It also simulates three traits in the same individuals and fits a joint BayesR model with covariance and mixture-weight learning, as described below. Run it using development installations of gsuite and gsim:

source("run_gbayes_workflow.R")
result <- readRDS("build/examples/gbayes-workflow/workflow.rds")
summary(result$learned)
result$weights
result$scores
summary(result$multivariate$fit)
result$multivariate$fit$estimates$pip
result$multivariate$scores

Outputs stay under build/examples/gbayes-workflow; rerunning replaces those example outputs. Set options(gsuite.bayes.out="another-directory") first to choose a different location. The serializable result bundle contains both fits, statistics, LD descriptor, labelled weights and the coding needed for scoring. Fits can be inspected after reloading without reopening LD or genotype files.

Apply effects to dosage columns in the same order, with matching counted alleles and the same centering/scaling used in preparation:

weights <- fit$estimates[,c("marker","allele1","allele2","mean")]
stopifnot(identical(colnames(target), weights$marker))
target_z <- sweep(sweep(target, 2, center), 2, scale_x, "/")
score <- drop(target_z %*% weights$mean)

These scores have standardized phenotype units and no intercept. The calculation illustrates weight reuse, not prediction accuracy. Production scoring belongs in gscore; this milestone does not add a gscore R interface.

Execution and current scope

The fit consumes existing sparse LD files and does not need genotype files. Default storage="memory" materializes sparse LD, including its reverse index, but never a dense matrix. max_ld_entries=1e7 limits stored upper-triangle entries; it is not a total RAM limit. Memory also grows with markers and chains. For larger resources, storage="disk" uses the native bounded column reader and requires threads=1. threads>1 with memory storage parallelizes chains, not marker updates. Exact seeds are recorded and thread allocation does not change a chain’s random-number stream.

Omitted LD entries are treated as zero. The supplied matrix is assumed positive semidefinite; truncating or thresholding LD can violate this, and the interface does not silently repair it. Reference mismatch remains a separate concern. The example uses complete, matching LD to keep these issues out of the demonstration.

Annotation controls and multiple reference panels/providers per trait remain native-only. Regional sets and colocalisation remain in the mapping workflow.

Fit several traits jointly

Pass a uniquely named list of standardized summary-statistic data frames. Every trait must match the same complete LD marker/allele order. The return values use these trait names and marker IDs throughout; nothing is silently reordered.

stats3 <- list(height=height_stat, weight=weight_stat, lipid=lipid_stat)
traits <- names(stats3)
V <- matrix(.01,3,3); diag(V) <- .04
dimnames(V) <- list(traits,traits)

# Omega is a justified fixed sampling-error covariance, in the same trait order.
joint <- gbayes(stats3, LD, method="bayesr",
  prior=list(effect_covariance=V,
    pattern_weights=c(.9,rep(.1/7,7)),
    covariance_prior=list(df=6,scale=V*2),
    pattern_prior=c(18,rep(2/7,7)), component_prior=c(1,1,1)),
  sampling=list(dependence="shared_ld", covariance=Omega),
  control=list(burnin=1000, sampling_sweeps=2000, seeds=c(31,97),
    estimate_covariance=TRUE, estimate_pattern_weights=TRUE,
    estimate_component_weights=TRUE))

joint
summary(joint)
joint$estimates$mean                 # marker x trait posterior means
joint$estimates$pip                  # marker x trait marginal PIPs
joint$estimates$any_pip              # active in at least one trait
joint$parameter_mean$effect_covariance
joint$expected_trait_sharing        # expected marker counts per trait pair
joint$posterior                     # native intervals and chain diagnostics

effect_covariance is the covariance of latent base effects. It is not realised genetic covariance or genetic correlation: activity patterns, magnitude scales and LD also determine those quantities. The inverse-Wishart prior uses explicit degrees of freedom and a scale matrix. A proper prior requires \(\nu>T-1\); its mean is \(\Psi/(\nu-T-1)\) when \(\nu>T+1\). Learning is optional and all three flags default to FALSE; omit unused hyperpriors for fixed-parameter fits.

State the sampling assumptions

Input Meaning and requirements
sampling=list(dependence="independent", residual_variance=c(height=1,weight=1,lipid=1)) Explicitly independent sampling errors. Common sample sizes may differ between traits. Genetic effects can still be correlated.
sampling=list(dependence="shared_ld", covariance=Omega) Correlated sampling errors with common N across all traits/markers, one shared LD operator and a fixed positive-definite covariance.

Shared LD uses \(E(S)=CB\) and \(\operatorname{Cov}(\operatorname{vec}S)=\Omega\otimes C\). Omega is neither a genetic covariance matrix nor a matrix of overlap counts. The simulated example obtains it from the known residual covariance, transformed to standardized phenotype units. Real data need a justified estimate/input on that scale. The interface does not infer overlap or estimate this covariance. Arbitrary differing LD and marker-specific overlap are outside this route.

Independent summaries additionally allow control=list(sample_size="variable"). That approximation requires explicit named sampling$study_sample_size metadata as well as per-marker n. Study sizes do not replace the per-marker values. No mean or maximum sample size is invented. Residual scales stay fixed in both modes.

Activity patterns and magnitude components

With three traits, the native default pattern order is 000,100,010,110,001,101,011,111: the first trait varies fastest and the null pattern comes first. pattern_weights assign probabilities to these patterns; the default is uniform. The example puts 0.9 on the null and shares 0.1 across the nonnull patterns.

Multivariate BayesC has one positive magnitude scale, 1. BayesR defaults to scales c(.01,.1,1) with equal weights conditional on a nonnull pattern. Unlike the single-trait weights argument, component_weights has no null component: null is already represented by pattern 000. This is a factorized pattern-by-scale mixture, not an unrestricted weight for every pattern/component combination. For BayesC, omit component_prior and estimate_component_weights.

Complete patterns are available for 2–12 traits, but there are \(2^T\) of them. For more traits, or a scientifically restricted model, supply an explicit binary matrix with labelled trait columns, unique row labels and the null first:

patterns <- rbind(none=rep(0,length(traits)), shared=rep(1,length(traits)))
colnames(patterns) <- traits
# Use prior=list(effect_covariance=V, patterns=patterns,
#                pattern_weights=c(none=.9,shared=.1)) for a fixed prior.

This changes the model to allow only those patterns; it is not an approximation to fitting every pattern. Every trait must appear in an allowed nonnull pattern. Trait count is not restricted to two or three. The native memory estimate is bounded by control$memory_limit_bytes (256 MiB by default), separately from LD storage and R result storage. Compact traces contain covariance and mixture parameters; all-marker draws and per-marker pattern-probability arrays are not retained.

The returned fit is serializable. To reuse the joint effects, multiply a compatible standardized dosage matrix by joint$estimates$mean; columns of the resulting score matrix retain the trait names. This demonstrates reuse and is not a prediction-accuracy assessment.

Let annotations inform the prior

annotation separates three questions: which markers are active, which magnitude component they belong to, and their relative effect variance. It connects the existing native annotation models; it does not change the LD preparation or sampling-error assumptions.

Role Single trait Multiple traits
inclusion BayesC logistic inclusion probability Use pattern
pattern Not applicable Continuation-probit probabilities over declared trait patterns
component BayesR continuation-probit probabilities, including the null component BayesR probabilities over positive magnitudes, conditional on a nonnull pattern
variance Centred log-linear relative effect variance One marker multiplier scaling the latent effect-covariance matrix

Each role accepts its own numeric design matrix. Row names must match the LD marker IDs exactly; column names must be unique. Binary or continuous columns are allowed, including overlapping annotations. Native preparation centres each column across the supplied markers, without standardising it. Do not add an intercept column. Annotation units therefore affect the coefficient prior.

Using the data from the example script:

# Artificial annotations; they do not represent biological categories.
A <- cbind(category=as.numeric(seq_len(m) %% 3L==0), position=seq_len(m)/m)
rownames(A) <- ids

annotated <- gbayes(stat, LD, method="bayesc",
  prior=list(residual_variance=1/scale_y^2, effect_variance=.04,
             inclusion_probability=.05),
  annotation=list(inclusion=list(design=A), variance=list(design=A)),
  control=ctl)

annotated_joint <- gbayes(stats3, LD, method="bayesr",
  prior=list(effect_covariance=V, pattern_weights=pattern_weights),
  sampling=list(dependence="shared_ld", covariance=Omega),
  annotation=list(pattern=list(design=A), component=list(design=A),
                  variance=list(design=A)),
  control=list(burnin=1000, sampling_sweeps=2000, seeds=c(31,97)))

annotated$annotations$inclusion$coefficient_mean
annotated_joint$annotations$pattern$prior_probability_mean
annotated_joint$annotations$variance$multiplier_mean
annotated_joint$posterior  # coefficients, intervals and native chain diagnostics

These additional fits reuse the same 10,000 individuals and 40 markers. They illustrate model specification and returned quantities, not evidence for annotation enrichment or a performance comparison.

Fixed coefficients, learning and interpretation

Each annotation model defaults to learn=TRUE, coefficient_prior_sd=1 and update_every=1. Set learn=FALSE to hold its coefficients fixed. For inclusion or variance models, initial is a vector named in design-column order; omitted values start at zero. For example:

annotation=list(variance=list(design=A, learn=FALSE,
                             initial=c(category=.2, position=-.1)))

BayesC inclusion uses a logistic model around inclusion_probability, which remains the baseline at zero centred annotations. It may still be learned with estimate_weights=TRUE and weight_prior. Its coefficient update uses a fixed random-walk proposal_sd=.1; proposal and acceptance counts are returned per chain. There is no automatic proposal adaptation.

Pattern/component annotations instead replace global weight learning for that axis. Disable estimate_weights for scalar BayesR, or the corresponding estimate_pattern_weights / estimate_component_weights flag for multivariate fits. Global weights still supply default intercept-prior centres. Other axes and effect-variance/covariance learning can remain enabled.

Continuation-probit models follow the declared category order. Each stick is labelled by the category where it can stop; the last category has no stick. Scalar BayesR labels are component_0,... (null first); multivariate magnitude labels are component_1,... (positive scales only). Pattern labels are the rows of prior$patterns. Optional intercept_means is named in stick order. Optional initial is a matrix with rows (Intercept) followed by annotation names, and columns in stick order. intercept_prior_sd defaults to 1. Changing category order changes this prior model.

Variance annotations multiply the base variance/covariance by \(\exp(\widetilde A_j\theta)\). At each draw these multipliers have geometric mean one across markers; their posterior means need not. There is no variance intercept. The native elliptical-slice update uses maximum_evaluations=10000 by default; exhausted budgets raise an error.

fit$annotations contains coefficient means/variances, design means, labelled marker prior probabilities or variance multipliers, and per-chain coefficient traces and update counts. Prior probabilities are averaged over retained draws; they are not posterior marker PIPs, which remain in fit$estimates. Coefficient intervals and diagnostics join fit$posterior. Fixed coefficients are labelled as fixed; retain_diagnostics=FALSE disables traces and intervals while retaining posterior means. Review mixing before interpreting coefficients, especially for correlated or weakly informed annotations. Annotation-group covariance models and partitioned genetic-variance summaries are not exposed here.
