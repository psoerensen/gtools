Architecture

A short map of gsuite packages, shared data and computational responsibilities.

gsuite brings together R packages, native computational libraries and analysis guides for statistical genetics. You usually work through a task-specific R package or the standalone mixed-model command; the native libraries do the computation underneath.

The authoritative gbayes R design specifies the target six fitters and shared resource, result and execution contracts, with no backward-compatibility requirement. The initial bayes/mbayes packed BayesC/BayesR adapters reuse the existing native samplers and share a labelled bayesfit result, resolved execution plan and scientific access. The R/native bridge supplies prepared response cross-products and likelihood dimension to joint residual learning. The sbayes/msbayes summary adapters share that result contract and reuse the existing checked scalar/joint summary samplers. Sbayes supports sparse or block-eigen LD; msbayes supports sparse shared or independent study-specific references with an explicit sampling declaration. Summary prediction is unavailable without identified training coding. Blr/mblr consume exact labelled common-design cross-products through the same samplers/result contract; their R/native bridge constructs shared immutable cross-products and private chain state. PSD/rank/scatter validation and explicit saved prediction transforms preserve supplied feature units. Mbayes bayesFA/bayesFR now use the common contract and existing factor samplers. FA constructs one additive relationship internally through public gmat/gbits interfaces, preserving selections/frequencies, excluding/reporting monomorphic markers and normalizing mean diagonal to one. There is no supplied K or Glist$K. FR retains per-draw total-effect reconstruction, distinct activity summaries and saved sample-SD coding. Chains are serial and diagnostics are scoped to retained invariants; paused mixing limits remain.

All six public fitters finish through one R result boundary. It validates the versioned structural fields, ordered effect axes, final states and logical-chain identities after route-specific formatting. Missing availability entries receive truthful stored-value status and explicit unsupported reasons; factor prediction status preserves its training-only FA and saved-coding FR limits. Provenance records R/package versions alongside native metadata. This boundary changes no sampler, prior, numeric result or qualified prediction/continuation capability.

Individual C/R continuation restores existing native full checkpoints through the common bayes/mbayes fit contract. R validates same-build/data/resource identity and preserves global thinning with at most one checkpoint advance; no sampler transition is duplicated. Resumed summaries cover the added segment. Full resource hashing and mandatory checkpoint/segment allocations are checked. The summary C/R adapters also restore existing native checkpoints, binding harmonized scores/N, trait/provider maps, sampling policies and full prepared LD bytes; eigen fits additionally bind verified blocks and eigen settings. Their global thinning and segment-summary semantics match individual C/R. Cross-product C/R adapters restore the same full native states through existing Rcpp control slots. R binds exact checked XX/Xy/yy, n, feature/trait labels, prediction coding and likelihood dimension, preserving supplied units, global thinning and added-segment summaries. The declared gbase dependency is initialized before runtime fingerprinting. No native numerical or bridge changes are added. Specialized-summary, annotation and factor continuation remain outside these contracts.

Individual C/R posterior capture reuses native covariance, partition and selected score accumulators. R checks explicit reference/target identities and memory, prepares target copies with saved fitting coding, repairs known scalar coordinate labels, and maps native moments/traces into bayesfit. Observational capture consumes no RNG or extra sampler transitions, including resumed segments. Full effect draws and the remaining method/interface capture gates are unchanged.

Cross-product C/R capture shares the checked fitting XX operator with native covariance/partition accumulators through a thin Rcpp adapter. The explicit reference=“training” request reports B’ XX B / likelihoodDimension in supplied feature coordinates; projected designs retain their projected interpretation. No LD or allele semantics are inferred. Public access reuses the common quantity formatter with explicit component/variance-ratio meanings, feature/reference identity, budgets and ordinary-prediction availability. Native numerical library sources and sampler transitions are unchanged.

Summary C/R capture shares that formatter and uses the existing native accumulators on sparse/scalar-eigen and joint sparse likelihoods. Covariance reporting requires an explicit aligned sparse-LD reference over all fitted markers, including study unions, independently of fitting LD/eigen policies. Partition activity needs no reference; covariance and explicit-denominator h2 retain their native meanings. Per-call capture excludes discarded continuation advances and preserves states/RNG. Summary coding/intercept identification and prediction gates remain in place; no native computation is added.

Scalar bayes/sbayes now expose bayesRC through the existing native annotation sampler. The R resolver separates pi-derived coefficient starts from proper Gaussian priors and maps updatePi to annotation learning without a global Dirichlet update. Sbayes requires verified block-eigen LD and records its separate block residual policy. Native summaries keep prior probabilities, posterior allocations and per-chain coefficient traces distinct in bayesfit. No new sampler, joint RC model or full sblr parity is implied.

Sbayes also exposes existing point-normal and continuous-shrinkage MCMC through a serial native orchestration bridge sharing one immutable LD preparation. Point-normal preserves all-postburn conditional means and requires thinning one; shrinkage uses verified blocks and the common completed-multiple retention map. Method-specific scale/learning contracts and available paths remain distinct. Missing variances, PIPs, traces and RNG checkpoints are not manufactured.

Sbayes variational/mixture_variational routes use the same common fit contract over existing native fixed-prior mean-field solvers. A budgeted R/native boundary checks LD and replicated mixture-state allocations before fitting. Whole-panel coordinate convergence, ordered-window approximation and relative objective endpoints retain separate meanings. Fixed priors are not posterior parameter estimates; sampled chains, responsibilities and absolute ELBOs are unavailable.

The common bayes/mbayes/blr/mblr adapters accept method="bayesCM" and algorithm="vbayes", resolving fixed covariance dictionaries and optional native residual EB. Variational results use the shared schema with explicit optimization/availability diagnostics and no MCMC chains. Joint packed missing outcomes use the published native route; complete scalar packed CM uses bounded exact Gram preparation. The design records current source, normalization and prediction limits. The existing development Bayesian R facade accepts method="bayesCM" and algorithm="vbayes" (also the default for this method). The R adapter resolves phenotype-table/Glist or explicit matrix inputs to existing complete, missing or RSS mr.mash numerical APIs. Default covariance patterns/scales and argument aliases are R interface policy; inference remains in gbayes. Historical routes are unchanged. Bayesian YAML is not required for this R workflow.

The same facade maps method="bayesFA" and method="bayesFR", with algorithm="mcmc" as the default, to the existing mega_lmm and mega_bayesc native routes. It normalizes phenotype tables, keeps the bayesFA relationship kernel explicit, and maps familiar sampling controls to retained draws and chain seeds. Native priors, separate-chain outputs and scientific limits are unchanged. No additional numerical implementation or YAML schema is introduced.

For an analysis, start with Methods or the tutorials. For implementation contracts and detailed limits, use the Architecture reference.

Native capabilities and R availability

The direct SumHer workflow keeps LD-score calculation in gmat with the gbase R adapter, and paired fitting in gcorr with the standalone gcorr R adapter. R checks labels and shapes; regression and jackknife execute in native code. The default SumHer dispatcher uses stored D scores; the previous estimator remains available explicitly.

Native gbayes owns a separate bounded MegaLMM factor MCMC backend with one relationship kernel, loading shrinkage, variance-proportion grids and supplied outcome masks. It reuses gsolve and existing Gaussian/BayesC primitives without calling greml’s REML optimizer or changing mr.mash. Covariance and prediction summaries handle factor sign ambiguity. A separate native MegaBayesC marker chain learns marker-to-factor and direct effects, sparse loadings and their inclusion/slab/order scales. It uses installed gsolve operations, preserves separate activity summaries and saves training genotype coding for prediction. The standalone gbayes R package owns its R adapters and Bayesian YAML runner (gbayes.model/v1); the standalone mixed-model YAML schema is unchanged. Both factor routes are bounded to 256 samples, 128 traits and 16 factors; the marker route also limits markers to 4096. The packed marker route is resident, not a streaming implementation. New-kernel MegaLMM prediction and arbitrary fixed-covariate fitting remain unavailable, and full-model MegaBayesC mixing remains unresolved. Large-scale qualification remains separate.

Native gbayes also owns supplied-dictionary mr.mash-rss and complete-data individual mr.mash variational regression. It shares genotype/LD operators and gsolve conditioning with the ecosystem, while retaining a separate inference backend from multivariate BayesC/BayesR. This development route supports PSD covariance mixtures, learned weights and a bounded native prediction adapter. Dense and existing packed BED individual adapters share the inference engine. Exact common-sample C,S,H or individual residuals permit optional full/diagonal residual-covariance empirical Bayes; reference-LD summaries retain fixed covariance. Complete outcomes and consistent training centering are required. An additive missing-outcome adapter shares the engine and implements published conditional imputation/intercept updates, with covariance and entropy corrections. Its augmented variational bound is separate from the observed-data likelihood diagnostic. Joint fixed-covariate, relatedness and latent-factor learning are not included. Its R/YAML adapter lives in the task package and adds no task-neutral gbase computation. Calibration, external-LD robustness and large-scale performance remain unqualified.

Packed individual mr.mash and MegaBayesC adapters reuse the existing immutable BED provider and Glist physical indices. MegaBayesC fetches one decoded marker column at a time and retains its sample-SD/centered-raw coding. mr.mash BED keeps HWE coding. Both estimate imputation frequencies on selected training samples; packed prediction reuses training coding and validates marker metadata.

Seven standalone genomic R packages are public source releases. The root gsuite R integration is development software; a root R package release is not planned, and greml/gsolve R packaging is deferred. The standalone command is gsuite run model.yml; binary availability is described on Downloads. Public and development versions can differ: check the release-status table.

Shared genomic resources

Glist carries checked genotype-panel identities and references to prepared resources, including LD where available. Analysis packages reuse that shared preparation rather than inventing their own genotype formats. Marker order, alleles, reference samples and covariance assumptions still need explicit checks. See the resource contracts.

Analysis flow

  1. Genotypes or summary statistics.
  2. Checked shared preparation.
  3. Task-specific analysis.
  4. Labelled results and diagnostics.

For example, glma::vegas() prepares gene evidence and gsea::gsea() analyses sets of genes. Required cross-gene covariance is a separate input, not something inferred by passing results between packages. See the connected pathway guide.

Mixed models and numerical methods

greml owns the statistical model, estimation and prediction. gsolve owns general numerical operations such as factorization and iterative solving. Available models, interfaces and uncertainty estimates depend on the chosen route; use the model catalog and its qualification notes.

The standalone frontend parses YAML and indexes observation/factor levels. Its DMU import/export frontend translates a documented ASCII linear-model subset between that YAML contract and DMU files, with source hashes, ID mappings and explicit exclusions. It introduces no numerical route or DMU runtime dependency. Wide fixed-design rank certification assembles sparse cross-products in the native driver and factors them through the public gsolve interface; it does not add a Python sparse-matrix dependency. Wide packed preconditioning likewise assembles fixed-effect precision from native records, uses a sparse inverse and bounds only the global aggregate correction. gsolve owns the reusable additive subspace action. Statistical equations and full coefficient dimensions remain owned by greml.

Dependency rules

Standalone job admission is separate from numerical libraries: development builds disable enforcement by default. An enforcement-enabled build requires annual entitlement for new jobs while admitted jobs finish. There is no runtime bypass. This is not a cleared commercial release; see standalone installation.

Task packages share task-neutral contracts through gbase; they do not depend on the root gsuite R package. Native libraries are reused through installed public interfaces. Statistical ownership stays with the analysis package. Developer details are in package boundaries and the dependency reference.

Direct regression summaries

The newer BLR and direct set-summary interfaces are development features in gbayes 0.1.6 and gsea 0.1.2, absent from the public 0.1.1 archives. See the release status and technical description.

Implementation does not imply broad statistical or performance qualification. Keep the current qualification limits and method-specific evidence alongside any capability claim.

Standalone observation precision, spatial residuals, selected prediction contrasts and additional-effect REML reuse greml’s model/session contracts. Genomic and parent-product matrix kernels belong to gmat; gsuite’s YAML layer binds inputs and labels results. These additions leave the existing R interface contracts separate. See model capabilities and limits.
