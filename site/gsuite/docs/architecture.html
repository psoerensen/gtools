Architecture

A short map of gsuite packages, shared data and computational responsibilities.

gsuite brings together R packages, native computational libraries and analysis guides for statistical genetics. You usually work through a task-specific R package or the standalone mixed-model command; the native libraries do the computation underneath.

The authoritative gbayes R design specifies the target six fitters and shared resource, result and execution contracts, with no backward-compatibility requirement. The initial bayes/mbayes packed BayesC/BayesR adapters reuse the existing native samplers and share a labelled bayesfit result, resolved execution plan and scientific access. The R/native bridge supplies prepared response cross-products and likelihood dimension to joint residual learning. The sbayes/msbayes summary adapters share that result contract and reuse the existing checked scalar/joint summary samplers. Sbayes supports sparse or block-eigen LD; msbayes supports sparse shared or independent study-specific references with an explicit sampling declaration. Summary prediction is unavailable without identified training coding. Blr/mblr consume exact labelled common-design cross-products through the same samplers/result contract; their R/native bridge constructs shared immutable cross-products and private chain state. PSD/rank/scatter validation and explicit saved prediction transforms preserve supplied feature units. Mbayes bayesFA/bayesFR now use the common contract and existing factor samplers. FA constructs one additive relationship internally through public gmat/gbits interfaces, preserving selections/frequencies, excluding/reporting monomorphic markers and normalizing mean diagonal to one. There is no supplied K or Glist$K. FR retains per-draw total-effect reconstruction, distinct activity summaries and saved sample-SD coding. Chains are serial and diagnostics are scoped to retained invariants; paused mixing limits remain.

All six public fitters finish through one R result boundary. It validates the versioned structural fields, ordered effect axes, final states and logical-chain identities after route-specific formatting. Missing availability entries receive truthful stored-value status and explicit unsupported reasons; factor prediction status preserves its training-only FA and saved-coding FR limits. Provenance records R/package versions alongside native metadata. This boundary changes no sampler, prior, numeric result or qualified prediction/continuation capability.

Individual C/R continuation restores existing native full checkpoints through the common bayes/mbayes fit contract. R validates same-build/data/resource identity and preserves global thinning with at most one checkpoint advance; no sampler transition is duplicated. Resumed summaries cover the added segment. Full resource hashing and mandatory checkpoint/segment allocations are checked. The summary C/R adapters also restore existing native checkpoints, binding harmonized scores/N, trait/provider maps, sampling policies and full prepared LD bytes; eigen fits additionally bind verified blocks and eigen settings. Their global thinning and segment-summary semantics match individual C/R. Cross-product C/R adapters restore the same full native states through existing Rcpp control slots. R binds exact checked XX/Xy/yy, n, feature/trait labels, prediction coding and likelihood dimension, preserving supplied units, global thinning and added-segment summaries. The declared gbase dependency is initialized before runtime fingerprinting. No native numerical or bridge changes are added. Specialized-summary, annotation and factor continuation remain outside these contracts.

Individual C/R posterior capture reuses native covariance, partition and selected score accumulators. R checks explicit reference/target identities and memory, prepares target copies with saved fitting coding, repairs known scalar coordinate labels, and maps native moments/traces into bayesfit. Observational capture consumes no RNG or extra sampler transitions, including resumed segments. Full effect draws and the remaining method/interface capture gates are unchanged.

Cross-product C/R capture shares the checked fitting XX operator with native covariance/partition accumulators through a thin Rcpp adapter. The explicit reference=“training” request reports B’ XX B / likelihoodDimension in supplied feature coordinates; projected designs retain their projected interpretation. No LD or allele semantics are inferred. Public access reuses the common quantity formatter with explicit component/variance-ratio meanings, feature/reference identity, budgets and ordinary-prediction availability. Native numerical library sources and sampler transitions are unchanged.

Summary C/R capture shares that formatter and uses the existing native accumulators on sparse/scalar-eigen and joint sparse likelihoods. Covariance reporting requires an explicit aligned sparse-LD reference over all fitted markers, including study unions, independently of fitting LD/eigen policies. Partition activity needs no reference; covariance and explicit-denominator h2 retain their native meanings. Per-call capture excludes discarded continuation advances and preserves states/RNG. Summary coding/intercept identification and prediction gates remain in place; no native computation is added.

Scalar bayes/sbayes now expose bayesRC through the existing native annotation sampler. The R resolver separates pi-derived coefficient starts from proper Gaussian priors and maps updatePi to annotation learning without a global Dirichlet update. Sbayes requires verified block-eigen LD and records its separate block residual policy. Native summaries keep prior probabilities, posterior allocations and per-chain coefficient traces distinct in bayesfit. No new sampler, joint RC model or full sblr parity is implied.

Sbayes also exposes existing point-normal and continuous-shrinkage MCMC through a serial native orchestration bridge sharing one immutable LD preparation. Point-normal preserves all-postburn conditional means and requires thinning one; shrinkage uses verified blocks and the common completed-multiple retention map. Method-specific scale/learning contracts and available paths remain distinct. Missing variances, PIPs, traces and RNG checkpoints are not manufactured.

Sbayes variational/mixture_variational routes use the same common fit contract over existing native fixed-prior mean-field solvers. A budgeted R/native boundary checks LD and replicated mixture-state allocations before fitting. Whole-panel coordinate convergence, ordered-window approximation and relative objective endpoints retain separate meanings. Fixed priors are not posterior parameter estimates; sampled chains, responsibilities and absolute ELBOs are unavailable.

The common bayes/mbayes/blr/mblr adapters accept method="bayesCM" and algorithm="vbayes", resolving fixed covariance dictionaries and optional native residual EB. Variational results use the shared schema with explicit optimization/availability diagnostics and no MCMC chains. Joint packed missing outcomes use the published native route; complete scalar packed CM uses bounded exact Gram preparation. The design records current source, normalization and prediction limits. The existing development Bayesian R facade accepts method="bayesCM" and algorithm="vbayes" (also the default for this method). The R adapter resolves phenotype-table/Glist or explicit matrix inputs to existing complete, missing or RSS mr.mash numerical APIs. Default covariance patterns/scales and argument aliases are R interface policy; inference remains in gbayes. Historical routes are unchanged. Bayesian YAML is not required for this R workflow.

The same facade maps method="bayesFA" and method="bayesFR", with algorithm="mcmc" as the default, to the existing mega_lmm and mega_bayesc native routes. It normalizes phenotype tables, keeps the bayesFA relationship kernel explicit, and maps familiar sampling controls to retained draws and chain seeds. Native priors, separate-chain outputs and scientific limits are unchanged. No additional numerical implementation or YAML schema is introduced.

For an analysis, start with Methods or the tutorials. For implementation contracts and detailed limits, use the Architecture reference.

Native capabilities and R availability

The direct SumHer workflow keeps LD-score calculation in gmat with the gbase R adapter, and paired fitting in gcorr with the standalone gcorr R adapter. R checks labels and shapes; regression and jackknife execute in native code. The default SumHer dispatcher uses stored D scores; the previous estimator remains available explicitly.

Native gbayes owns a separate bounded MegaLMM factor MCMC backend with one relationship kernel, loading shrinkage, variance-proportion grids and supplied outcome masks. It reuses gsolve and existing Gaussian/BayesC primitives without calling greml’s REML optimizer or changing mr.mash. Covariance and prediction summaries handle factor sign ambiguity. A separate native MegaBayesC marker chain learns marker-to-factor and direct effects, sparse loadings and their inclusion/slab/order scales. It uses installed gsolve operations, preserves separate activity summaries and saves training genotype coding for prediction. The standalone gbayes R package owns its R adapters and Bayesian YAML runner (gbayes.model/v1); the standalone mixed-model YAML schema is unchanged. Both factor routes are bounded to 256 samples, 128 traits and 16 factors; the marker route also limits markers to 4096. The packed marker route is resident, not a streaming implementation. New-kernel MegaLMM prediction and arbitrary fixed-covariate fitting remain unavailable, and full-model MegaBayesC mixing remains unresolved. Large-scale qualification remains separate.

Native gbayes also owns supplied-dictionary mr.mash-rss and complete-data individual mr.mash variational regression. It shares genotype/LD operators and gsolve conditioning with the ecosystem, while retaining a separate inference backend from multivariate BayesC/BayesR. This development route supports PSD covariance mixtures, learned weights and a bounded native prediction adapter. Dense and existing packed BED individual adapters share the inference engine. Exact common-sample C,S,H or individual residuals permit optional full/diagonal residual-covariance empirical Bayes; reference-LD summaries retain fixed covariance. Complete outcomes and consistent training centering are required. An additive missing-outcome adapter shares the engine and implements published conditional imputation/intercept updates, with covariance and entropy corrections. Its augmented variational bound is separate from the observed-data likelihood diagnostic. Joint fixed-covariate, relatedness and latent-factor learning are not included. Its R/YAML adapter lives in the task package and adds no task-neutral gbase computation. Calibration, external-LD robustness and large-scale performance remain unqualified.

Packed individual mr.mash and MegaBayesC adapters reuse the existing immutable BED provider and Glist physical indices. MegaBayesC fetches one decoded marker column at a time and retains its sample-SD/centered-raw coding. mr.mash BED keeps HWE coding. Both estimate imputation frequencies on selected training samples; packed prediction reuses training coding and validates marker metadata.

Seven standalone genomic R packages are public source releases. The root gsuite R integration is development software; a root R package release is not planned, and greml/gsolve R packaging is deferred. The standalone command is gsuite run model.yml; binary availability is described on Downloads. Public and development versions can differ: check the release-status table.

Shared genomic resources

Glist carries checked genotype-panel identities and references to prepared resources, including LD where available. Analysis packages reuse that shared preparation rather than inventing their own genotype formats. Marker order, alleles, reference samples and covariance assumptions still need explicit checks. See the resource contracts.

Analysis flow

  1. Genotypes or summary statistics.
  2. Checked shared preparation.
  3. Task-specific analysis.
  4. Labelled results and diagnostics.

For example, glma::vegas() prepares gene evidence and gsea::gsea() analyses sets of genes. Required cross-gene covariance is a separate input, not something inferred by passing results between packages. See the connected pathway guide.

Mixed models and numerical methods

greml owns the statistical model, estimation and prediction. gsolve owns general numerical operations such as factorization and iterative solving. Available models, interfaces and uncertainty estimates depend on the chosen route; use the model catalog and its qualification notes.

The standalone frontend parses YAML and indexes observation/factor levels. Its development Linux runner detects the permitted CPU topology and selects native core binding within that mask, while preserving inherited NUMA policy unless interleaving is explicitly selected. Placement decisions are recorded separately from numerical qualification; see execution diagnostics. The greml contract exposes stochastic marginal-pedigree diagonal estimation for preconditioning; the model precision and its exact-diagonal interface remain exact. YAML lowering records explicit probing controls and requires a supporting native driver. Exact setup remains the default. Its LMT frontend separates directive translation from data conversion. A shared input contract binds optional conversion manifests without rereading large data; scientific numeric encoding is recorded and required for manifest reuse, avoiding unbounded decimal mantissas in real-valued exports; unsupported genomic ridge semantics block XML generation. Neither command executes LMT or claims numerical equivalence. See LMT preparation. Sample-mean centered pedigree-moment adjustment maps to LMT’s adjustg2a; the small comparison helper records native gsuite checks separately from live LMT adjustment verification.

Its DMU import/export frontend translates a documented ASCII linear-model subset between that YAML contract and DMU files, with source hashes, ID mappings and explicit exclusions. It introduces no numerical route or DMU runtime dependency. Wide fixed-design rank certification assembles sparse cross-products in the native driver and factors them through the public gsolve interface; it does not add a Python sparse-matrix dependency. Wide packed preconditioning likewise assembles fixed-effect precision from native records, uses a sparse inverse and bounds only the global aggregate correction. gsolve owns the reusable additive subspace action. Statistical equations and full coefficient dimensions remain owned by greml.

Dependency rules

Standalone job admission is separate from numerical libraries: development builds disable enforcement by default. An enforcement-enabled build requires annual entitlement for new jobs while admitted jobs finish. There is no runtime bypass. This is not a cleared commercial release; see standalone installation.

Task packages share task-neutral contracts through gbase; they do not depend on the root gsuite R package. Native libraries are reused through installed public interfaces. Statistical ownership stays with the analysis package. Developer details are in package boundaries and the dependency reference.

Direct regression summaries

The newer BLR and direct set-summary interfaces are development features in gbayes 0.1.6 and gsea 0.1.2, absent from the public 0.1.1 archives. See the release status and technical description.

Implementation does not imply broad statistical or performance qualification. Keep the current qualification limits and method-specific evidence alongside any capability claim.

Standalone observation precision, spatial residuals, selected prediction contrasts and additional-effect REML reuse greml’s model/session contracts. Genomic and parent-product matrix kernels belong to gmat; gsuite’s YAML layer binds inputs and labels results. These additions leave the existing R interface contracts separate. See model capabilities and limits.

Native gbayes development also exposes a fixed-prior continuous Gaussian vector conditional over supplied score/information matrices, reusing gsolve dense SPD solves. This conditional is reused by the bounded native fitting reference below. Ancestry storage, an R interface, model qualification and release remain separate.

Supplied-design Gaussian BOA reference

Native gbayes now provides bounded fixed-covariance Gaussian BOA regression with explicit dense ancestry-specific designs, exact joint posterior moments, same-response marker conditionals and genetic prediction. The caller supplies centred designs and a pre-adjusted response; fixed effects are not jointly fitted. Diagonal and full SPD ancestry priors are supported. This is a native numerical reference (at most 256 effects), with no R interface, packed ancestry operator, ancestry inference, covariance learning, scalable or routine BOA prediction claim. See the component gbayes/docs/boa-gaussian.md contract and development evidence. Implementation and focused numerical validation do not establish population-level scientific calibration, broader qualification or release status.

Ancestry-aware phased genotype operations

Native gbits now provides D, C, D-C*p, forward/transpose products and marker-wise information/residual updates over existing packed H1/H2 and known ancestry labels. Native gmat binds these operations to sample/marker/allele identities, declared phase alignment and training centring frequencies. Inputs use byte ancestry labels; resident labels are now bit-packed; no dense ancestry-expanded matrix or genomic relationship matrix is used by these operations. Missing genotypes, unknown/probabilistic ancestry and unphased dosage are unsupported; no automatic inference, harmonisation or imputation is performed.

Focused explicit genotype arithmetic checks and small gbayes integration examples are distinct from large-scale or scientific qualification. The existing dense BOA fitter remains bounded to 256 effects. Genotype operations alone do not establish a packed fitter, label persistence/streaming, R/YAML interfaces or biobank-scale qualification; the Gibbs route below has separate evidence. See component gbits/docs/design/ancestry_operations.md, gmat/docs/ancestry-panel.md and gbayes/docs/boa-gaussian.md for contracts, resource bounds and method-specific evidence. No release is implied.

Packed fixed-covariance Gaussian BOA sampling

Native gbayes now supplies a systematic marker-block Gaussian Gibbs route over existing gbits/gmat ancestry operations. It maintains one phenotype residual, reuses exact fixed-prior Gaussian conditionals, caches small within-marker covariances, accumulates marginal moments/selected covariance pairs, and supports selected sampling diagnostics, in-memory continuation and ancestry-specific genetic predictions with unchanged training centring. It does not allocate a dense ancestry-expanded design or complete joint marker-effect covariance.

The response is explicitly pre-adjusted and identity-aligned; fixed effects and variances are not learned. Execution remains serial; the initial byte-label storage assessment is superseded by bounded resident bit-packing measurements described below. Small dense-posterior comparisons with Monte Carlo uncertainty and existing regression checks are separate from routine large-panel, mixing/population and scientific qualification. There is no R/YAML interface or release claim. See component gbayes/docs/boa-packed-gibbs.md and its development evidence for contracts, resource bounds and limits. The bounded dense BOA reference remains unchanged.

Gaussian BOA robustness and resident label memory

Controlled native examples now cover ancestry-column aliasing, strong LD, ancestry imbalance and a rare counted allele at frequency .004. Direct conditional and residual checks remain numerically accurate, but LD marker contrasts remain poorly mixed after the tested continuation. Good selected prediction diagnostics do not qualify individual effect covariance estimates or covariance learning. Unsuccessful and inconclusive sampling outcomes are retained in component evidence.

Native gbits now bit-packs resident deterministic labels behind unchanged byte constructor inputs and gmat identity contracts. Bounded measurements show 8x label payload reduction for K=2 and 4x for K=3, with increased CPU cost and unchanged byte-import peak limitations. No new file format, statistical prior, covariance learning, streaming interface or routine biobank-scale qualification is added. See gbayes/docs/boa-robustness.md and gbits/docs/design/ancestry-storage-evidence.md for conditions, measurements, regressions and limits. Earlier validation/release boundaries remain distinct.

Bounded joint-marker Gaussian BOA updates

Native gbayes adds an opt-in fixed marker partition for exact joint Gaussian updates of coupled ancestry effects, using the existing conditional factorization, shared residual, packed marker decoding, summaries, diagnostics and prediction contracts. No more than 64 effects per block or 256 decoded sample rows are used in temporary design calculations. The original sampler and public structure layouts remain available with their established numerical and RNG update branch.

The fixed posterior, input identities and training centring are unchanged. The caller chooses blocks; correlations crossing block boundaries can still limit exploration. Conditional accuracy, Monte Carlo precision, measured resource cost and scientific qualification are recorded separately in gbayes/docs/boa-blocked-gibbs.md. This adds no covariance learning, automatic LD grouping, R/YAML interface, routine large-panel qualification or release claim.

In controlled duplicated-marker examples, keeping that pair together restores the weak contrast variance and substantially increases its effective sample count; splitting the pair remains unsuccessful. Independent Gaussian references and same-build continuation checks support the bounded update. This does not qualify unknown or long-range LD structures, larger partitions or covariance learning. Original unsuccessful evidence remains preserved.

LD-informed Gaussian BOA scheduling

Native gbayes adds fixed bounded partitions derived from an identity-checked gmat sparse LD resource, with optional BOA design scoring for explicitly supplied candidate pairs. Ancestry-specific likelihood-column correlation can differ from ordinary genotype LD. The builder reports strong supplied edges that cross the chosen groups and those left without a scheduled joint visit.

An opt-in route performs fixed cross-boundary Gaussian conditionals at recorded global sweep intervals, reusing the existing posterior and shared-residual calculation. Blocks retain the 64-effect ceiling and bounded sample decoding. The existing manual and single-marker interfaces remain unchanged. Missing graph edges, limited bridge budgets, collective LD and unverified large panels remain explicit limitations. This adds no covariance learning, adaptive priors, R/YAML layer or release qualification. Component contracts and method-specific evidence are in gbayes/docs/boa-ld-partitions.md.

Controlled fixed-covariance examples show improved exploration when a missing minor-ancestry dependence is represented and jointly visited. Collective LD directions still defeat the tested pairwise graphs and limited bridge budgets. Independent Gaussian references and exact continuation support the numerical transition; general partition robustness and covariance learning remain unqualified.

Matrix-free Gaussian BOA inference

Native gbayes now offers an opt-in prior-whitened precision operator over the existing packed ancestry products, deterministic posterior-mean solves and global Gaussian draws using randomized right-hand sides and gsolve PCG. The fixed-covariance, pre-adjusted-response model, sample/marker identities and training centering are unchanged. No genome-wide dense design, cross-product, precision or posterior covariance is formed.

Finite iterative solves produce numerically approximate draws. Independent bounded Gaussian references, tolerance/conditioning checks, selected posterior diagnostics and computational observations remain distinct from scientific or large-panel qualification. Existing single-marker, blocked and boundary routes remain available with their earlier mixing limitations. See component gbayes/docs/boa-packed-global.md for native contracts and evidence. This adds no covariance learning, ancestry inference, R/YAML integration or release claim.

Focused Gaussian reference and posterior comparisons support the selected known-phase LD, ancestry-imbalance and mosaic examples. Extreme-conditioning checks retain rejected covariance solves and inaccurate loose-tolerance draws. A bounded resource observation confirms small operator storage but substantial repeated genotype traversal cost; it does not establish routine large-panel use.

Block preconditioning for global Gaussian BOA inference

Native gbayes provides an opt-in bounded block preconditioner for the same complete prior-whitened Gaussian precision. Supplied disjoint marker blocks reuse installed gsolve factors; cross-block terms remain in every full operator application. The diagonal default, Gibbs routes and training-centering contracts remain available. No automatic block construction or posterior approximation beyond the existing finite solve tolerance is added.

Independent bounded references support means, covariance products, identical-normal draws, prediction, residual reconstruction and tagged continuation. Selected LD/ancestry cases and one 4,096-sample, 2,048-marker resource observation show benefits including setup costs; a poor extended-LD partition instead increased solve time. These observations establish neither universal speedup nor routine large-panel qualification. See component gbayes/docs/boa-block-preconditioning.md for the construction, evidence and costs. Earlier conditioning and partition failures remain applicable; global covariance learning and release remain unqualified.

Hierarchical Gaussian BOA covariance learning

Native gbayes provides an opt-in blocked Gaussian route with a shared inverse-Wishart SNP-effect covariance and fixed residual variance. It reuses packed known-ancestry designs, exact Gaussian conditionals, shared-response residual updates and existing diagnostics. Covariance-dependent factors are rebuilt each sweep; tagged continuation includes the covariance and RNG state. The initial interface supports one to four ancestries and supplied disjoint blocks of at most 64 effects. It has no R/YAML or global-learning interface.

Independent conditional checks and bounded two-ancestry collapsed-posterior references support the implemented route. Prior sensitivity, unobserved ancestry and identical design columns remain identifiability limits. A deliberately poor LD partition failed mixing criteria. The published heavy-tailed prior is supported, with covariance MCSE marked unverified when moment existence is unestablished. Empirical variances and low R-hat do not establish identifiability. See component gbayes/docs/boa-covariance-learning.md for evidence and costs. This bounded capability does not establish routine large-panel qualification, empirical population validation or release; earlier failures remain recorded.

Scientific evidence for Gaussian BOA

A bounded controlled population study compares pooled SNP-BLUP, separate purebred predictions, breed-proportion prediction and native fixed/learned Gaussian BOA. Known ancestry and common supplied centering are retained in future-generation purebred, F2 and backcross targets. Benefits depend on effect heterogeneity and reference composition; pooled prediction is competitive when breed effects are nearly shared. Oracle supplied covariance is distinguished from learned covariance throughout.

The study supports selected synthetic prediction and prior-predictive covariance calibration, while retaining poor boundary/low-variance recovery, prior sensitivity and numerous fits with inadequate Monte Carlo precision. Low R-hat and accurate prediction do not establish covariance identification. Matched-target fixed Gaussian comparisons support bounded blocked, overlapping and global routes; poor LD partitions still fail precision criteria. See component gbayes/docs/boa-scientific-study.md for the frozen design, complete results, costs and qualification decisions. These results establish neither published software parity nor routine large-panel or empirical-population qualification. Production algorithms, native interfaces and public release status are unchanged.

Supplied-tree covariance ownership

The optional installed gmat::arg target owns immutable supplied-tree resources, explicit diploid sample-node identities, branch-area covariance actions, fixed training centering and selected training/target products. It uses installed tskit C behind a private implementation and implements gsolve’s public operator contract. Existing greml covariance sums, REML/RHE and Gaussian prediction retain their statistical ownership. Core gmat::gmat consumers acquire no tskit dependency. This is bounded native numerical research support; genealogy inference, R/YAML integration, population prediction calibration and biobank qualification are absent. See gmat/docs/arg-covariance.md for the initial contract and independent evidence.

Fixed-score environmental moment cache ownership

greml owns GxeMomentCache and its phenotype-specific GxeResponseSummary. They compose installed gsolve operators and checked moment solving; packed callers reuse installed gbits covariance adapters and gmat panel ordering. The generic cache adds no genotype dependency to greml and no R/YAML frontend. Its factorized environmental sketches preserve ordinary fixed-effect projection and avoid an environmental-pair cache. See the owner contract (unpublished greml contract) for resource identity, mathematics and bounded evidence. The separate native sampling_covariance method composes these same operators and installed gsolve probes/checked solves to propagate Gaussian sampling covariance at an explicit SPD-certified working state. Numerical trace MCSE, working-state availability and interval calibration are distinct; there is no additional genomic storage or R/YAML interface. Learned scores, association, production-scale qualification and release remain separate.

Randomized G×E variance-component estimation: ownership

greml owns this capability, which implements the GENIE estimator and retains GENIE attribution. The existing native API GenieMomentCache is unchanged: supplied exposure-specific GxE/NxE kernels, GENIE finite Gaussian-probe moments, heritability fractions and genomic block-jackknife arithmetic. It composes existing installed gsolve operators/checked solves and gbits/gmat packed panel contracts without changing GxeMomentCache or adding a genotype dependency to the generic library. The owner contract (unpublished greml contract) and reference comparison (unpublished greml research report) define the full-rank SPD support domain and differences from original QR/output conventions. Annotation and exact published testing-tail parity remain incomplete. No R/YAML frontend, learned environmental score, new inference engine or release is added.

Annotation and numerical compatibility

greml’s native GenieMomentCache now accepts binary annotation/block operators and intersection counts, using existing gbits products and gmat identity contracts. gsolve owns the additive full-pivot Householder QR solve; greml selects it through the GENIE default reference QR option, retaining checked-SPD as an explicit choice. Statistical ownership includes overlap/deletion normalization and distinct published-result testing conventions. Contract (unpublished greml contract) and algorithmic comparison (unpublished greml research report) retain literal pinned-source quirks and provenance limits. No new storage framework, R/YAML frontend, learned-score engine or public release.

Selected covariance models and missing-data preparation

greml extends the existing GENIE cache with G/G+GxE/full-model selection and explicit original-row masks. Native tabular/one-marker helpers preserve the reference normalization and imputation mapping; gbits still owns decoding and packed products, gmat identities and annotations, and gsolve numerical solves. No new storage or inference engine, R/YAML frontend or dependency was introduced. See the contract (unpublished greml contract) and mathematical/software evidence (unpublished greml research report).

Randomized G×E native file adapter

greml’s existing gsuite_model_driver gxe application route owns keyed BED/phenotype/environment/covariate/annotation orchestration and reports; GenieMomentCache retains the equations and QR default. gmat supplies panel and annotation identities, gbits supplies marker decoding and direct packed covariance products, and gsolve retains projection/factorization/QR ownership. No native library ABI, R/YAML frontend or inference engine is added. The adapter contract (unpublished greml contract) defines alignment, frozen completion, blocks, budgets and output states. Existing routes remain unchanged.

Supervised environmental-score learning ownership

greml owns the new GxeMomentCache::score_objective and fit_score native research members. They reuse its immutable factorized cache, response binding, projection and installed gsolve rank-checked moment solver. Existing gbits/gmat operators supply genotypes and identity; learning adds no operator calls or new dependencies. GENIE and other native routes are unchanged. Regularization, variant splitting, learned-score inference and new R/YAML/file adapters remain outside this bounded capability; operator preparation is not claimed to be a single physical genotype pass.

Regularized score and variant-split ownership

greml owns the source-defined spherical threshold map and split orchestration over its existing GxeMomentCache and gsolve moment solver. Existing gbits/gmat selection, transformation and covariance operators supply disjoint normalized marker subsets. Held-out averages and full-marker refits are separate outputs; full moments combine cached actions before cross-products, requiring no third genotype cache or new kernel calls during fitting. GENIE is unchanged. No new numerical engine, storage format, R/YAML adapter or post-learning inference is introduced, and marker splits do not certify statistical independence.

Environmental-score uncertainty ownership

greml owns the new labelled inference primitives over existing G×E fits, including source-style numerical delta propagation and paired refit records/ observation-group comparisons. gsolve owns Student-t complement probabilities, reusing its private Boost.Math dependency. Existing gmat/gbits contracts still own panels/operators; deletion data and baseline/preprocessing definitions are caller-supplied. GENIE and its jackknife/testing behavior remain unchanged. No new inference engine, storage scheme, R/YAML wrapper or broad qualification is introduced, and probe variation is not silently added to phenotype SEs.

Native environmental-score workflow ownership

greml owns fit_gxe_score_inference: complete observation-group score/baseline refits and paired S2 summaries over supplied ordered y/E/C and native kernel operators. It uses installed gsolve contracts, fixed-transformation row restriction and existing single/variant-split learners; caches are streamed and compact failures retained. This adds no root R interface or numerical dependency. GENIE and the previous score/covariance algorithms are preserved.

ENGINE file adapter ownership

greml’s optional model driver owns the engine BED/keyed-table adapter. It reuses the unchanged GENIE input/QC/completion functions, installed gmat panel identities and gbits direct covariance operators, then calls the existing native environmental-score inference workflow. Observation grouping and explicit supplied starts/baseline/scales belong to this application route; no native solver or estimator changes are introduced. GENIE’s gxe command, root R interfaces and separate public launcher dispatch remain unchanged.

Individual-level RHE in gcorr

The standalone gcorr R package owns rhe() input alignment, Glist orchestration, method-specific summaries and results. greml owns ordinary RHE and GENIE estimation; gsolve owns moment solves and gbits owns packed products. Estimation does not invoke prediction or REML. Source distribution links ordinary RHE from the existing bounded gbase archive and compiles only canonical greml GENIE source in gcorr. The gbase greml closure is explicit and does not follow the expanding full native core. No root gsuite import is required.

Direct LD scores use gbase::gprep(task = "ldscores"). Ordinary values retain the existing lowercase Glist$ldscores per-component layout; architecture arrays and resolved settings are stored separately in Glist$ldscore_models.

SumHer fitting uses gcorr(..., method = "sumher"). The default marginal/pairwise route uses stored D scores when available, retains full-reference contribution totals and returns a distinct SumHer fit class. It returns h2 per trait and rg for all trait pairs. Select sumher_fitter = "standard" for the previous estimator; its compatibility entry point remains unchanged.

The standalone DMU and restricted four-trait LMT adapters share staged data manifests. Directive translation and data conversion are independent operations; the legacy combined DMU commands reuse the same parser and writer. Reverse LMT conversion requires explicit marker/allele metadata rather than inferring it from text dosages.

MiX99 I/2022 CLIM and ASReml-SA 4.2 preparation reuse the shared classification writer and interoperability manifests through classical_interop.py. Directive parsing/rendering is separate from binary64 table conversion; the admitted single-trait identity profiles exclude pedigree/genomic computation and never launch third-party software.
