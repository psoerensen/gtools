Canonical LMM capability catalog

This is the authoritative catalog of LMM routes and their recorded evidence. Status terms are defined in model architecture. Evidence is indexed in model qualification; reusable machinery and exact reductions are in the primitive registry and model reductions.

R interface coverage inventory

This inventory follows the exported constructors, dispatch code and existing test sources; it is not a new numerical qualification run. The single-trait, multitrait, longitudinal, repeatability and direct/maternal tutorial models, plus grouped, AR(1) and exponential residual examples, have been executed with the 10,000-animal pedigree; other rows below still need a comparable user-workflow check. formula and formulas now select the same general gfit() adapter. Starts do not determine dispatch. Explicit scalar components can represent multiple independent pedigree/identity random intercepts. Named grouping vectors additionally declare correlated channels for a single response under a shared kernel. A typed gs_fit_control() explicitly selects the specialized compiled interface with complete starts. The broader public R API still contains capabilities beyond this adapter.

Solver policy and outstanding defaults

Use CHOLMOD with selected inversion as the reference configuration for the new sparse-direct model examples. Selecting CHOLMOD alone is insufficient: coordinate tracing can still do many solves. The three pedigree tutorial models already select linear_solver = "sparse_direct", direct_backend = "cholmod", exact_trace_method = "selected_inverse". The general formula adapter and compiled-control constructor now follow this default; explicit solver choices remain authoritative.

The source currently differs from that policy:

  • General pedigree formulas default to sparse direct, CHOLMOD and selected inversion. Explicit alternative backends use coordinate tracing unless the caller requests another trace method; unsupported requests are not repaired.
  • The four specialized pedigree control constructors default to PCG, automatic backend and coordinate tracing.
  • Compiled gs_fit_control() defaults to CHOLMOD and selected inversion. Its selected-inversion argument is trace_route, not exact_trace_method.
  • gs_lmm_control() already defaults to CHOLMOD. Its public signature does not expose the native component PCG/stochastic/adaptive controls; those native capabilities are a separate R-exposure gap.
  • Dense exact and matrix-free covariance routes are different algorithms; a global CHOLMOD substitution is not applicable to them.

Keep explicit solver choices and clear errors when requested CHOLMOD support is unavailable. Specialized low-level control defaults remain separate. The timing difference observed in the tutorial is not evidence that one backend is universally faster for every model and workload.

Minimal verification programme

Use 10,000 animals/individuals as the default demonstration size for scalable routes, with trait and observation counts stated separately. Tiny deterministic oracle tests remain tiny; dense reference routes and bounded uncertainty targets should not automatically be expanded to 10K dimensions.

Keep this coverage table as the inventory, the existing pedigree tutorial as the introductory example, and reuse build/examples/ for replaceable runtime outputs. Do not create a folder or a dated report for each attempted fit. Promote only selected, reviewed figures and concise results to website sources.

Check each recipe in this order: expressibility through exported R functions, correct model/ID mapping, convergence, result extraction, then agreement with an existing equivalent route or appropriate reference. Passing one example does not requalify every covariance/backend combination.

PARDISO selected inversion is unsupported for every route. PARDISO capability metadata reports this explicitly and no fallback is permitted. Longitudinal pedigree coordinate tracing is a bounded moderate-problem PARDISO route; it does not imply that selected inversion is absent globally. The separate selected_solve cells above use documented retained-factor multi-RHS solves; they do not change PARDISO’s selected-inversion classification.

For incomplete multitrait stochastic REML, covariance optimization, optional approximate restricted likelihood, and all-animal BLUP are separate result capabilities. Score/AI convergence and BLUP can succeed when final SLQ exceeds its requested standard-error limit; in that case likelihood is explicitly unavailable and its estimate, uncertainty, and work remain diagnostic only.

The same separation applies to qualified stochastic component REML. Its missing-channel claim means absent canonical scalar records, not imputation or complete-case deletion. The scalable supplied sparse-precision constructor and structured-residual PCG/stochastic paths are retained implementations, but they are not a completed qualified combination. Supplied precision is fixed-state qualified; its stochastic optimizer is not. AR(1) fixed-state evaluation and stochastic optimization are qualified. Continuous exponential coefficient, derivative, trace, AI, and PCG evaluation is fixed-state qualified, whereas its stochastic optimizer ended in explicit score-merit line-search exhaustion. The combined supplied-precision/structured-residual stochastic illustration was not run. Exact CHOLMOD component capabilities in those rows remain qualified and unchanged.

The optional adaptive component policy preserves those scientific boundaries. It uses deterministic nested probe prefixes and phase-specific PCG tolerances for exploratory, accepted-state, and certification work; the fixed-budget path remains the default. Final convergence is always recomputed with the declared fixed certification prefix and requires score compatibility, deterministic stationarity, and an absolute transformed-parameter uncertainty envelope. Adaptive execution is qualified for the independent-residual identity/ pedigree scope. The bounded FA revisit ended with explicit insufficient parameter-step precision, so it does not change the FA row above.

CHOLMOD support for longitudinal pedigree models

The irregular-record public path is qualified within the scope below. gs_longitudinal_pedigree_reml_control() exposes CHOLMOD selected-inverse traces and prediction error; the same canonical MME is consumed by LongitudinalPedigreeSparseDirectSession; focused native and R tests cover selected-inverse trace parity, retained-factor longitudinal PEV, trajectory uncertainty, and typed work accounting. The PCG block-preconditioned fixed solve and PARDISO coordinate-trace REML profile are independently qualified; they do not replace or weaken the CHOLMOD path.

Named biological models such as permanent environment, litter, herd-year, direct/maternal covariance, random slopes, and reaction norms are component recipes when their relationship and incidence contracts fit gs_lmm_*(). They must not receive duplicate model-specific production engines.

Implemented but unqualified combinations

  • Simultaneous component active boundaries and AR(1)/exponential residual correlation; both mechanisms are qualified separately.
  • Standalone combinations of the public native SparseIndexedCovarianceModel and SparseIndexedRemlSystem that have no matched public R adapter and focused end-to-end qualification.

These are qualification or route-integration gaps, not new global algorithms.

Genuinely unsupported combinations

  • PARDISO selected inversion.
  • Exact selected-inverse PEV from PCG.
  • Cross-component covariance outside channels sharing one relationship group.
  • Active semidefinite boundaries for covariance blocks larger than two, and zero/singular residual covariance.
  • Mixed residual structures in one component fit, heterogeneous temporal marginal scales, ARMA, antedependence, spatial, Matérn, and spatiotemporal residuals.
  • New random-effect levels in prediction rows.
  • Genotype/GRM construction, \(H^{-1}\), and ssGBLUP in the component/pedigree LMM APIs.
  • A general component formula parser; the canonical public component API is constructor-based.

Anti-duplication guard

Future work must not propose selected-inverse infrastructure, selected-inverse trace contractions, bounded retained-factor target solves, complete-MME PEV/reliability, identity/group components, permanent/common environment effects, correlated channels, structured longitudinal residual blocks, scalar/rank-one active boundaries, or existing pedigree/multitrait/longitudinal PCG/direct REML and BLUP as new global capabilities. A future extension must name the exact unsupported or implemented-unqualified cell it changes.

Evidence-based future selection

No additional implementation is needed for longitudinal pedigree CHOLMOD selected inversion or PEV/reliability: that public path is already qualified. Potential bounded future work, if prioritized, is limited to catalogued gaps:

  1. A qualification-only closure for an implemented_unqualified combination, such as component active boundaries together with correlated residual blocks, without adding either mechanism again.
  2. Specialized repeatability uncertainty integration, only if that public convenience route must expose the existing complete-MME machinery rather than using the qualified component recipe.
  3. A genuinely unsupported residual family or prediction contract selected from the catalog, implemented through the existing component and residual abstractions rather than a parallel model engine.

These candidates have no committed implementation schedule. Qualification work should be chosen only when the corresponding public combination is useful.
