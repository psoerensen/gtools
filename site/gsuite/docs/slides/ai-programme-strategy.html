What is AI?

Term Meaning
Artificial intelligence The broad field of building systems that perform tasks associated with human intelligence
Machine learning and deep learning Methods that learn patterns from data. Deep learning uses neural networks with many layers
Generative AI Models that generate text, code, images, audio or other content
AI assistants and agents Systems built around generative AI that can work with users, files and tools. Agents can carry out multistep tasks

This presentation focuses on AI assistants and agents used for data analysis, method and software development, and teaching.

People use the term AI in different ways. Some think of machine learning or deep neural networks used to analyse data. Others think primarily of generative tools such as ChatGPT.

Machine learning covers methods that learn patterns from data. Deep learning is a form of machine learning based on neural networks with many layers. Modern generative AI is largely based on deep learning, but its purpose is to generate new content rather than only produce predictions.

Assistants interact with users and may have access to files and tools. Agents can use these capabilities to carry out more complex, multistep tasks.

This presentation concerns practical AI-assisted work. Applying machine learning as the scientific method being studied is outside its scope.

How researchers use generative AI

Activity Examples
Writing and communication Draft, revise, translate and shorten text
Literature work Find relevant papers, summarise them and compare their conclusions
Data analysis Inspect data, write code, make figures and explain results
Teaching Develop slides, exercises, examples and explanations
Administration Prepare emails, meeting notes, plans and reports

Writing and literature review are common entry points. The same technology can also contribute directly to mathematical, analytical and software work.

Many researchers first encounter generative AI as a writing assistant. It can also help identify literature, organise information, write analysis code and develop teaching material.

These uses still require review. Literature searches must be checked against the original sources, and scientific claims must not be accepted simply because the generated text sounds convincing.

AI can help with mathematical reasoning, coding, analysis and documentation. Researchers set the scientific direction, review the decisions and determine what evidence is sufficient.

These activities are connected but distinct. A data-analysis question may reveal the need for a new statistical method. The method must then be translated into reliable software before it can be used routinely. A validated implementation can support new analyses and become a teaching example.

AI is particularly useful at the connection between mathematics and software. It can help examine equations, compare algorithms, implement them in R or C++, and prepare numerical checks. Researchers define the scientific problem, review the statistical and computational decisions, and decide what evidence is required.

gsuite: developed with AI assistance

A concrete example of method and software development, from numerical algorithms to an R package.

What was developed

  • Numerical algorithms and native C++ code
  • Shared libraries and reusable model components
  • R interfaces, examples and documentation

The development process

  • Discuss mathematics and design with AI
  • Implement and test in the repositories
  • Review decisions and commit accepted changes

The infrastructure exists. Connecting it with assistants for research is the next step.

This presentation uses gsuite as the concrete example behind a strategy for Computational and Statistical Genetics. AI assistance has contributed to the development itself, with scientific direction and review provided by the developer. The contribution spans mathematics, algorithms, code, interfaces and documentation.

The public website explains the work; gsuite remains development software. The platforms were developed first. Bringing them together with an assistant for research workflows is more recent and has only just begun.

Architecture · Numerical foundation

Read the table from top to bottom, following the development from algorithms to the user interface. gsuite is the R-facing package; the numerical and statistical components live in focused libraries behind it.

CHOLMOD and PARDISO are external libraries. The gsolve selected-inverse implementation uses retained CHOLMOD factors. It computes needed inverse entries without forming the full dense inverse; PARDISO is not used for that selected-inverse route. The work also includes the surrounding solver infrastructure, reuse, model computations and R integration.

A Python interface remains a possible future addition, not a current claim. The technical deck contains the repository map and equations.

From a scientific question to a model

Each extension can add capabilities that other models can reuse.

The gsuite ecosystem is a collection of reusable computational building blocks. A scientific question determines the model and method, which determine the components required. Existing components may already provide what is needed. Otherwise, development adds the missing components to the collection.

Availability does not establish that a particular combination is supported. The assembled model still needs statistical and numerical validation, including reference calculations and checks of assumptions, convergence and predictions. AI can help identify, combine, implement and check components. Researchers and developers define the scientific meaning and decide what evidence is sufficient.

A shared collection of building blocks

Bayesian components illustrate an extension direction; current gsuite R support depends on the model and route.

These are conceptual groups, not a repository dependency graph or a claim that every combination is currently supported. gsuite provides the R interface; related libraries provide reusable model and numerical components.

Bayesian and non-Bayesian methods can share data handling, model structures, matrix operations and solves. They also require different inference machinery. Prior specification, posterior calculations and appropriate sampling or other Bayesian inference components must be implemented and checked where missing. The Bayesian route is an extension direction for this presentation, not a claim that a general Bayesian workflow is already exposed through the gsuite R API.

Reusable components make focused extensions possible. The amount of new work depends on the model, and an extension may require substantial algorithmic work. The value is cumulative: checked components remain available for later methods.

Developing gsuite with AI

Mathematics and design

  • Discuss the model and its assumptions
  • Derive the required computations
  • Compare algorithms and special cases
  • Decide what to implement or reuse

Implementation and review

  • Work directly with the R and C++ code
  • Compile and run focused checks
  • Inspect failures and revise the approach
  • Retain reviewed code and documentation

AI assistance connects statistical ideas with their implementation.

ChatGPT supported discussion of statistical models, mathematics and software design. Codex supported work directly in the repositories. The assistant can examine the code, make a focused change, build it, run checks and explain the result.

This has made it possible to work through several layers in the same conversation. The developer remains the editor: defining the purpose, questioning assumptions, reviewing decisions and deciding what evidence is sufficient.

A concrete computational example was obtaining selected inverse entries from retained sparse factors. The task connects a mathematical requirement in REML with an algorithm, a native implementation and a reusable solver capability.

Historical comparison: gsuite 0.29.0 and DMU 5.6; three frozen pedigree models. Results and scope

Both the small references and the efficient selected-inverse algorithm are native C++. The references include a dense inverse and a separate scalar Takahashi calculation. Independence comes from the different computational approaches, not from using different programming languages.

The saved DMU evidence covers single-trait, multitrait and longitudinal models. The numerical agreement is concrete evidence for those versions, models and settings. It does not qualify every current capability. The following slide shows historical runtime evidence. Individual desktop timings varied markedly in later reruns.

Checks must continue as the software changes. A recent current-version multitrait rerun reached estimates close to the historical endpoint but failed its line-search requirement. That remains a failure to investigate, not a successful current-version benchmark. Running code and supported models are not the same acceptance state.

Analysis with an assistant · Model development with an assistant

The order matters. This is not a proposal to start with a general chatbot and hope it invents the whole analysis. The assistant works with existing model interfaces, documentation, numerical components and validation evidence.

The repositories and documentation are now being brought into a shared workspace. The linked walkthroughs illustrate how this can support analysis and focused extensions. This connection is still developing and does not yet constitute a complete automatic research system.

A pedigree analysis as a conversation

How much genetic variation is present in body weight, and how accurately can breeding values be predicted?

Work through the analysis

  1. Check pedigree, observations and missing values
  2. Discuss fixed effects and genetic effects
  3. Fit the model and check convergence
  4. Inspect estimates and predictions
  5. Save the R script, figures and report

Keep the model explicit

fit <- gfit(
  formula = BW ~ sex + cohort + herd + (1 | id),

  pedigree = pedigree,

summary(fit)

Worked example: 10,000 pedigree animals

This code follows the single-trait pedigree tutorial. The data frames and fit_control are prepared in that tutorial; the slide is an excerpt, not a standalone analysis script. The saved example has 10,000 pedigree animals, with 8,588 animals observed.

The assistant can help inspect identifiers, missingness and covariates, explain the model and run the code. Researchers review which effects belong in the analysis and what the resulting estimates mean. The report should include variance estimates, fit status and diagnostic plots, not just a fitted object.

Simulation truth supports the teaching example. Real data require scientific interpretation and sensitivity checks; a plausible plot does not establish that the model assumptions are correct.

When the question needs something new

An analysis may reveal a model or interface that gsuite does not yet support.

Step Work with the assistant
Identify the gap State the missing capability and its statistical meaning
Reuse what exists Inspect the model, covariance and solver components
Implement the extension Add the required computation or interface
Establish support Compare references, examine failures and document the limits

Code that runs becomes a supported model only after its statistical meaning and numerical behaviour have been checked.

From a scientific question to a supported model

For example, repeated observations may raise the question of residual correlation. The first step is to check whether the desired combination is supported. If not, the covariance model must be defined and reusable components identified. Not every combination of longitudinal and residual structures is qualified.

The general model specification and reusable computational components make focused extensions possible. They do not make every model extension trivial. AI can help derive, implement and test it. Researchers retain responsibility for the scientific contract and acceptance criteria.

Where is AI taking research?

What is likely to change

  • Writing, coding and analysis will become faster
  • More groups will develop advanced methods and software
  • AI assistants will perform increasingly complex tasks
  • Research roles and expectations will change

Questions for the programme

  • Which expertise and resources will distinguish the programme?
  • How can AI be combined with the available data and infrastructure?
  • Which capabilities should be developed and shared?
  • How should training, review and responsibility change?

What needs to change now for the programme to remain scientifically distinctive as AI becomes part of research?

AI is already part of research, and its capabilities will continue to develop. Routine use of writing assistants or code generation will become common. The strategic question concerns how this changes research and what will remain distinctive.

Scientific questions, domain knowledge, trusted data, critical evaluation and responsibility will remain important. Shared platforms provide one possible advantage because they capture expertise in infrastructure that researchers and AI assistants can use and extend.

Discussion can focus on the capabilities required, changing research roles, and investments that support scientific strength.

The gsuite experience suggests connecting applied research and development through manageable scientific questions. Each project can leave reusable analyses, checked components and documented evidence for later work. Scientific quality, review effort and maintenance matter alongside time saved.
