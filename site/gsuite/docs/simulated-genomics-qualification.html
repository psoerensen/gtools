Connected genomic workflow: qualification record

Initial execution, 2026-09-21

Historical execution record. This section describes the initial example, including its original Bayesian working scale of 0.7. The current tutorial uses working scale one and adds ten new simulations, as described under Working scale and repeated simulations. The timings and Bayesian prediction results in this historical section are not the current tutorial results. Starting source was gsuite b9dffbb, using installed gsuite 0.43.0, gsim 0.16.0 and R 4.4.1 on Windows. The initial run used the existing installation. The native sparse-LD adapter correction below subsequently changed gmat and gbayes; cached stages from the initial run retain their original execution metadata.

Preparation required script-only corrections to BIM integer formatting and explicit SumHer baseline score preparation; regional calls exclude score-method jackknife block labels. Seeds and numerical acceptance thresholds were unchanged.

Native Bayesian scaling correction. The initial 50K-marker memory-backed BayesC/BayesR stage was stopped after several minutes without a completed stage result. Inspection found that gbayes/src/cross_products.cpp delegates each column update to SparseLdCsr::add_cross_product_column() in gmat/src/sparse_ld_csr.cpp. That routine calls validated_marker_roots() for the entire marker vector on every update. Sparse neighbour updates therefore also incur linear full-panel validation/allocation/square-root work. This is a code-path finding, not a completed runtime profile or a measured speedup. Following review against sblr’s st_csr_common.h and CsrOperator::apply_offdiag() in st_ld_operator.h, gmat now supplies PreparedSparseLdCrossProducts. It validates and caches scales once and reuses the sparse forward/reverse indices; gbayes uses it for memory-backed LD. Per-column work is proportional to retained neighbours, with no marker-wide allocation or validation inside the update. This corrects an implementation error rather than changing the Bayesian model. Samplers, priors, seeds and sweep counts are unchanged; sblr has not been modified.

The focused gmat.unit, gbayes.numerical and gbayes.multivariate checks passed, including prepared/checked arithmetic and dense/sparse fit agreement. The isolated R package was rebuilt with the corrected libraries and its Windows runtime verification passed. The unchanged 50K-marker rerun completed in 90.86 seconds for BayesC and 217.82 seconds for BayesR. Each method visits 120 million marker steps: 50,000 markers times 1,200 sweeps times two chains. Bayesian means were finite, PIPs were in range, and maximum recorded residual drift was below \(1.8\times10^{-12}\).

A focused comparison with installed sblr 0.2.0 used the same prepared summaries, sparse-LD files, BayesC prior, seeds, one worker and sweep counts, through stblr_cpg_omp_csr(). It took 87.43 seconds (84.01 user CPU seconds), retaining 1,000 samples per chain. Thus the corrected gsuite BayesC execution was close to this installed sblr execution; this is one sequential local timing, not a benchmark claim across implementations or machines. The gsuite timing includes its public R validation/results; the sblr timing uses its native R wrapper. The implementations also differ in stored cross-product precision. No BayesR speed comparison with sblr was performed, and the interrupted original run provides no completed before/after speedup ratio.

A short gsuite BayesC run with ten sampling sweeps and no burn-in took 1.89 seconds. Its R profile attributed 0.70 sampled seconds to LDlist validation and 0.54 to the native call. This is a check on preparation overhead, not a substitute for profiling the full sampler. BayesR still creates temporary mixture vectors per marker; that is a potential optimization, not an established remaining scaling failure or an implemented change.

The saved rerun records hashes of the installed DLLs, verified against the prepared native prefix: gmat MD5 eca3bd8db5f79cb25f251de6d045ec16, gbayes MD5 017fb6fd3c3c4cdcf332608ef523f712. Native starting commits were gmat 379e1a1 and gbayes 3793875, plus the uncommitted correction. The installed sblr DLL identity, session, timing and output are retained in bayesian-cost-check.rds; its correspondence to the inspected sblr source is not asserted.

Controlled gene-tail limitation. The gene-evidence run completed, but 5 of 3,000 gene/trait p-values were unavailable: A/gene0004; B/gene0002 and gene0004; C/gene0002 and gene0004. All reported Series did not reach requested absolute and relative accuracy within term budget, with 4,096 terms and error bounds around \(3.02\times10^{-14}\). No fallback was used. The positive-series route therefore did not meet its requested accuracy for these strong signals. The initial pathway stage stopped; unavailable genes were neither dropped nor assigned substitute p-values. Full evidence is saved in gene-evidence.rds.

Source inspection of gsolve/src/quadratic_tail.cpp explains the failure: the bound adds a floating-point allowance to the remaining mixture mass and requires both absolute and relative accuracy. At 4,096 terms the allowance is about \(3.02\times10^{-14}\) on this build. It dominates the requested relative accuracy for these extreme tails; merely adding terms cannot remove that floor. The routine correctly reports that it cannot certify its result. No numerical library or tolerance was changed to bypass this condition.

Explicit approximate pathway route. To exercise the rest of the workflow, all 3,000 gene/trait calculations were separately evaluated using the existing default saddlepoint approximation. All returned available p-values, with zero moment-matching fallbacks. The five corresponding p-values range from \(3.60\times10^{-27}\) to \(2.81\times10^{-12}\); these are approximate outputs, not replacements certified by the controlled-series calculation. Among the 2,995 results available from both routes, the median absolute difference in \(\log_{10}(p)\) is 0.000489 and the maximum is 0.0133. This comparison does not certify accuracy for the five unavailable controlled-series tails.

ORA, preranked GSEA, competitive regression, bounded MAGMA and scalar BayesC pathway analyses completed without dropping genes. All 36 reported frequentist p-values and three Bayesian PIPs were finite and in range; all nine preranked inferences were available. Nominal enriched-set MAGMA p-values were 0.008565, 0.000771 and 0.001825 for A/B/C. Trait-A pathway PIPs were 0.9995 (enriched), 0.0705 (background) and 0.0315 (mixed). Frequentist pathway p-values are unadjusted; this one constructed example is not a false-discovery or power evaluation. The independent-block assumption and the approximate gene tails remain explicit. No claim of full MAGMA software equivalence is made.

Statistical findings. Realized h2 is 0.2958/0.3957/0.3467. Baseline LDSC estimates are 0.1643/0.2846/0.1967; annotation-aware estimates are 0.2700/0.3985/0.2989. Out-of-range rg values remain visible (B/C baseline LDSC 1.0948, SE 0.3311, versus truth 0.7264). HESS covariance SEs were unavailable for 40/60 regional results because the plug-in matrices were not positive semidefinite. SUPERGNOVA returned 60/60 SEs; this LAVA covariance route supplies none. Colocalisation gives H4 effectively one for the shared signal and H3 effectively one for the distinct signals in this single draw.

Held-out correlations with genetic truth were 0.1388 for ridge, 0.3933 for BayesC and 0.4060 for BayesR; phenotype correlations were 0.0856, 0.2219 and 0.2330. The centered truth-weight score matched simulated genetic values to \(4.7\times10^{-15}\). These are single-draw results with fixed priors/penalty; they do not rank optimized methods. Active-marker trace R-hat was about 1.0004 for BayesC and 1.0005 for BayesR; this does not certify every marker posterior.

Saved stage files are data, ld, gwas, gcorr, annotation, gbayes, gscore, gmap, gsea and gbayes-summary (each .rds) in the fixed output directory. Diagnostics are in build/report/simulated-genomics*.log. --resume --only=gmap,gsea selects stages using existing prerequisite caches without producing a complete report. The final --resume run generated the complete tables and three figures from saved fits, checked unchanged LD checksums, and finished with SIMULATED_GENOMICS|completed. gene-evidence-saddlepoint.rds and gene-tail-comparison.csv keep the approximate route separate from the original controlled evidence. No full package check was run for this example.

Initial additional GWAS and Bayesian reporting

The original data, GWAS, Bayesian fits and timing evidence are retained. The gbayes-summary stage repeats the same two seeded chains for each Bayesian method, enabling native joint-draw genetic-variance summaries against the pooled LD reference and explicitly supplying phenotype variance one on the fitted standardized scale. It requires exact equality of marker estimates and parameter means with the original fits. Its elapsed time is reported separately and does not replace the original BayesC/BayesR timing comparison.

Reference heritability is calculated per draw as \(b^\mathsf{T}R_{\mathrm{ref}}b/V_y\). Native posterior summaries provide its mean, equal-tailed 95% interval, R-hat, bulk ESS and Monte Carlo standard error. It includes posterior effect dependence. Residual variance, effect-variance parameters and mixture weights remain fixed; the posterior is conditional on these truth-informed settings and the approximate LD reference. This is not residual-variance learning or an independent test of heritability recovery. Full marker draws are not stored.

Earlier Bayesian heritability discrepancy, at working scale 0.7. BayesC gives 0.5366 (equal-tailed 95% interval 0.4960–0.5788); BayesR gives 0.6145 (0.5606–0.6724), against population truth 0.2958. Heritability trace means agree with the reported native means within \(10^{-10}\). R-hat is 0.9993/0.9998 and bulk ESS is 2,038/1,901, but these diagnostics do not establish accuracy or interval coverage. Posterior expected active-marker counts are 1,230.5/1,181.7 against 984 directly causal markers for trait A. These are not counts of markers above a PIP threshold.

A scale check gives population genetic variance divided by the observed training phenotype variance of 0.2899, so this denominator distinction cannot explain the discrepancy. Marginal effect-posterior variances sum to 0.4337/0.4273; squared posterior means sum to 0.1022/0.1901. Their sums are close to, but are not substitutes for, the joint reference-LD quadratic summaries above. The high values are not just the variance of posterior mean predictions. A subsequent focused review identified the working summary-likelihood scale as the issue in this example; see below. The historical results are retained as evidence, not used in the current replicate summaries.

Four additional figures show GWAS Manhattan plots, Bayesian PIPs and effect recovery, heritability chains/distributions, and held-out genetic-value prediction. Causal indicators use nonzero simulated effects for the plotted trait (984 per trait; 985 distinct markers across traits). The GWAS threshold is \(0.05/50{,}000\) per trait. Associated zero-effect markers may tag causal markers through LD. True marker effects and genetic values are converted to the fitted standardized scale; predictions are centered but not rescaled to match truth.

The compact association-summary.csv, bayesian-posterior.csv and bayesian-fit-summary.txt accompany the figures. The original three figures and all earlier numerical limitations remain in the report. That reporting pass added no methods or simulation replicates.

Working scale and repeated simulations

The reference-LD Bayesian example now fixes the working summary-noise scale at one. This is distinct from the simulated environmental variance of 0.7: blockwise population LD omits sample cross-block terms in marginal summaries. In the original example, the standardized residual score noise computed using known population effects and LD is 0.9931, while environmental variance on the training phenotype scale is 0.6901. At working scale 0.7, a matched installed-sblr BayesC calculation with its adaptive adjustment disabled also gives inflated genetic variance (0.5360). With its existing adjE=0.9 adjustment it gives 0.3158. The fixed-scale-one gbayes calculation gives 0.3108 for BayesC and 0.3068 for BayesR, against population truth 0.2958. These comparisons identify a working-likelihood issue; they are not full software equivalence tests.

No native sampler default changed, and sblr was not edited. Its adaptive adjustment is not exposed by this example. Working scale one is a checked approximation for this reference-LD design, not a replacement for environmental variance in individual-level regression. Priors remain informed by the simulated architecture. The original Bayesian/scoring stage objects are preserved locally in pre-working-noise-update.rds, alongside the earlier diagnostic evidence.

The revised driver collects posterior genetic variance during the original fit, so it no longer repeats the sampler solely to obtain summaries. Dependent scores and figures are regenerated together. Comparisons include marginal GWAS effects against \(R_{\mathrm{pop}}B\), direct Bayesian effects on matching standardized units, regional covariance, annotation heritability, component-set causal coverage, colocalisation probabilities, and held-out prediction calibration. Calibration regresses genetic truth divided by the training phenotype SD on the predicted score; the target slope is one.

Ten additional simulations use genotype/effect seeds 20261100 through 20262000 in steps of 100; gsim uses each seed plus one. The original example (20260921) is not included in this aggregate. Settings are fixed before these fits: same population size, LD generator, architecture, disjoint samples, priors, regions, chain lengths and analysis methods. Each repetition generates new genotypes, effects and phenotypes. Sampler seeds remain 11 and 29 and preranked GSEA uses seed 31. Failed seeds are recorded, never replaced by new seeds.

The replicate runner uses two R processes in this execution, with one native thread per call. Each reuses one large working directory under build/examples/simulated-genomics/replicates/; compact per-replicate objects retain estimates, truths, diagnostics, timing, warnings, script hashes and installed-library identities. Concurrent timings are execution records, not controlled performance comparisons. The report script reads all ten planned attempts and retains failed-run and missing-interval denominators. Trait and region rows are not treated as independent replicates. Approximate normal intervals and conditional posterior intervals stay labelled separately. Ten repetitions provide a small descriptive check, not precise coverage, false-positive calibration or method rankings.

Completed repetition checks, 2026-09-21

All ten planned seeds completed all nine stages, without replacement or failed attempts. The three analysis-script hashes agree across runs; each dataset has a distinct LD checksum set. Installed native-library identities agree across all 90 stage records. The 150 selected marker/trait OLS comparisons and ten truth-weight scoring checks passed the predeclared \(10^{-9}\) tolerance; the largest absolute error was \(8.72\times10^{-15}\).

Mean trait-A population heritability was 0.30048. BayesC and BayesR posterior means averaged 0.31248 and 0.30737, with RMSE 0.01257 and 0.00989; their conditional 95% intervals contained truth in all ten datasets. Mean held-out genetic-value correlations were 0.50255 and 0.51895, and calibration slopes were 1.45846 and 1.09442. Fixed-prior results do not establish general heritability-learning accuracy or calibrated posterior coverage.

All 40 component sets covered the true causal marker in the two deliberately simple regions. HESS supplied 189/600 regional covariance standard errors; SUPERGNOVA supplied 600/600 and the exercised LAVA route supplies none. Six annotation-category correlations were undefined. The controlled gene-tail route left 60/30,000 p-values unavailable; the separate approximate route returned all values, recording 11 moment-matching fallbacks. These limits remain visible in the aggregate tables and figures.

The public aggregate tables include every planned run, numerical checks, source identities, method-specific uncertainty and execution timings. Both workers ran concurrently; timings are not benchmarks. No native code, package installation or full package check was changed or rerun for this reporting and simulation extension.

Scope agreed before execution

One seeded example connects glma, gbayes, gmap, gcorr, gscore and gsea through the current gsuite R interfaces. It does not add methods. The focused native adapter correction was added after the first run exposed its repeated full-panel work. Pedigree/greml/gsolve qualification, literature attribution and further enrichment development remain separate tasks.

The runnable driver is simulated_genomics_workflow.R. Its fixed output directory is build/examples/simulated-genomics/. Nine named stage files retain inputs/results and execution metadata; native LD and BED files are reused. Default execution regenerates those outputs. --resume is for an interrupted run of the same design: it reuses completed stages and records the script hash separately for every executed stage. It is not a general cache invalidation mechanism; regenerate after changing a completed stage or its assumptions.

Design and targets

  • 10,000 unrelated artificial individuals and 50,000 biallelic markers.
  • 500 independent regions, each with 100 markers. Regions are encoded as artificial chromosomes to retain all within-region LD without storing between-region sampling correlations. This is a population block assumption.
  • Binomial dosage frequency 0.3; copy-or-redraw dependence gives the known population correlation \(R_{jk}=\rho^{|j-k|}\). Regional \(\rho\) ranges from 0.2 to 0.8. This is an artificial generator, not demographic simulation.
  • gsim generates three continuous phenotypes with target heritabilities 0.30, 0.40 and 0.35. Effects are enriched in the first 80 regions. Region 1 has one shared causal variant; region 2 has distinct variants for traits A/B.
  • Disjoint GWAS samples: 3,000 people for each trait. The remaining 1,000 are held out from GWAS, LD preparation and parameter fitting for score assessment.
  • The pooled 9,000 GWAS individuals provide LD. This reference is shared with the studies, not an external independent panel. LD-based summary likelihoods remain approximations to each separate cohort’s sample cross-products.
  • Population truth uses realized gsim raw-dosage effects and known population LD: \(G_r=B_r^\mathsf{T}(0.42R_r)B_r\), \(G=\sum_rG_r\), and \(V_t=G_{tt}+(\Sigma_e)_{tt}\). Compare h2 with \(G_{tt}/V_t\), rg with \(G_{st}/\sqrt{G_{ss}G_{tt}}\), and regional covariance with \((G_r)_{st}/\sqrt{V_sV_t}\). The same observed LD is not used to define truth.

All native operation-local thread counts are one; BayesC/BayesR use 200 burn-in and 1,000 retained sweeps per chain, seeds 11 and 29, with fixed variances and mixture settings. These deliberately short chains demonstrate execution, not posterior calibration. GSEA uses 999 permutations and seed 31. Genotype/effect seed is 20260921; gsim seed is 20260922. No seed search or tuning to outcomes.

Single-run estimation errors are reported, not converted into pass/fail thresholds. A method can execute correctly and give a poor estimate on this draw. Unavailable uncertainty and boundary results must remain visible.

The enriched annotation occupies the low-LD end of the generator. Baseline LD-score models do not describe that nonuniform architecture. During design review, before inspecting fit results, an additional LDSC fit was specified using the two disjoint, exhaustive enriched/background marker groups. It uses the same data, not a new seed or tuned partition; baseline results remain in the report. A single draw still cannot establish bias or comparative accuracy.

Limits

This is an initial integration and scale example, not qualification of every engine, every interface option, or statistical calibration. The ten repetitions describe errors and observed coverage under one non-null design; they do not establish general bias, power, coverage or false-discovery control. It excludes binary traits, population structure, multi-ancestry analysis, LD mismatch experiments, MR/SEM/GGM, Bayesian annotation/variance learning, multitrait Bayesian fitting, LOCO association, and full package/platform checks. Apart from the focused installed-sblr BayesC timing, no external analysis software is run for comparison. The R OLS and simulated truth-score checks are small independent checks of the exercised execution.

The public walkthrough reports the observed results with figures. Website rendering never executes the simulation.

gsuite is in private development. gsim and gact are public.
