Gene-set and pathway analysis

gsea() connects prepared gene-level evidence to the native gsea library. The same named sets and explicit gene background support several questions:

Method Question Main result
ora Are selected genes over-represented in a set? Hypergeometric upper-tail p-value and fold enrichment
preranked Does a set concentrate towards either end of a gene ranking? ES, NES, leading edge and gene-label permutation p-value
competitive Is a gene score associated with a pathway after covariate adjustment? GLS coefficient, standard error and upper-tail enrichment p-value
magma What does the bounded MAGMA summary workflow estimate from prepared gene p-values? Probit-score preprocessing and competitive set regression
bayesc, bayesr Which pathway effects are supported under a joint shrinkage model? Posterior means, variances, PIPs and chain summaries

The last two choices also accept several traits fitted jointly. Bayesian PIPs are probabilities under the specified model and priors; they are not p-values. This interface does not perform SNP-to-gene preparation or gene-ID conversion. The capability overview describes the separate native gene-evidence operations.

A complete artificial example

Download the runnable R example. It contains all six methods and uses 120 artificial genes and three overlapping pathways. This is an interface demonstration, not a comparative calibration study.

library(gsuite)
set.seed(2401)
genes <- paste0("gene", seq_len(120))
sets <- list(pathway_A=genes[1:25], pathway_B=genes[21:45],
             pathway_C=genes[71:95])
X <- vapply(sets, function(s) as.numeric(genes %in% s), numeric(120))
noise <- matrix(rnorm(240),120,2)
stat <- list(
  trait_A=data.frame(gene=genes, score=2*X[,1]+noise[,1]),
  trait_B=data.frame(gene=genes, score=1.5*X[,1]+X[,2]+
                      .3*noise[,1]+sqrt(.91)*noise[,2])
)

stat is a data frame for one trait or a named list for several traits. Every frame must contain the same unique character gene IDs in the same order. All genes in the declared background remain in the analysis, including genes outside every set. Unknown or duplicate set members are errors. Set overlap is allowed. For competitive and Bayesian regression, a labelled numeric feature matrix can replace binary set membership.

Selected genes or a ranked list

ora <- gsea(transform(stat$trait_A, selected=score>2), sets, "ora",
            control=list(adjustment="BH"))
ranked <- gsea(stat$trait_A, sets, "preranked",
               control=list(replicates=999, seed=2401, adjustment="BH"))
ranked$pathways
ranked$details$trait$leading_edge
plot(ranked)

ORA requires a logical selected column over the complete background; the selection rule is the caller’s decision. Preranked GSEA uses a finite score, a stable decreasing ranking and whole-background gene-label permutations. It does not correct for LD or perform phenotype permutations. Excluded sets and unavailable directional inference remain in the result with diagnostics. adjustment="BH" or "BY" adjusts the tested p-values, not pooled NES values as in Broad GSEA’s FDR calculation. Defaults are no adjustment, exponent 1, set sizes 1–500, seed 1, 999 permutations and one thread.

Competitive regression

fit <- gsea(stat, sets, "competitive",
             sampling=list(gene_covariance="independent"),
             control=list(adjustment="BH"))
fit$pathways
summary(fit)
plot(fit, trait="trait_A")

Classical methods analyse traits separately, with adjustment within each trait. Competitive regression fits pathways jointly by default; joint=FALSE fits each pathway separately with the same covariates and background. Covariates are a numeric matrix with gene row names or a data frame with gene and numeric columns; an intercept is added internally. Encode factors explicitly.

Regression always requires sampling$gene_covariance. Supply "independent" only when that working assumption is intended, or provide a labelled covariance matrix / named list of labelled blocks that partition the complete background. Block labels are used explicitly to map to gene order. Blocks must be symmetric positive definite; singular designs fail rather than silently drop columns. Student-t inference is a working approximation for non-Gaussian gene scores.

The bounded MAGMA route

gene_p <- transform(stat$trait_A,
  p_value=pnorm(score,lower.tail=FALSE), marker_count=10,
  effective_parameters=8, sample_size=10000, mean_minor_allele_count=2000)
magma <- gsea(gene_p, sets, "magma",
               sampling=list(gene_covariance="independent"),
               control=list(adjustment="BH"))
magma$pathways
magma$preparation$trait

These artificial p-values illustrate the API. Real analyses require calibrated gene-level evidence. Native preprocessing applies the documented probit transformation, clipping and gene-property corrections; the default adjusts the outcome for internal covariates before fitting each pathway separately. Constant internal covariates are reported. correct_size, correct_density, correct_sample_size and correct_mac default to TRUE; their positive input columns are required whenever enabled. truncate and residualize_internal also default to TRUE; bounds are lower_z_bound=-3, upper_z_sd=6 and covariate_sd_bound=5. External custom covariates use competitive instead.

For this method, gene dependence means quadratic-score correlation, with nonnegative entries and unit diagonal. The native workflow applies the recorded working-correlation power (default 1.1). This is not exact covariance of the transformed probit scores. It is a defined subset of MAGMA’s workflow, not full MAGMA equivalence. SNP-to-gene tests, allele alignment and reference preparation are separate native operations and are not hidden inside this call.

Joint Bayesian pathways

Omega <- matrix(c(1,.3,.3,1),2,dimnames=list(names(stat),names(stat)))
G <- diag(2);dimnames(G)<-dimnames(Omega)
fit <- gsea(stat, sets, "bayesr",
  sampling=list(gene_covariance="independent",trait_covariance=Omega),
  prior=list(effect_covariance=G),
  control=list(burnin=100,sampling_sweeps=1000,seeds=c(11,29)))
fit$pathways                 # trait-specific effects and PIPs
fit$joint                    # probability of activity in any trait
fit$parameters$joint         # prepared-scale parameter summaries
fit$diagnostics$joint        # conditioning, threads and chain PIP spread
plot(fit, trait="trait_A")
saveRDS(fit, "pathway-fit.rds")

Bayesian models fit all pathways jointly and adjust both response and features for the shared nuisance design. They support overlapping pathways and proper priors when the number of features exceeds the number of genes; highly dependent sets can still make individual PIPs difficult to interpret.

For one trait, supply prior=list(residual_variance=1,effect_variance=1) with values chosen for the prepared score scale. BayesC defaults to inclusion probability 0.5. Scalar BayesR defaults to weights (0.7,0.1,0.1,0.1) and variance multipliers (0,0.01,0.1,1). Optional scalar learning flags are estimate_effect_variance, estimate_residual_variance and estimate_weights. The corresponding priors are effect_variance_prior=list(df=...,scale=...), residual_variance_prior=list(df=...,scale=...) and positive weight_prior counts.

Joint fits require a labelled effect_covariance prior and a separate, fixed residual trait_covariance on original response units. The latter describes remaining gene-score dependence between traits, not pathway-effect covariance. All traits share genes, features, covariates and gene dependence. The native likelihood uses a separable gene-by-trait covariance model. It does not infer sample overlap or substitute a genetic-correlation matrix for residual covariance.

By default, joint models enumerate activity patterns across 2–12 traits. For larger trait sets, explicitly provide restricted binary patterns with labelled trait columns, distinct rows and the null row first; the native maximum is 64 traits. A restricted pattern set changes the model. pattern_weights default to equal probabilities. Joint BayesC has one positive component scale, 1; BayesR uses (0.01,0.1,1) with equal conditional component weights. The null is represented by the null pattern, not a zero component scale.

Joint learning is optional: estimate_covariance requires covariance_prior=list(df=...,scale=...) (an inverse-Wishart scale matrix); estimate_pattern_weights requires positive pattern_prior counts; and BayesR’s estimate_component_weights requires positive component_prior counts. The residual trait covariance stays fixed.

Results, units and bounds

  • pathways retains method-specific statistics; summary() also returns parameters, diagnostics and provenance. plot() requires a trait choice when several are present. No automatic significance or PIP cutoff is applied.
  • Bayesian pathway means and variances use original response/feature units. Priors, native chain traces and parameter summaries use prepared coordinates. preparation records response and feature scales and nuisance rank.
  • scale_response and scale_features default to TRUE. Chain defaults are 100 burn-in sweeps, 1,000 sampling sweeps, thinning 1, seeds (1,2) and one thread. retain_diagnostics=TRUE retains parameter traces. Joint retain_pattern_probabilities=TRUE additionally stores pathway-by-pattern probabilities. Chain PIP spread is not an ESS or R-hat convergence check.
  • Regression defaults bound features (255 classical / 4,096 Bayesian), user covariates (128), each covariance block (2,048 genes) and preparation payload (512 MiB). Bayesian preparation checks its native payload estimate; the R classical check bounds the feature matrix, not total process memory. Joint sampler storage has a separate 256 MiB memory_limit_bytes estimate.
  • Competitive fits permit at most 256 coefficients by default and require reciprocal condition at least 1e-10; both controls are configurable. The bounded MAGMA route retains those native limits. No dense whole-genome covariance is formed when explicitly partitioned blocks are supplied.

The focused R checks compare ORA to the hypergeometric calculation, GLS to a dense R reference, and unadjusted MAGMA preprocessing to the corresponding competitive fit. Bayesian checks cover chains, units, labels, joint probabilities, learning and serialization. These integration checks complement the small native oracles; they do not establish broad genomic calibration or full package qualification.
