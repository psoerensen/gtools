gbayes methods and algorithms

Current focused developer checkpoint: 8 November 2026. gbayes 0.1.16 and gscore 0.1.2 build and pass the focused references for the annotation, residual-learning, population, scalar IBSS, weighted elastic-net, prepared-design, streamed/batched mixture and Gaussian co-data extensions below. The gmap 0.2.11 consumer also builds and passes its saved-fit checks. This is isolated developer validation, not a published release, complete R CMD check or broad statistical calibration. Full-model co-data CV remains planned; gscore selects the ordinary ridge initializer only.

This page records the four common genomic interfaces, their existing native engines, and the remaining adapter boundaries. It is a capability matrix, not a count of benchmark configurations or a new statistical qualification. The working checkout includes the recent adapters; this does not imply that every route is in a published package release.

method identifies the fitted family. algorithm identifies computation. Annotations, MAF bins, supplied prior means, penalty grids and fold selection are configurations or workflow choices. They do not each create a new method. The common interfaces also accept the checked multi_effect and normal_mixture routes below. Several spellings share a statistical family; native coverage is wider than the exposed R adapters.

Interface Fitted input and effect axes
bayes One quantitative phenotype and selected individual genotypes
sbayes One trait’s marginal summaries and prepared LD
mbayes Joint quantitative phenotypes on one selected genotype panel
msbayes Joint trait/study/population summaries with explicit sampling dependence and LD/reference mapping

All four functions default to method="bayesR". algorithm=NULL selects the method default: MCMC for C/R/RC, factors, point_normal and continuous_shrinkage; VB for CM, Laplace–Gaussian and the two named summary variational engines; PCG for marker_gaussian; IBSS for the SuSiE engines. In pending source, prior$coData selects the direct Gaussian default for the bounded scalar X route. BayesC keeps MCMC as its default even though explicit scalar algorithm="vbayes" is now available.

The current factor adapters require 3–256 selected individuals, 2–128 traits and at most 16 factors, plus their memory admission. Current IBSS adapters use a bounded one-chromosome domain (default maximum 2,048 markers); they are not unbounded genome-wide fits. These limits are separate from a method existing.

Individual effect units follow saved training coding and outcome scale. Ordinary summary C/R/RC/Gaussian/VB effects use standardized phenotype/genotype units; MultiSuSiE preserves its checked OLS study coordinates. Supplied means already match fitted counted alleles/units. Algorithm names alone do not define units, sampling assumptions, exactness, PIP meaning, continuation or mapping eligibility. Use the saved bayesfit, fit_contract() and route-specific availability fields. Mean-field PIPs are approximate activity probabilities; continuous priors have no spike PIPs; single-effect assignments are different from joint activity.

BayesC baseline pi learning stays separate from inclusion-slope learning. BayesR component annotations replace global weight learning; updatePi controls annotation learning there. Designs/allele frequencies have exact fitted-marker order. The MAF exponent acts on the fitted effect-variance scale with centered log(2p(1-p)), not an automatically translated raw-dosage model. Joint C/R, variational/fixed-informed annotations, capture, continuation and saved gmap conversion remain gated. The existing BayesRC contract is unchanged.

No new sampler is needed merely to expose those existing engines. Their missing work is not uniformly trivial: prepared-design contracts, effect scales, sampling dependence, result adapters and focused references must agree first. Missing native statistical capabilities, if requested, require a separate scope.

Source and evidence

Admission was checked against the current package dispatchers individual.R and summary.R and the CM, factor, RC, informed BayesC, Gaussian, elastic-net, Laplace–Gaussian, specialized-summary and IBSS adapters. Native presence was checked against the owning gbayes public headers and current source/docs. No sibling source is copied or made a runtime dependency by this page.

The slab-mean baseline has 101 focused assertions and related interface/continuation/Gaussian/VB/gmap regression evidence. Marker probability/variance adapters extend its independent mixture and coordinate reference tests. Other existing routes retain their recorded qualification. This documentation update does not rerun every fitter or establish genome-scale calibration/performance. The old prediction benchmark is a legacy regression panel, never the capability boundary.

See the interface contract, workflow and qualification limits for detailed inputs and unresolved limits. Saved-fit gmap conversion is method-specific; implementing a fitter does not automatically qualify posterior-set conversion.

The bounded scalar co-data contract is described in the design. Its gaussian algorithm does not turn other marker_gaussian routes into direct solvers.

Multiple annotation sets use the same method/algorithm and the same scalar effect/prediction contract; see the design contract. Set weights are prior-variance multipliers, not posterior model probabilities.

Saved feature-group tuning uses zero hyperLambda and explicit saved partitions with the same family/algorithm, units and prediction contract. See the design contract. These splits do not replace patient train/test separation.

Scalar co-data residual learning uses the same family/algorithm and one-time native joint_noise_ml, not a new joint-trait method or iterative noise sampler. See the design contract.

Supplied-fold co-data initializer CV is a gscore workflow, not a new bayes method or algorithm: gscore::co_data_cv selects/verifies public gbayes fold statistics then calls bayes marker_gaussian/gaussian at the frozen pair. Both group/set routes and fixed/feature-split-tuned penalties compose with it. Focused references pass in development gscore 0.1.2 / gbayes 0.1.16. See the design contract. These tuning losses are not final annotated-model/outer performance estimates.
