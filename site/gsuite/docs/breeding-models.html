Weighted, spatial and non-additive mixed models

Observation precision, spatial trials, selected prediction uncertainty, additional-effect REML and dominance/GCA/SCA models.

All these models use the same gsuite run model.yml command. Inputs, natural covariances, execution settings and outputs stay in the model file. See the YAML specification for complete syntax.

These are small numerical references. They do not qualify industrial REML throughput, large spatial blocks or large dominance/cross-product relationships.

Observation precision and known measurement error

The residual covariance of one response unit is \(D^{-1/2}R(\theta)D^{-1/2}+sS\), where \(D\) contains positive precision weights, \(S\) is a supplied positive-semidefinite measurement-error covariance and \(s\) is an optional nonnegative variance multiplier. It is not a standard deviation. Missing responses select the corresponding covariance submatrix before inversion.

model:
  residual:
    type: independent
    covariance: residual
    precision_weights: {trait1: weight1, trait2: weight2}
    measurement_error: {covariance: sampling_error, scale: error_scale}

The names on the right refer to mapped input columns or named covariances. A single weight column can apply to every trait. Weights are precision weights, not frequency counts or likelihood powers; zero weights are rejected. Known error is fixed and is excluded from variance estimation. Its multiplier must agree within a residual unit. Supply covariance matrices, not inverses. See the weighted observation example (models/multitrait-observation-precision.yml).

These modifiers currently apply to independent/grouped/supplied residual blocks. Packed REML with these modifiers is rejected; use compiled REML.

Spatial field trials

covariances:
  trial_A:
    type: spatial_ar1
    variance: 1.2
    nugget: 0.3
    row_correlation: 0.45
    column_correlation: 0.30
model:
  residual:
    type: spatial_ar1
    group: trial
    row: plot_row
    column: plot_column
    block: field
    covariances: {A: trial_A}

For observed plots \(i,j\) in a field, covariance is \(v\rho_r^{|r_i-r_j|}\rho_c^{|c_i-c_j|}+e\,1_{i=j}\). variance and nugget are positive variances; correlations lie strictly between minus one and one. Trials have separate named parameter blocks. Optional fields are independent replicates sharing a trial’s parameters. Actual integer gaps are retained, missing plots are marginalized and duplicate cells are rejected.

The initial implementation is univariate and stores dense matrices within each observed field: storage grows quadratically with its observed plot count. It does not allocate the entire rectangular grid. See the spatial trial example (models/spatial-field-trial.yml).

Selected prediction uncertainty

Define a named prediction once, then reference its level or prediction-grid record in output.uncertainty.contrasts. The same channel, incidence and basis definitions determine the prediction and its uncertainty. Exact output includes PEV and optionally cross-contrast PEC. Direct sessions reuse their accepted factor; packed sessions retain pedigree transforms and the PCG preconditioner. Coefficient right-hand sides stream one at a time.

maximum_solves explicitly bounds inverse actions. Stochastic diagonal output also requires probes, deflation_rank, seed and maximum_mcse in PEV units. The existing independent-sketch estimator operates in target space. Outputs retain raw estimates, MCSE and qualification flags; negative stochastic estimates are not clipped. Sampling qualification is separate from point-fit acceptance. The existing genetic reliability estimators and their limits are unchanged.

Uncertainty is conditional on covariance parameters and excludes their estimation error. The initial contrast YAML route uses a solve task and excludes inherited group effects. Fit covariances first, then refit them for conditional uncertainty. See the contrast example (models/prediction-contrasts.yml).

Additional-effect REML

analysis.estimate can select genetic, residual and additional independent-effect covariances on packed EM-REML. Omitted blocks stay fixed. Genetic regression channels may have a different width from the residual trait vector. Small precision templates refresh with each covariance state while level assignments, the exact pedigree factor and genotype provider are retained.

The same inverse actions supply all posterior moments. Score/MCSE gates, the independent final probe check and total solve accounting are unchanged. Optional likelihood changes include the determinants of estimated additional priors. Whole unstructured blocks are free or fixed; FA, serial parameters, finer coordinate constraints and weighted/known-error REML remain on the compiled route. See the additional-effect example (models/packed-additional-covariance-reml.yml) and packed REML details.

Dominance and hybrid combining ability

relationships:
  D: {type: dominance, genotypes: genotypes, independent_ridge: 0.05}

The native genotype kernel counts BIM allele 1. With allele frequency \(p\), dominance scores for dosages 0, 1 and 2 are \(-2p^2\), \(2p(1-p)\) and \(-2(1-p)^2\). The Gram matrix is divided by \(\sum[2p(1-p)]^2\) before the explicit ridge is added. Frequencies are estimated from nonmissing FAM samples; missing calls contribute zero coded value and monomorphic markers are omitted. This population-orthogonal coding follows Vitezica, Varona and Legarra (2013) under Hardy-Weinberg assumptions. It does not guarantee sample orthogonality. Additive predictions remain breeding values; additive plus dominance predictions represent a total genotypic contribution. Dominance is a separate effect on the panel individuals; it does not create a single-step dominance pedigree model. See the dominance example (models/multitrait-dominance.yml).

relationships:
  A1: {type: covariance, input: pool1}
  A2: {type: covariance, input: pool2}
  S: {type: cross_product, parent1: A1, parent2: A2, crosses: crosses}

For ordered crosses \((a,b)\) and \((c,d)\), \(S_{(a,b),(c,d)}=A1_{a,c}A2_{b,d}\). The crosses table supplies unique IDs and ordered parent pairs. Parent relationships currently use supplied dense natural covariance matrices. Separate parent GCA effects and a cross SCA effect use the existing random-effect incidence mappings. The model is the sum of those contributions; no unrequested one-half coefficient is inserted. See the hybrid GCA/SCA example (models/hybrid-gca-sca.yml).

Both relationship preparations currently produce a dense covariance and use the compiled relationship factor. They are not matrix-free industrial dominance or cross-product operators. Dominance decoding uses bounded marker tiles; kernel storage is quadratic in selected individuals/crosses. Optional per-relationship maximum_workspace_bytes bounds kernel construction, not total process RSS or the consuming factor. The default introduces no fixed memory ceiling. Existing runner timings, memory reporting and result collection apply.
