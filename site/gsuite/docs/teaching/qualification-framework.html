Qualification framework: establishing correctness and scientific value

Companion to the advanced mixed-model notes — first draft

Published

November 1, 2026

Advanced notes: contents

1 Three different claims need three kinds of evidence

A method can be algebraically correct, statistically inappropriate for a data collection process, and computationally impractical at the intended scale. Conversely, a fast implementation can agree with another program while both share an error. Qualification must separate these possibilities.

Numerical correctness concerns whether the specified equations and outputs are computed to the declared accuracy. Inferential validity concerns prediction, estimation and uncertainty under stated model and sampling assumptions. Practical value concerns predictive performance, interpretation or resource savings for an intended application.

This framework describes how to assess those claims. It is not a statement that all existing methods have passed every assessment. Completed evidence has its own dated and scoped record, described at the end. The general principles connect numerical analysis with genomic benchmarking (Daetwyler et al., 2013; Higham, 2002).

2 Define the object being qualified

Specify the model family, observation pattern, covariance parameterization, relationship construction, prediction target and inferential operation. Coefficient solving, variance estimation and PEV calculation are different operations; success in one does not establish the others.

Also identify the representation, numerical backend, approximation policy, input contract and reported result. A test of dense complete-data GBLUP does not automatically qualify packed single-step estimation with missing traits. An animal-model oracle can support an exact marker-model reduction only when the reduction and reconstructed target are checked.

Freeze the expected invariants and acceptance rules before examining results. Use an existing declared residual or uncertainty gate when evaluating a replacement algorithm; do not relax it retrospectively to obtain a pass.

3 Layer 1: independent algebraic references

On small deterministic problems, construct the model from its scientific definition with explicit matrices. Compare the conditional mixed equations and marginal covariance formulation, not two wrappers around the same solver. Independent derivations expose coding and normalization mistakes that repeated execution of the same implementation cannot reveal.

Quantity Independent reference or identity
Fixed effects and BLUP Dense marginal GLS/BLUP versus complete mixed equations
Genomic animal values Gaussian marker model versus its induced animal covariance
Pedigree marginal precision Dense submatrix inverse versus a Schur-complement action
REML objective Marginal determinants/quadratic versus complete-equation identity
Score Analytic derivative versus finite differences of the same objective
Curvature Analytic information versus the appropriate reference definition
PEV and contrasts Complete-system inverse or target solves, including fixed effects
Missing traits Direct observed covariance versus the selected complete model

These checks should include heterogeneous scales, nontrivial cross-covariances and unobserved prediction targets. An identity covariance with one intercept is insufficient to expose many ordering and incidence errors.

Finite-difference derivative checks need several reasonable step sizes to separate truncation error from roundoff. The objective and derivative must use the same parameter scale, active set and normalization. Average information is not generally the observed Hessian, so testing them for equality would itself be incorrect (Gilmour et al., 1995; Higham, 2002).

4 Layer 2: invariance, reductions and invalid requests

Equivalent representations should agree after mapping back to the same scientific identities. Useful invariants include permutation of input records, permutation of animal or trait order, consistent allele reversal and a full-rank basis transformation with the covariance transformed appropriately.

Test reductions such as one trait from a multitrait model, zero additional components where the boundary is supported, or genomic and marker formulations at matching scale. A rank-changing boundary needs its own derivation and likelihood treatment; it is not an arbitrary small positive variance.

Invalid input and infeasible requests should produce an explicit outcome: duplicate identities, unmatched alleles, indefinite supplied covariances, non-estimable targets, exhausted iteration limits and unavailable uncertainty operations. An output file alone is not evidence of an accepted result.

Failure controls should show that under-solving and nonfinite operations are rejected. Successful cases establish that a route can pass; failure controls establish that the acceptance mechanism is capable of saying no.

5 Layer 3: repeated simulation for inference

Parameter recovery and uncertainty coverage require repeated datasets. One simulation that estimates a variance near its generating value does not establish unbiasedness, calibration or nominal coverage.

For an estimator \(\hat\theta_b\) over \(B\) replicates, report bias and RMSE against a declared target. For interval coverage, if \(\hat c\) is the fraction of intervals containing that target, a binomial Monte Carlo standard error is approximately \(\sqrt{\hat c(1-\hat c)/B}\) for independent replicates. The number of replicates must support the precision of the claimed conclusion.

For prediction, distinguish repeated draws of effects and records at fixed pedigree/genotypes from simulations that regenerate the population. They assess different conditional and population-level questions. Include PEV or interval calibration, prediction error, bias and dispersion, not only correlation with truth. When covariances are estimated, evaluate both plug-in and any broader uncertainty target explicitly (Kackar and Harville, 1984).

Include difficult but relevant settings: weakly identified components, boundary variances, high trait correlations, uneven recording and selection. The generating target must be explicit under selection or time-varying parameters. A founder parameter and a selected-cohort variance are not necessarily the same estimand.

6 Bayesian posterior computation

On a small Gaussian model, check posterior means and covariance against an analytic distribution. For finite mixture examples, enumeration or another independent calculation can test allocation probabilities and normalization. With estimated hyperparameters, compare the intended joint posterior rather than only conditional coefficient solutions (Habier et al., 2011; Sorensen and Gianola, 2002).

For MCMC, assess multiple independently initialized chains, mixing, effective sample size and Monte Carlo error for the reported scientific quantities. Posterior standard deviation measures uncertainty in the quantity; Monte Carlo standard error measures uncertainty from finite sampling. Successful numerical updates and visually stable traces alone do not prove adequate exploration. Simulation-based recovery and interval calibration address further inferential questions under the specified prior and data-generating design.

For variational methods, optimization convergence does not establish agreement with the exact posterior or calibrated uncertainty. Check relevant means, variances and predictions against tractable references and clearly identify which approximation is being qualified.

7 Layer 4: approximations and stochastic precision

An approximate preconditioner should be assessed with the same original equations and acceptance rule as the reference solve. An approximate target kernel, such as a truncated relationship construction, needs an additional assessment of model sensitivity. Do not combine these into one generic “approximation error” number.

For randomized derivatives or uncertainty, separate Monte Carlo variability from deterministic inner-solve error. Compare with exact references where tractable, use independent random replications to assess reported stochastic precision, and retain solve accounting. A single fixed seed provides a reproducible realization, not evidence about an error distribution (Avron and Toledo, 2011; Hutchinson, 1989).

If tuning adapts the number of probes, target allocation or solve accuracy, assess that complete adaptive procedure. Existing prediction residual and PEV precision gates remain separate; neither substitutes for the other.

8 Layer 5: deployment-aligned prediction validation

Choose the split from the application: future generations, new families, populations or environments. Define which phenotypes, genotypes and covariates are available at the actual decision time. All phenotype-dependent feature discovery, weighting, tuning and covariance fitting belong inside the training procedure for the claimed validation design (Daetwyler et al., 2013; Runcie and Cheng, 2019).

Use appropriate baselines with the same information. For feature priors, compare the unannotated model, informative features and defensible null or misspecified features. A feature chosen after viewing the test results has not been independently validated. Trait availability and residual correlation can particularly distort multitrait validation (Runcie and Cheng, 2019).

In field data, true breeding values are not directly observed. State the assumptions behind phenotype-based accuracy measures and partial/whole-data comparisons such as the LR method (Legarra and Reverter, 2018). Report calibration and prediction error alongside correlation. Predictive success does not by itself establish a causal biological interpretation of a genomic component.

9 Layer 6: performance and reproducibility

Compare accepted work at matching targets and numerical requirements. Record complete elapsed time and phase breakdowns, physical CPU allocation, runtime libraries, data placement, memory metric and variability between runs. Setup must be included unless the claim explicitly concerns amortized repeated use.

Count operator applications, factorization work, solve RHS and refinements, including derivative and uncertainty calculations. An outer iteration count alone cannot explain total work. State which resources are measured versus estimated; sampled process-tree RSS, GNU Time RSS and scheduler high-water marks are different quantities.

Preserve small deterministic qualification cases separately from opt-in representative-scale studies. Resource-intensive campaigns need an explicit design and budget; they should not be launched merely because a model can be expressed. A benchmark result applies to its frozen workload and environment, not automatically to the full model family.

10 How an evidence record should be written

A useful record includes the scientific specification, code and runtime identity, data provenance, expected target, reference method, acceptance criteria, observed errors, work counts and result status. Record failures and unavailable outputs as well as positive results. A corrected implementation needs fresh evidence for the affected behavior; a theoretical argument or documentation edit is not that evidence.

Conclusions should name their scope: for example, agreement for a supplied- covariance prediction target under a particular missingness pattern, rather than “the entire model is validated.” A reference comparison should say whether it checks predictions, likelihoods, derivatives, uncertainty or parameter estimates. These results need not all follow from one another.

Resource Role
Theory chapters Define models and assumptions, including methods beyond current software
Algorithmic reference Derive representations, computational steps and acceptance quantities
Existing model evidence index Locate recorded evidence with its original scope
Existing capability catalog Interpret model/backend/inference status
Recorded qualification limits Preserve unresolved and negative results

The last three resources describe software evidence; they are not prerequisites for discussing a model’s theory. They also must not be silently promoted by new theoretical material. This separation allows the notes to cover the field broadly while keeping claims about completed software work precise.
