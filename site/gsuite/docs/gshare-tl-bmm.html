Learn from source effect estimates with TL-BMM

A continuous-mixture alternative for learning across separate genomic datasets.

This example fits a Bayesian regression at site A, sends its posterior marker-effect means, then fits site B using those means as one component of a continuous mixture prior. Both sites use the same ordered predictors, allele labels and effect scale. This follows the single-trait TL-BMM model described by Wu and colleagues. The existing BayesC transfer has a distinct zero-effect component.

For marker \(j\), component 0 has mean zero and source component \(k\) has the fixed mean \(m_{jk}\) supplied by source \(k\):

\[ \beta_j \mid c_j=k,s_k^2 \sim N(m_{jk},s_k^2),\qquad P(c_j=k)=\omega_k. \]

Each component variance can have its own scaled inverse-chi-square prior; the weights can have a Dirichlet prior. Every component is continuous. Allocation probabilities describe which source component is preferred. They are not probabilities of a nonzero effect; this model has no PIPs.

Run the example script from the gsuite checkout after installing its development package:

source("tools/examples/gshare_tl_bmm.R")

The script simulates 60 individuals at source A and 100 at receiver B, with three centred predictors and a centred phenotype. It runs two seeded chains, saves a versioned source message under build/examples/gshare-workflow/, reloads it, and prints source, separate and transferred fits. Its numerical priors are illustration settings, not general defaults. A third, smaller site has deliberately conflicting effects; the script compares its separate and transferred effect errors so that borrowing is not assumed to help.

gshare_bmm() also accepts a prepared BED-backed Glist and phenotype data frame through Glist= and data=, with a named reference_frequency= in exact marker order. Its packed operator does not construct a dense genotype matrix or GRM. A small exact-CSR native check exercises the same sampler; sparsified reference LD defines an approximate likelihood and need not agree with an individual-level fit.

The message contains marker-effect estimates, identity and coordinate metadata. The receiver checks marker order, counted alleles, scaling, trait, units and the declared covariate preparation. disjoint=TRUE is an assertion by the analyst; labels cannot verify sample overlap. No individual records are included, but effect estimates can still reveal information. This workflow has no encryption or formal privacy guarantee.

Source estimates are treated as fixed; source posterior uncertainty is not propagated. Source sample size is recorded but does not automatically change the borrowing weight; the analyst supplies the weight and variance priors. The current model assumes a pre-adjusted Gaussian trait and shared effect coordinates. It does not infer allele flips, adjust covariates or fit longitudinal outcomes.

gsuite is in private development. gsim and gact are public.
