Mendelian randomisation with prepared instruments

Prepare aligned candidate variants and use native GSMR, GSMR2, IVW, Egger and weighted median.

Two explicit steps

Prepare instruments from aligned GWAS summaries and an existing LDlist, then fit a method to that saved preparation. All selection, LD filtering, HEIDI and estimation calculations use native gcorr components. Alignment is a separate task.

Download the complete example. It constructs 12 candidate variants with exactly independent LD and outcome effects close to 0.3 times exposure effects. This is a workflow illustration, not a simulation study or a comparison of statistical accuracy. It writes one result bundle, estimate table, figure and reference files under build/examples/mr-workflow. The reference has 1,024 artificial individuals; the illustrative GWAS sample-size metadata are 100,000 and 90,000. No individual-level GWAS is simulated.

library(gsuite)
source("run_mr_workflow.R")
example <- readRDS("build/examples/mr-workflow/workflow.rds")
stat <- example$stat
LD <- example$LD
head(stat$X)

Each trait table contains marker, allele1, allele2, beta, se and n. allele1 is the counted allele. Both tables must match the same subset of the reference in its existing order, including alleles. Rows are not reordered or flipped. Sample sizes are provenance; GSMR does not use them as weights.

Prepare and inspect instruments

prepared <- gcorr(stat, LD, method = "gsmr", task = "prepare_mr",
  exposure = "X", outcome = "Y",
  control = list(non_overlapping_samples = TRUE,
                 effect_units = c(X = "X units", Y = "Y units"),
                 ancestry = c(X = "artificial", Y = "artificial")))
print(prepared)
prepared$decisions
prepared$ld_decisions

Default preparation excludes missing estimates, very small standard errors and exposure associations above \(p=5\times10^{-8}\). It applies the original GSMR LD-pruning rule at \(r^2=0.1\), then filters retained correlations using reference sample size and BH-adjusted LD tests. At least ten instruments must remain. Use method="gsmr2" during preparation for its \(r^2=0.05\) default.

Pruning is degree-based, not significance-ranked clumping; input-order ties can change selection. Every candidate decision and every retained LD-pair decision is recorded. The prepared result is an ordinary serializable R list containing its selected statistics, filtered LD, metadata and decisions. It is not another LD reference format. saveRDS()/readRDS() preserves it without native pointers.

The initial interface materializes at most 2,048 candidate markers by default. Supply a bounded candidate set, not an entire GWAS. Omissions in a sparse reference remain zeros as stored; they do not prove population independence. An invalid or poorly conditioned filtered matrix returns an unavailable result rather than being silently repaired. Inspect available and reason.

Fit and examine results

gsmr <- gcorr(prepared, method = "gsmr", task = "mr")
gsmr2 <- gcorr(prepared, method = "gsmr2", task = "mr")
ivw <- gcorr(prepared, method = "ivw", task = "mr")
egger <- gcorr(prepared, method = "egger", task = "mr")
median <- gcorr(prepared, method = "weighted_median", task = "mr",
  control = list(seed = 19, bootstrap_replicates = 1000))
summary(gsmr)
gsmr$details$heidi
gsmr2$details$heidi$rounds
gsmr2$details$retained_original_indices
plot(gsmr)

These calls deliberately share the same prepared set. GSMR applies original HEIDI filtering; GSMR2 applies iterative global HEIDI. apply_heidi=FALSE disables that additional filtering. Preparation is never repeated during fitting. HEIDI indices refer to prepared rows; retained_original_indices maps the final subset back to the original candidate rows. All indices exposed in R are one-based.

IVW, Egger and weighted median use the preparation before HEIDI, and require approximately uncorrelated instruments. Their default absolute LD tolerance is \(10^{-8}\). Raising this tolerance does not add correlated-instrument uncertainty. The constructed example has exactly zero off-diagonal LD, so all five routes can use it. The weighted-median seed is explicit; generated draws are reproducible within the same C++ runtime, not necessarily across different toolchains.

Results label the exposure, outcome, method, estimate, SE and p-value. Egger also returns its intercept. Method-specific diagnostics include heterogeneity, exposure-strength measures, GSMR weights and ratio covariance, filtering results and bootstrap completion. Missing estimates mean unavailable, not zero effects. MR effects have outcome units per exposure unit; they are not genetic correlations.

Example results

The constructed slope is 0.3. The example produces the following effect estimates (the Egger intercept is reported separately in the saved table):

Method Estimate SE
GSMR 0.2998 0.0147
GSMR2 0.2998 0.0147
IVW 0.2998 0.0144
Egger 0.2938 0.0502
Weighted median 0.2984 0.0179

This simple example checks that preparation, fitting and reporting connect correctly. It does not establish calibration or robustness to invalid instruments.

Direction and interpretation

For reverse-direction MR, prepare again from the original candidate tables with exposure and outcome swapped. The reverse direction must select its own instruments; do not simply reverse a forward-selected set.

This interface supports univariable, non-overlapping-sample analyses with one matching reference ancestry. It does not infer sample overlap, correct for it, perform multivariable MR or convert binary-trait effects to liability scale. User-supplied effects retain their stated units.

Instrument association, a high F statistic, HEIDI filtering or colocalisation does not establish the exclusion restriction. IVW, Egger and weighted median rely on different assumptions about invalid instruments and pleiotropy. Treat their agreement as a diagnostic, not proof of causality. See also the colocalisation workflow.

gsuite is in private development. gsim and gact are public.
