Summary-statistic analysis

gcorr() connects aligned GWAS summary statistics to a prepared LDlist. The R interface handles inputs and results; the calculations run in the native gcorr library. Annotation definitions remain a separate argument.

Start with the complete worked example for runnable code and artificial data supplied with the development package.

Capability table

All methods accept named trait lists. Cross-reference trait pairs are rejected; separate ancestry references do not by themselves define cross-ancestry inference.

Method Exposed tasks Partition or region Uncertainty exposed in R
LDSC h2, cov, rg Ordinary; binary categories and enrichment; weighted annotation coefficients Block jackknife and normal summaries where defined
GNOVA h2, cov, rg Ordinary; binary nonredundant categories, with supporting component h2 Coordinated multivariate block jackknife conditional on the supplied common overlap intercept
SumHer h2, cov, rg Nonnegative architecture weights and totals; category/enrichment helpers are not exposed Coordinated fixed-weight block deletes; joint sampling covariance when available
HESS/rho-HESS h2, cov, rg Independent regional fits, or joint correction across a disjoint complete regional partition Conditional Gaussian plug-in uncertainty and delta-method rg; compact cross-region covariance for joint fits
LAVA h2, cov, rg, partial_rg, regression Shared regional fits; named target, conditioning, outcome and predictor selections Univariate tests; optional seeded bivariate/conditional simulation; regression omnibus test
SUPERGNOVA cov Regional spectral regression Native spectral-WLS covariance uncertainty

LDSC and SumHer support per-marker N; the other exposed methods require one N per trait. LAVA alone has explicit binary-trait metadata and preprocessing in this interface: continuous, binary and mixed inputs, observed-scale covariance and supporting liability h2. The other bindings do not provide automatic binary-trait conversion or prevalence handling.

LAVA uses one shared fit per region. GNOVA and SumHer coordinate their marginal and pairwise calculations so their annotation/component results retain joint block-jackknife covariance across traits. The remaining R paths use marginal or pairwise fits; multi-trait input alone does not imply joint multivariate inference. Missing uncertainty remains missing. All methods use the LD actually retained in the reference. This table states interface coverage, not identical assumptions, calibrated coverage or parity with the original software.

Prepare once

Start with a Glist containing prepared sparse LD, then make an independent LDlist:

library(gsuite)
LD <- ldprep(Glist, reference = "reference-panel", ancestry = "EUR")
saveRDS(LD, "reference-LD.rds")

The LD files must remain available; genotype files are not required to consume this reference. See LD preparation. Use a suitable reference panel and LD construction settings for the intended method. Scores describe retained sparse LD: discarded correlations are not restored.

One trait: heritability

Each input data frame has marker, signed z, and n columns. Rows must match the complete reference marker order. Alignment and allele orientation are a separate preparation task; gcorr() does not harmonize or silently intersect inputs.

# stat contains the already aligned GWAS results.
stopifnot(identical(stat$marker, LD$resource$markers$marker_id))
fit <- gcorr(stat, LD, method = "ldsc", task = "h2")
fit
summary(fit)
plot(fit)

Alternatively supply sample_size = 10000 when there is no n column. Per-marker sample sizes are supported by LDSC and SumHer; the other exposed methods require one sample size per trait. Add a block column to request block-jackknife uncertainty for the score methods. Blocks are a scientific choice, not arbitrary row groups: use a partition appropriate to the LD structure. Without blocks, these methods can return point estimates with unavailable uncertainty.

For a small algebra check using the same LD reference:

ld <- unname(ld_scores(LD))
toy <- data.frame(marker = LD$resource$markers$marker_id,
                  z = sqrt(1 + 10000 * 0.2 * ld / length(ld)), n = 10000)
check <- gcorr(toy, LD, method = "ldsc", task = "h2")
check$estimates  # h2 = 0.2 when the regression design has full rank

This constructs exact regression moments. It is a calculation check, not simulated GWAS evidence or a calibration study.

Two traits and annotations

stats <- list(height = stat_height, weight = stat_weight)
fit <- gcorr(stats, LD, method = "ldsc", task = "rg")
fit$estimates

# annotation is an aligned marker-by-category matrix with row/column names.
LD <- ldprep(LDlist = LD, task = "scores", annotation = annotation)
partitioned <- gcorr(stats, LD, annotation = annotation,
                     method = "ldsc", task = "rg")
partitioned$estimates
partitioned$details

LDSC estimates the cross-trait intercept by default. Binary annotations allow category estimates; continuous annotation weights yield regression coefficients and total estimates, without binary-category enrichment. Overlapping category estimates must not be added together.

GNOVA uses the same inputs, with an explicitly supplied sampling-overlap intercept:

fit <- gcorr(stats, LD, annotation = annotation, method = "gnova", task = "rg",
             control = list(overlap_intercept = 0))

Here zero assumes no correlated sampling errors; it is not a universal default. GNOVA requires binary, nonredundant annotations. Supplied overlap intercepts are treated as fixed in this interface’s uncertainty calculations.

Regional analysis

regions <- list(locus1 = locus1_markers, locus2 = locus2_markers)

# Optional persistent full eigensystems; repeat once for each region.
LD <- ldprep(LDlist = LD, task = "eigen", markers = regions$locus1,
             region_name = "locus1")

sampling <- diag(2)
dimnames(sampling) <- list(names(stats), names(stats))
local <- gcorr(stats, LD, regions = regions, method = "lava", task = "rg",
               control = list(sampling_correlation = sampling))
local$estimates
local$diagnostics

The identity sampling-correlation matrix assumes independent sampling errors. Replace it when samples overlap or sampling errors are correlated. LAVA’s current R route exposes continuous-trait point estimates and univariate F tests. Check the per-trait eligibility and processing diagnostics before interpreting a pair.

Uncertainty for regional genetic correlation

Request the native bivariate simulations explicitly:

local <- gcorr(stats, LD, regions = regions, method = "lava", task = "rg",
  control = list(
    sampling_correlation = sampling,
    inference = list(seed = 12345,
                     pvalue_draws = c(10000, 100000, 1000000),
                     escalation_thresholds = c(1e-4, 1e-6),
                     interval_draws = 10000)
  ))
local$estimates[, c("region", "trait1", "trait2", "estimate",
                     "lower", "upper", "p", "p_mc_se")]
local$diagnostics[[1]]$inference
plot(local)

Without control$inference, no simulation runs. Both traits must pass native univariate screening (default threshold 0.05) for inference to proceed. A pair that fails screening keeps its raw estimate and reports why its uncertainty is unavailable. Adjust the univariate threshold deliberately for the analysis; there is no automatic multiple-testing correction.

lower and upper are native 95% simulation percentile interval endpoints. p_mc_se measures Monte Carlo error in the p-value, not uncertainty in the correlation estimate. Estimator se and normal z remain unavailable rather than being inferred from the interval width. Squared correlation and its interval are retained in local$details under rg_squared.

Inspect pvalue_precision_met, interval_precision_met, draw counts and budget flags. P-value escalation follows the specified thresholds; it does not necessarily continue until the precision target is met. Larger budgets may be needed for small p-values or unstable endpoints. The default relative p-value Monte Carlo tolerance is 0.1 and the endpoint-width tolerance is 0.05. A scalar pvalue_draws requests a single budget with no escalation. All resolved controls are recorded in the fit.

The same explicit seed is used for each pair/region. It leaves R’s RNG state unchanged and is reproducible for a fixed native build, without promising the same random sequence across platforms. P-value and interval simulations use separate streams. These remain pairwise analyses, not joint multivariate inference.

Raw estimates outside [-1,1] are retained. The native interval model can adjust a correlation near the boundary; interval_model_adjusted records this, while interval endpoints are bounded to [-1,1]. Estimates beyond the default absolute inference limit of 1.25 do not receive inference. Diagnostics also retain invalid-draw counts and draws with both variance estimates negative, following the native product rule. These conventions and the reference/rank assumptions remain relevant when interpreting an interval; this interface does not establish new coverage guarantees.

HESS and rho-HESS use the same regional selection:

h <- gcorr(stat_height, LD, regions = regions, method = "hess", task = "h2")
rho <- gcorr(stats, LD, regions = regions, method = "hess", task = "rg",
             control = list(shared_sample_size = 0, phenotypic_correlation = 0))

covariance <- gcorr(stats, LD, regions = regions, method = "supergnova",
                    task = "cov", control = list(overlap_intercept = 0))

HESS fits each region separately, conditioning on supplied outside-region heritability/covariance (zero by default). Supplying several regions does not activate the native joint HESS correction. SUPERGNOVA exposes covariance only; its working heritabilities are not substituted into a genetic-correlation estimate.

Joint correction across regions

For a collection of disjoint regions covering the complete supplied LD reference:

joint <- gcorr(stats, LD, regions = regions, method = "hess", task = "rg",
               control = list(joint = TRUE, shared_sample_size = 0,
                              phenotypic_correlation = 0))
joint$estimates  # regional and total correlations, labelled by scope
joint$details   # also regional and total heritabilities and covariances
joint$diagnostics[[1]]$uncertainty$total_covariance

Use task = "h2" for marginal traits or task = "cov" for covariance. Outside-region contributions are estimated jointly; fixed outside-contribution controls are rejected. Total rows have scope = "reference" and region = NA, so a region called “total” remains unambiguous. Total correlation is computed from total covariance and heritabilities; it is not a sum of regional correlations.

The supplied reference defines the analysis universe. Regions must partition it, and the method assumes independent regional moments. Disjoint marker sets alone do not establish independence. Sample size is constant within each trait and sample overlap is common across regions. Total retained rank must be below the sample sizes; minimum_correction_denominator (default 1e-8) guards an unstable correction. Regional diagnostics retain estimated outside contributions and flags.

Uncertainty includes the cross-region terms introduced by the joint correction. The compact representation stores named raw moment_blocks, a region-by-parameter coupling matrix and total_covariance. It avoids a dense all-region covariance matrix. These are conditional Gaussian plug-in estimates; LD-reference and overlap uncertainty are not propagated. Undefined estimates retain reasons and negative raw estimates are not clipped. The native row-rank correction differs from the upstream HESS column-rank convention for unequal retained regional ranks; this interface does not claim identical upstream results in that case.

Binary traits in regional LAVA analyses

Declare case/control traits explicitly; unlisted traits remain continuous:

stats <- list(disease = stat_disease, height = stat_height)
sampling <- diag(2)
dimnames(sampling) <- list(names(stats), names(stats))

fit <- gcorr(stats, LD, regions = regions, method = "lava", task = "rg",
             control = list(
               binary = list(disease = list(
                 cases = 2000, controls = 8000, population_prevalence = 0.1)),
               sampling_correlation = sampling,
               inference = list(seed = 42)))
fit$estimates
fit$details       # observed-scale and supporting liability-scale h2
fit$diagnostics   # trait type, screening, reconstruction and inference

The example identity sampling matrix assumes no correlated sampling errors; it is not inferred from case/control counts. For two binary traits, add both to binary. For marginal heritability, use task = "h2"; no sampling matrix is needed.

Binary inputs are signed logistic Wald Z statistics. Missing n is filled from cases + controls; any supplied n or sample_size must equal this total, not effective sample size. Each trait needs an explicit population prevalence. The selected LDlist already provides aligned allele frequencies; no additional frequency file is required. Frequencies in each requested region must lie within (0,1). Statistics and reference alleles must already be aligned.

Native binary reconstruction assumes HWE and folds frequencies to min(f,1-f) under its documented LAVA convention. It checks the recovered Wald statistic and rejects unsupported reconstruction rather than silently removing markers. Observed-scale h2/covariance remain the primary estimates. Liability-scale h2 appears separately in details; positive rescaling leaves rg unchanged. Binary univariate screening uses chi-square tests, while continuous traits use F tests. The same screening and optional seeded bivariate inference work for binary/binary and mixed pairs. Raw invalid estimates and screening reasons remain visible. Prevalence and LD-reference uncertainty are not propagated.

The native implementation has equation-matched numerical checks. Differences from the upstream binary optimizer are documented in native evidence; this R binding does not claim full upstream parity or new statistical calibration. Multiple traits share one regional LAVA fit; conditional analyses are described below.

Shared and conditional LAVA analysis

Supply all traits in a named list, with one common LD reference for rg/cov or conditional analysis. Each region is fitted once. An explicit sampling correlation matrix is required for multiple traits, including h2 calls. Binary metadata uses the same controls as above.

ctl <- list(sampling_correlation = sampling)
shared <- gcorr(stats, LD, regions = regions, method = "lava", task = "rg",
                control = ctl)
shared$matrices[[LD$reference]]$region[[names(regions)[1]]]$cov
shared$matrices[[LD$reference]]$region[[names(regions)[1]]]$rg

partial <- gcorr(stats, LD, regions = regions, method = "lava",
                 task = "partial_rg", targets = c("A", "B"),
                 conditioned_on = c("C", "D"), control = ctl)

regression <- gcorr(stats, LD, regions = regions, method = "lava",
                    task = "regression", outcome = "A",
                    predictors = c("B", "C", "D"), control = ctl)
regression$estimates  # coefficients
regression$details   # also standardized coefficients, explained/residual variance and R2

Selectors must name supplied traits, with no duplicate or overlapping roles. All supplied traits influence the common component selection and sample-size cap. Shared fits can differ from separately fitted pairs when their caps differ. The component sampling covariance retained in native_matrices describes per-component noise, not the sampling covariance of final h2/rg estimates.

Coefficients and variances use the native regional covariance scale, including observed scale for binary traits. They are not silently converted to liability scale. Partial correlations and genetic R2 are invariant to positive rescaling. Raw matrices and out-of-range estimates are not repaired.

Conditional inference

Add control$inference = list(seed = 42) to request native simulation inference. Partial correlation supplies tests and intervals. Regression supplies coefficient tests, coefficient/standardized-coefficient intervals, and genetic R2 and explained-variance intervals. These intervals are not global tests.

For the global null test, add control$omnibus = list(seed = 43, draws = 10000) to a regression call. This native fixed-metric simulation tests whether all coefficients are zero. The statistic and p-value are in details; tail-probability bounds, draws and precision flags are in diagnostics[[...]]$conditional$omnibus. It can be requested independently of coefficient inference. It is not a Wald test or an upstream compatibility mode.

Point estimates do not require univariate significance. Inference requires screening, enough retained components, and acceptable genetic/sampling covariance. Default numerical controls within control$multivariate are maximum_traits = 32, minimum_relative_eigenvalue = 1e-4 and residual_variance_tolerance = 1e-8. Partial inference additionally uses maximum_conditioning_r_squared = .95 as a p-value gate; this alone does not suppress intervals.

Inspect rejection reasons, covariance checks, Monte Carlo precision, exhausted budgets and discarded draws. Missing inference does not erase point estimates. Simulation intervals do not manufacture SEs. Multi-pair intervals have no simultaneous coverage guarantee, and there is no automatic adjustment across pairs, regions or conditional models. This interface reuses native qualification; it does not establish new calibration.

SumHer architecture models and multiple traits

SumHer uses model-weighted LD scores and separate positive tagging values. The annotation argument supplies nonnegative architecture weights, including continuous weights; NULL specifies equal per-marker weights. The complete LD reference is the causal-marker universe in this interface. Scores include the diagonal and use the LD entries retained by the resource, so sparse-LD omissions remain part of the reference approximation.

# architecture: marker-by-component weights, rows in LD reference order
LD <- ldprep(LDlist = LD, task = "scores", annotation = architecture,
             score_name = "architecture")

# Explicit choice: ordinary uncorrected LD scores as redundancy/tagging weights.
tagging <- ld_scores(LD)

heritability <- gcorr(stats, LD, annotation = architecture,
                     method = "sumher", task = "h2",
                     control = list(tagging = tagging, score_name = "architecture"))

# stats can contain two, three or more named traits.
fit <- gcorr(stats, LD, annotation = architecture,
             method = "sumher", task = "rg",
             control = list(tagging = tagging, score_name = "architecture"))
fit$estimates
fit$matrices[[LD$reference]]$reference$all$rg
fit$matrices[[LD$reference]]$architecture_component
fit$diagnostics[[1]]$joint_jackknife

The native SumHer cross-trait path supplies the SumCors-style covariance and correlation analysis. Each marginal is fitted once; all unique pairs are fitted. Without overlap_intercept, each pair’s raw Z-product intercept is estimated. A scalar fixes every pair to that value. A symmetric matrix named in trait order allows different values per pair; NA estimates an off-diagonal intercept and the diagonal is ignored. Use task = "cov" to select covariance instead of rg.

inflation selects "none" (default), "multiplicative" or "additive_sample_size". These are explicit model choices, not automatic corrections. Architecture scores must be uncorrected and match the supplied weights. Tagging is required, used as supplied, and never silently replaced by model-weighted scores. Both scalar and per-marker sample sizes are supported.

Results distinguish architecture components from the reference total using scope. Components are not overlapping-category heritabilities or correlations. The native category/enrichment helper is not exposed here. All traits in a cov/rg call must use the same reference and, if supplied, identical block labels. Native coordinated block deletes provide joint sampling covariance across outputs while keeping final regression weights and architecture sums fixed. The diagnostics include a parameter table indexing the covariance matrix and block-by-parameter delete estimates. Without blocks, SEs remain unavailable. This is coordinated marginal/pairwise estimation, not a multivariate likelihood.

Negative components and correlations outside [-1,1] are preserved with native reasons or flags. Trait matrices are not repaired to be positive semidefinite. Rank failure, nonpositive fitted marginal means and nonconvergence are errors. The convergence controls in ?gcorr are separate for marginal and cross fits. This binding does not extend statistical qualification.

References and results

For several references, use a named list and an explicit trait map:

fits <- gcorr(list(EUR = stat_eur, AFR = stat_afr),
              list(EUR = LD_eur, AFR = LD_afr),
              reference = c(EUR = "EUR", AFR = "AFR"),
              method = "ldsc", task = "h2")

Each marginal analysis uses its own reference. Cross-reference pairs are rejected: ancestry-specific LD scores alone do not define a cross-ancestry covariance model. For three or more traits, most methods make separate pairwise fits with common controls. SumHer uses its coordinated native path and can retain joint jackknife covariance across outputs, as described above.

A common result layout

All methods return estimates for the requested task and details for supporting quantities. Heritability rows use quantity = "h2", the actual name in trait1 and trait2 = NA; pair-position names are retained only in native_quantity. diagnostic_id connects every row to fit$diagnostics, without changing native parameter tables or uncertainty objects. diagnostic_summary counts unavailable outputs and out-of-range estimates; absence of an SE is not itself a failed fit.

Scope Meaning
reference Total for the supplied analysis universe; name = "all"
region A named set of regional markers
annotation_category Category summary, including overlap contributions
architecture_component Contribution from one fitted model component
annotation_coefficient A regression coefficient such as LDSC tau

A category can overlap other categories, so its heritability must not simply be summed to obtain a total. SumHer architecture components are a different estimand. GNOVA’s supporting component heritabilities appear in details; its primary h2 output remains category heritability. Weighted LDSC annotations supply coefficients and a total, without inventing binary-category summaries. Conditional LAVA quantities remain explicitly named within their region.

fit$estimates
fit$diagnostic_summary
fit$diagnostics[[fit$estimates$diagnostic_id[1]]]

# The same nesting applies to every method:
fit$matrices[[LD$reference]]$reference$all$cov
# For a regional fit:
regional$matrices[[LD$reference]]$region[[names(regions)[1]]]$rg

plot(fit)                              # requested quantity
plot(fit, scope = "reference")          # totals only
plot(fit, quantity = "h2")              # supporting marginal results

Each matrix set contains named h2, cov and rg matrices. Heritability occupies the diagonal of h2 and cov; off-diagonal h2 entries are NA. A correlation diagonal is one only when its estimated heritability is positive. Uncomputed quantities stay NA: SUPERGNOVA covariance does not imply an h2 or rg estimate. Binary LAVA matrices use observed-scale covariance; liability h2 remains a separate supporting quantity.

uncertainty$cov$se (and the analogous h2/rg fields) contains estimator SEs. Other fields retain p-values, simulation interval endpoints, confidence level, Monte Carlo p-value error, method labels and native reasons. These are marginal entry summaries, not a joint sampling covariance. Native joint jackknife, HESS coupled uncertainty and LAVA simulation diagnostics remain in diagnostics. Additional native matrices are retained in native_matrices, keyed by diagnostic ID.

Separate pairwise fits can disagree about a marginal. Conflicting matrix entries are NA with status = "inconsistent_pairwise_estimates"; no averaging occurs. source_rows identifies the original details$row_id values. Conflicting uncertainty also remains unavailable and is labelled. Raw long-table estimates are retained. Matrices are not clipped or repaired; incomplete covariance matrices have cov_positive_semidefinite = NA.

Plots label reference, scope, name and traits. Bars use an available 95% simulation interval, otherwise one estimator SE; absent uncertainty gives a point only. Monte Carlo error is never used as an estimator SE. Undefined estimates are marked in labels. Use scope, quantity, reference and traits to select results, and ordinary graphics arguments such as main or xlim to format them. One plot cannot combine different quantities or incompatible scales. Method labels do not imply identical assumptions, calibrated coverage, simultaneous inference or software parity.

No result files are written automatically. Matching cached spectra are verified once per region during a call, then reused for trait pairs. Missing spectra are computed in memory. Explicitly prepare annotation scores before fitting.

Current boundary

The common R interface covers LDSC, GNOVA, ordinary and architecture-partitioned SumHer (including multiple-trait covariance/correlation), independent and joint-region HESS/rho-HESS, continuous/binary LAVA point estimates, univariate tests and optional bivariate simulation inference, and SUPERGNOVA covariance. LAVA additionally exposes shared matrices, partial correlations, regression and supported conditional/omnibus inference. SumHer category/enrichment summaries and other native capabilities remain outside this R interface. Consult ?gcorr for method-specific controls and defaults.

Small deterministic tests check the bindings against independent algebra and cache reuse. They do not extend the native methods’ statistical qualification or establish full upstream-software parity.

gsuite is in private development. gsim and gact are public.
