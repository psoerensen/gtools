Methods

A suite-wide catalogue of implemented, experimental and planned capabilities.

Catalog authority. This page contains route-specific method descriptions and historical version notes. The current suite-wide LMM status is defined by the canonical model catalog, with evidence in model qualification. An exclusion below applies only to the workflow and version being described; it is not a global gsuite capability statement.

This catalogue maps confirmed public capabilities to their owning repository. Implemented means the capability is implemented in development code and exercised by relevant repository validation; it does not claim production-scale qualification. Experimental identifies a present but deliberately provisional integration surface. Planned identifies work with no current public implementation.

The pedigree tutorial demonstrates the data-frame interface on 10,000 simulated animals. It reuses existing numerical engines:

Formula model Scope
Pedigree animal model One or multiple traits; missing responses omitted trait by trait
Genetic random regression One response, one pedigree effect and homogeneous residuals
Independent components Multiple pedigree/identity intercepts, including permanent environment and common groups
Correlated channels One response with named channels under a shared kernel, such as direct/maternal effects
Structured residuals Grouped variances, integer-gap AR(1), or continuous-time exponential correlation

Short and explicit forms share normalization. formula and formulas are aliases; starts do not select the engine. REML initializes omitted starts, while supplied values remain authoritative. Fixed solves require complete covariance values. The tutorial gives the route-specific initialization rules.

Distinct descriptors are independent. Correlated channels must be declared explicitly and have known IDs for observed responses. Correlated residual blocks require unique positions within one variance group. Multi-component multitrait/random regression, multi-response residual descriptors, nuggets and unknown-time imputation remain outside this adapter. Covariance boundaries and unsupported combinations are not silently repaired. These examples do not extend workload or platform qualification.

Marker-space and RHE methods

With marker weights D, normalization s, genomic variance V_g, and residual variance V_e, gsuite derives \(\Lambda = (V_e s/V_g)D^{-1}\). Explicit marker_gs constructs gbits’ existing fused-coordinate PackedGsPreconditioner and uses it inside every covariance PCG solve in the REML evaluation and optimizer. It is therefore reported as marker_gs_preconditioned_pcg, not as a direct marker inverse solve. The fused coordinate cache is prepared once per fit; a changed parameter state builds a bounded penalty/preconditioner state, while identical common-precision reevaluation may reuse the exact immutable pairing.

marker_preconditioner_sweeps is the exact symmetric sweep count per preconditioner application. Diagnostics separate cache construction, parameter-state preparations, PCG applications, processed RHS columns, sweeps, marker visits, packed decode passes, factor lifecycle, and memory. Fused coordinate application uses no block-Cholesky factorization. The surrounding covariance route continues to report response/preparation/information PCG iterations and true residuals together with operator and preconditioner work. Multiple RHS, including block PCG, are supported by gbits; concurrent outer applications are rejected before fitting because the packed preconditioner is nonconcurrent.

The total genomic prediction is recovered as \(y-F\beta-V_e Py\), so no generic \(XB\) pass or final marker solve is performed for that result. A precise final marker solve is reserved for explicitly requested component-specific marker effects or validation.

initializer="rhe" asks greml to build projected response moments and common- probe trace moments, solve the unregularized small system, retain raw estimates, and make every zero/positive boundary adjustment explicit. RHE is a start, not an ML/REML estimate; the existing safeguarded AI-REML route remains responsible for the reported likelihood and convergence. RHE diagnostics cover initialization only. Evaluation at the RHE starting point, subsequent optimizer work, and optional final marker prediction are separate stages; whole-fit elapsed time is not labeled as RHE initialization.

genomic_solver="marker_batch" is distinct from the preconditioner. For every parameter state it derives one penalty vector per ordered genomic component and calls gbits 0.16 once with response plus the complete deterministic probe prefix. AI component right-hand sides are submitted in one additional batch. Each system owns independent fixed effects, marker coefficients, residual, convergence and warm state; all components in that system share the same observation residual. One decoded block is read by disjoint system-column owners, and exact forward/backward marker order is retained per system.

Response/common-probe and component-Py batches retain independent warm states. Existing ordered columns remain warm through compatible penalty changes and staged precision tightening; deterministic prefix extensions initialize only new columns at zero. An active component-set change invalidates the incompatible marker state. When all genetic variances are zero, gsuite handles the residual-plus-fixed projection analytically and never constructs an invalid marker penalty.

For precisely one genomic component plus identity residual under REML, the explicitly selected experimental option marker_score_ai="identity_optimized" uses the identities

\[ \begin{aligned} V_g\operatorname{tr}(PK)+V_e\operatorname{tr}(P)&=n-p,\\ V_g KPy+V_e Py&=y-X\widehat{\beta},\\ V_g P(KPy)+V_e P(Py)&=Py. \end{aligned} \]

to derive the genomic trace and score vector from the projected common probes and response, then projects only Py in the information batch and derives \(P(K Py)\). The mathematical score and full 2-by-2 AI definition do not change. marker_score_ai="direct", the public default, retains the component covariance applications and two-column information batch. The optimized route requires \(V_g>64\sqrt{\epsilon_{\mathrm{double}}}\max(\lvert V_g\rvert,\lvert V_e\rvert)\); near or at zero, for ML, or for any model other than exactly genomic-plus-identity, it falls back to the direct route. This is independent of the opt-in determinant- deferred acceptance policy.

With the direct statistical policy, the independent execution control marker_coefficient_reuse defaults to "automatic"; "off" forces the original component applications and "required" fails if a safely eligible packed component cannot supply all coefficient-derived quantities. This does not select another estimator. The packed MME equations use \(\Lambda_{cj} = V_e s_c/(V_c w_{cj})\) and therefore return \(a_c(b) = V_c D_c W_s^{\mathsf T}Pb/s_c\). gsuite caches \(W_s^{\mathsf T}Z\) once per prepared-source and probe identity, then evaluates the original direct probe realization \(a_c(z)^{\mathsf T}W_s^{\mathsf T}z/V_c\) and response quadratic \(s_c a_c(y)^{\mathsf T}D_c^{-1}a_c(y)/V_c^2\).

The cache is double precision and bounded by marker_coefficient_cache_memory_limit (512 MiB by default). Its identity includes the prepared packed storage, ordered sample/marker selection, transformation and missing policy, common-probe stream, dimensions, and actual probe columns. A compatible prefix hit reuses old columns and transposes only the extension; independent verification probes and incompatible sources form separate entries. Exceeding the budget falls back in automatic mode and fails in required mode. At zero or below the scale-aware guard \(64\sqrt{\epsilon}\,\texttt{parameter\_scale}\left(1+\frac{\texttt{achieved\_normal\_residual}}{\texttt{requested\_tolerance}}\right)\) the direct boundary component path is retained, so no division by a small variance occurs.

For one packed component plus identity, \(KPy\) uses the exact response residual identity. Multiple weight-defined components sharing a source concatenate their response marker coefficients and use one multi-RHS packed xmat, so the source is decoded once. Generic components retain direct operator application. The cache transpose and fused reconstruction use the existing operation-local packed thread controls and no nested OpenMP. Diagnostics report requested and resolved policy/components, fallback reasons, cache hits/misses/columns/bytes, reused/appended columns, reduction and reconstruction time, avoided and direct applications, information width, and reconciled marker visits/decode passes. Likelihood and determinant computation, including determinant-deferred’s one final likelihood-only verification, are unchanged. Longitudinal AI-REML coefficient reuse remains future work.

Fixed-parameter evaluation can omit likelihood and SLQ explicitly. The default optimizer remains likelihood-monotone. Opt-in acceptance_policy="determinant_deferred" uses curvature-scaled projected score and Newton decrement for backtracking, with fixed and active-boundary components removed from the free AI solve. Provisional convergence additionally requires projected KKT score, parameter change, solver residual, score SE, stable active set, a larger final probe prefix, and independent verification probes; a complete deterministic trace basis may bypass fresh probes. Iterative accepted/rejected/verification states do no determinant work. One generic covariance-PCG/SLQ likelihood-only verification runs after provisional convergence and is merged without repeating packed score/AI batches.

The policy is supported for single-trait, complete-record multivariate, balanced structured longitudinal, and general observed-record longitudinal matrix-free workflows with the safeguarded nonadaptive optimizer. Sparse, hybrid, legacy indexed/sparse longitudinal, adaptive, and other facade routes reject it. Work diagnostics separate all score/AI, likelihood, verification, SLQ, batch, thread, sweep, warm-system, decode, residual, and timing categories. Score/AI trials can cost more than likelihood-only rejected trials, so speedup is workload-dependent. Balanced-longitudinal BLUP requires REML convergence; an unavailable BLUP reports that failure explicitly and does not establish a converged boundary solution. Structured Q defaults to "positive" (unchanged log-Cholesky SPD behavior). Balanced "may_be_zero" blocks use symmetric covariance coordinates with PSD projection and AI quadratic proposals, accepted by likelihood backtracking. Convergence requires the AI-scaled projected-score mapping to satisfy the existing score tolerance; projection or failed backtracking alone never suffices. At zero, a positive score eigen-direction can be released. Complete explicit probes and full-dimensional Lanczos depth bound this initial deterministic route. RHE keeps its raw estimates and maps PSD starts without a positive eigenvalue floor. Residuals stay strictly positive; fixed and observed-record PSD blocks remain unsupported. Likelihood and BLUP apply Q without inverting it.

Packed-call diagnostics label response/common-probe, component-information, identity-information, and likelihood-inverse work and report RHS width, requested/resolved threads, marker visits, decode passes, decode time, compute time, and wall solve time. The compatibility packed_decode_passes field keeps its prior marker-batch meaning. batched_total_packed_decode_passes includes likelihood-inverse batches, covariance_packed_decode_passes includes packed covariance products used by score components, PCG, and SLQ, and the explicitly named total_packed_decode_passes is their sum; marker-visit and timing totals are exposed alongside them.

Multivariate RHE-to-BLUP workflow

gs_multivariate_rhe_blup() is a single bounded workflow: it estimates named component trait covariances and the residual trait covariance once with matrix-free randomized HE, then passes the explicitly PSD-adjusted estimates directly to one multivariate BLUP solve. The return value keeps raw RHE estimates, adjusted prediction parameters, component-specific values, and the combined value distinct.

Packed genomic terms created from the same gs_bed() resource are grouped by prepared-source identity. All marker-weight components share one decode for the phenotype moments, one decode per bounded common-probe batch, each batched multivariate covariance application, the diagonal preparation, and the final component-value application. Generic dense, pedigree, group, and sparse relationship terms retain the ordinary matrix-free operator route.

Controls expose probe count/batch/seed, packed threads, moment rank and conditioning limits, PSD floors, multiple-RHS strategy, PCG tolerances and iteration cap, block numerical-rank tolerance/restart cap, true-residual tolerance, and the explicit unavailable-diagonal fallback. Packed execution is the only OpenMP layer. Diagnostics attach a purpose to every traversal and report marker visits, decode passes, RHS width, component count, thread resolution, and decode/compute time.

The supported scope is complete traits on common individuals, one common full-rank fixed design, and arbitrary named PSD relationship components. Multivariate AI-REML, determinants, missing traits, marker effects, PEV, reliability, single-step GBLUP, and longitudinal models are not part of this workflow.

Complete-record multivariate AI-REML packed reuse

The existing gs_multivariate_model() plus gs_model_fit() stochastic AI-REML route retains its finite log-Cholesky parameters, derivative matrices, optimizer, likelihood-monotone acceptance, and determinant calculation. The execution-only marker_coefficient_reuse control now also applies to compatible packed terms in complete-record multivariate fits.

For \(K_c = W_c D_c W_c^{\mathsf T}/s_c\), gsuite obtains \(W_c^{\mathsf T}Z\), \(W_c^{\mathsf T}PZ\), and \(W_c^{\mathsf T}PY\) with the existing packed multi-RHS transpose. Components sharing a prepared BED source share the unweighted transposes; their weights and normalizations are applied only in marker-space reductions. The resulting small trait matrices are

\[ \begin{aligned} (PZ)^{\mathsf T}K_c Z&=(W_c^{\mathsf T}PZ)^{\mathsf T}D_c(W_c^{\mathsf T}Z)/s_c,\\ (PY)^{\mathsf T}K_c PY&=(W_c^{\mathsf T}PY)^{\mathsf T}D_c(W_c^{\mathsf T}PY)/s_c. \end{aligned} \]

greml contracts these matrices with the unchanged log-Cholesky derivative \(H_j\). gsuite reconstructs all \(K_c PY\) for a shared source with one fused packed output call; greml then forms \(K_c PY H_j\) and retains its existing batched information projection and AI definition. Native multivariate marker coefficients are not required or exposed.

The double-precision \(W^{\mathsf T}Z\) cache is bounded by marker_coefficient_cache_memory_limit, keyed by prepared-source and explicit probe identity, supports compatible prefix extension, and isolates independent probe streams. Automatic mode falls back term-by-term to direct covariance application; required mode fails for an unresolved packed term; off is the original direct route. Dense/operator-defined relationship terms remain direct.

PLINK mode validation remains in gbits and rejects non-SNP-major BED files. Packed transposes process all trait/probe columns together with disjoint marker rows, and shared-source reconstruction processes every component/trait column in one output call. Diagnostics report cache lifecycle, \(W^{\mathsf T}Q\) source, packed purposes, contiguous SNP runs, decoded records, fused width, components, requested/resolved threads, avoided/direct applications, and reconciled totals. Thread count does not multiply decode passes.

Experimental multivariate determinant-deferred acceptance composes with this reuse path without altering its sufficient statistics. It evaluates rejected trials with score only in the current accepted AI metric, completes AI once for an accepted state, and runs the unchanged likelihood exactly once after numerical convergence. Optimizer convergence and fixed-probe Monte Carlo adequacy are separate diagnostics; an iteration-limit exit has no finalized likelihood. Exact singular covariance boundaries, missing or unbalanced traits, unbalanced/indexed longitudinal structures, PEV/reliability, and marker-effect output remain outside this route.

Formula and variance-component pedigree REML

The persistent covariance constructor gs_model_pedigree(sire, dam, observation_animal, name, ...) supplies a gs_covariance term to gs_model() and gs_model_fit(). It preserves the ordered-parent and optional Mendelian variance contract in the persistent interface. The formula kernel below is a separate constructor; no implicit dispatch or compatibility alias connects the two APIs.

gs_pedigree(), gvc(), gs_fit_control(), and gfit() provide the bounded in-memory formula interface documented in formula-reml.md. One single-trait formula or named multitrait formula list is lowered to greml’s installed public compiled-MME interface when compiled controls are explicitly requested. Those single-trait models accept one or two (1 | variable) terms: at most one pedigree and one independent identity component, plus a homogeneous residual. Multitrait models retain one shared pedigree intercept per trait. This route requires complete positive-interior starts. General formula calls accept either argument spelling and have optional starts and a broader independent-component scope, as described in the pedigree tutorial.

Fixed effects use base R model machinery. Random incidence is compiled from record IDs, trait/member identities, and unit weights; gsuite does not construct an R random-effect incidence matrix. Missing trait responses are absent scalar records in complete or incomplete patterned residual units. The immutable plan performs one record pass, a direct session retains one symbolic structure, and successful optimization reuses the accepted likelihood and response for one BLUP finalization.

The control maps direct and support thread domains, exact trace selection, and all public resource limits, including required/configured peak dense RHS workspace. Rejected preflight and unsupported support execution retain greml’s status and perform zero solver work. PARDISO coordinate-exact traces and CHOLMOD selected inversion are reported without capability substitution.

Balanced structured longitudinal workflow

gs_balanced_longitudinal_model() is one shared specification for the complete pipeline. It accepts a finite n by T phenotype matrix, common full-rank sample design X, full-rank time design F, and named components constructed by gs_longitudinal_component(). Component c supplies a relationship base, an explicit T by r_c basis B_c, and an interior r_c by r_c coefficient covariance Q_c. The model is

\(\operatorname{E}(Y) = X C F^{\mathsf T}\),

\[ V(A) = \sum_c K_c A B_c Q_c B_c^{\mathsf T} + \operatorname{residual}(A). \]

The residual is homogeneous independent by default or complete-record unstructured SPD. No dense production Kronecker design, GRM, or nT covariance is constructed.

gs_longitudinal_fit() runs RHE once, maps its separately preserved adjusted prediction covariances to explicitly reported finite log-Cholesky REML initial coordinates, runs AI-REML once, and optionally runs BLUP once. RHE returns raw and adjusted Q_c, observed-grid covariances, residual adjustment records, moment rank/condition/Monte Carlo diagnostics, fixed-design diagnostics, and packed traversals. REML retains the existing derivatives \(B_c \frac{\partial Q_c}{\partial\eta_j} B_c^{\mathsf T}\) and uses packed marker sufficient statistics without one source traversal per Q_c parameter.

The new workflow defaults to experimental determinant-deferred acceptance. Score stationarity is the configured raw-score rule or the joint curvature-scaled-score/Newton-decrement rule at a valid accepted state; it does not require another accepted micro-step. Line-search exhaustion is never a convergence condition. Numerical convergence and fixed-probe stochastic precision are separate. Successful convergence has zero iterative likelihood, determinant, and SLQ work and one final likelihood-only evaluation; final score and AI are retained.

BLUP returns latent \(U_c = K_c \alpha B_c Q_c\), component trajectories \(U_c B_c^{\mathsf T}\), their total, and fixed/fitted trajectories. Explicit compatible B_new and F_new matrices provide common-new-grid prediction. The balanced route remains the optimized common-grid convenience path.

Missing and irregular observed-record longitudinal workflow

gs_longitudinal_records_model() represents only observed scalar records. Its y, subject vector, optional reporting time, and rows of the general fixed design have common length Nobs. Each component supplies an Nobs by r_c basis and components may have different ranks. gs_record_longitudinal_residual() maps every record to a homogeneous or grouped diagonal variance and requires every group to occur. Absent records are never imputed or silently dropped.

The native operator scatters record RHS values through each component basis to an n by r_c subject matrix, applies the relationship to all coefficient/RHS columns together, multiplies by Q_c, and gathers to records. RHE, REML, likelihood and BLUP use this same operator. Raw RHE estimates, adjusted prediction estimates, and finite-interior REML initial values remain distinct. Record REML defaults to determinant-deferred acceptance with fixed common probes, zero iterative likelihood/SLQ calls, and one final likelihood after verified convergence.

Packed components sharing a prepared BED source share SNP-major \(W^{\mathsf T}Z\), \(W^{\mathsf T}PZ\), \(W^{\mathsf T}PY\), and fused reconstruction. Diagnostics report cache activity, purpose-specific traversals, fused RHS width, component count, marker visits, decode passes, and requested/resolved threads. gs_longitudinal_fit() returns latent subject coefficients, observed values and residuals, and optional values for explicit prediction-record subject/fixed/basis rows.

Deliberate exclusions are pedigree and sparse MME, multiple response channels per record, AR(1)/continuous-time residual correlation, exact singular boundaries, PEV/reliability, marker effects, and single-step models.

Sparse-direct pedigree methods

The three pedigree APIs use the same canonical lower-CSC MME for their supported direct backends. Retained factors supply exact determinants and bounded coordinate traces or CHOLMOD selected-inverse traces. Rejected likelihood-only trials omit trace/AI work; accepted response coefficients finalize BLUP without another response solve. Backend factor-memory limits are preflight bounds, not strict allocator quotas.

Use the model catalog for backend/inference status, multitrait workflow and longitudinal workflow for record contracts, and prediction error for complete-MME PEV, CHOLMOD selected inversion, and bounded PARDISO retained-factor target solves. PARDISO selected inversion remains unsupported. Direct and support thread domains and requested/resolved methods remain distinct diagnostics.

Independent LD references

A separate LDlist describes one reference panel using gmat’s existing signed, disk-backed sparse LD. Create it from a gsuite Glist after sparse-LD preparation:

LDlist <- ldprep(Glist, reference = "1000G-EUR", ancestry = "EUR",
                 assembly = "GRCh37")
saveRDS(LDlist, "LDlist-EUR.rds")
LDlist <- readRDS("LDlist-EUR.rds")
validate_LDlist(LDlist)
scores <- gsuite_ld_scores(LDlist$resource)

The resource field retains authoritative marker order, alleles, chromosome, position, reference sample count, file paths and construction settings. af and ldscores are named vectors in resource marker order. reference identifies a particular panel; ancestry and assembly are caller-supplied labels. No genotype files are needed after construction. Keep the external LD files: RDS saves their descriptor, not their contents. Checksums and native inspection reject accidental file replacement; validation reads the resource rather than being a constant-time operation. It does not establish population suitability.

ldprep(task = "sparseld") can also compute native LD directly from a prepared Glist. The caller’s Glist remains unchanged. task = "scores" prepares named ordinary or annotation-specific score sets on an existing reference:

LDlist <- ldprep(Glist, reference = "1000G-EUR", task = "sparseld",
                 out_prefix = "reference_ld", r2 = 0.01,
                 max_distance_bp = 1000000)
LDlist <- ldprep(LDlist = LDlist, task = "scores", annotation = annotation,
                 score_name = "functional", corrected = TRUE)
scores <- ld_scores(LDlist, annotation = annotation,
                    score_name = "functional", corrected = TRUE)

Annotation rows must already match the reference marker order. Saved sets retain annotation values/names, column sums, correction settings, reference sample count and resource checksums. Retrieval rejects mismatched definitions or changed resources. A repeated preparation with identical options reuses its saved set; a different definition needs a new name or explicit overwrite = TRUE. Payload checksums detect accidental edits; they are not a security mechanism. Retrieval validates the reference files but does not recompute annotation scores.

The base ldscores vector remains ordinary and uncorrected. Corrected sets use native gmat finite-reference correction with the selected reference sample count; negative corrected contributions are retained. All scores reflect retained sparse pairs: omitted correlations are not reconstructed. Arbitrary finite annotation weights can be prepared, but each estimator enforces its own restrictions. Summary harmonization remains separate; the gcorr R interface requires complete aligned inputs. Glist is unchanged, and LDlist does not contain Glist. Multiple panels can be held in a named R list. Old qgg binary formats are not silently interpreted as the gmat CSR format.

Regional matrices and reusable eigensystems

Select a region using unique marker IDs already in reference order:

R_region <- ld_region(LDlist, markers = region_markers)

gmat extracts the dense regional matrix through its validated streaming reader; no full CSR is loaded. gsolve computes the complete symmetric eigensystem using its existing Eigen backend and verifies reconstruction, residual and orthogonality. The result contains descending values, column vectors with marker row names, and numerical diagnostics. Singular or indefinite matrices are not silently repaired: zero and negative eigenvalues remain available to method-specific checks. Thresholded or windowed sparse LD is not necessarily positive semidefinite.

Named caches retain region marker order, reference sample count, resource checksums and computation settings. Identical preparation reuses the entry; changed regions or settings require a new name or explicit overwrite = TRUE. Retrieval checks those definitions and detects accidental payload edits without recomputing the eigensystem. Reference validation still reads the LD files. Save/reload requires the LD files but no genotype inputs. Annotation definitions are independent of regional eigensystems; each method chooses its own eigenvalue selection later.

eigen_control accepts maximum_dimension (default 2048), symmetry_tolerance (default 64 times machine epsilon), and verification_tolerance (default 1e-10). Supply matching settings at retrieval if preparation used nondefaults. The full decomposition takes quadratic storage and cubic computation; increasing the limit is an explicit choice. Omitted sparse correlations remain zero, the diagonal is one, and no harmonization, clipping or PSD repair is performed.

The native gcorr library can now consume the underlying resources through score adapters and PreparedRegionalLd. HESS, rho-HESS, SUPERGNOVA and LAVA have single-region overloads that reuse a complete checked eigensystem; LDSC and GNOVA already accept prepared gmat score inputs. gsolve can verify imported eigenvalues and vectors against a regional matrix without rerunning the eigensolver. This dense verification is performed once on native import, followed by reuse across fits. The gcorr R interface connects selected methods to these resources, including explicit joint HESS/rho-HESS correction with regional and total uncertainty. It adds no cross-ancestry estimator and also exposes shared LAVA matrices and native conditional inference.

Across these methods, result tables use explicit reference, region, annotation-category and architecture-component labels. Named h2/cov/rg matrices share one layout; method-specific uncertainty, native diagnostics and inconsistent pairwise estimates remain visible. See result conventions.

The common gcorr() interface also exposes SumHer architecture-component and reference-total h2/cov/rg. Multiple traits use the native coordinated marginal and pairwise fits, with joint fixed-weight jackknife covariance when blocks are supplied. Tagging weights are explicit and separate from architecture-weighted scores; no cross-ancestry or full upstream-software parity is implied.

Regional LAVA also accepts explicit binary-trait metadata, reusing LDlist allele frequencies for native logistic-Wald reconstruction. Observed and liability h2 remain distinct; binary/mixed pairs use the existing screening and optional bivariate simulation inference. LAVA shares each regional fit across traits and exposes partial correlations, multiple regression, explained variance and supported conditional/omnibus inference.

Native regional execution now supports multiple named references and regions. Each request explicitly assigns a reference to every trait; all traits in that request must agree. Independent requests may use different references. Results retain analysis, region and reference labels, along with method diagnostics or a per-request failure. Execution is sequential and writes no result files. Joint HESS and rho-HESS can reuse prepared regions within one selected reference while retaining their existing disjoint-region and joint uncertainty assumptions. Reference labels are caller-declared identities, not an ancestry validation step.

For continuous-trait regional LAVA correlations, gcorr() now accepts an explicit control$inference list. The native bivariate procedure supplies screened p-values, 95% simulation intervals and Monte Carlo diagnostics while retaining raw point estimates. See the regional inference example. This adds no new numerical algorithm or statistical calibration claim.

Native colocalisation

gmap provides approximate-Bayes-factor colocalisation for one region and two continuous traits, assuming at most one causal variant per trait and non-overlapping samples. It returns H0-H4 probabilities and explicit prior-sensitivity summaries. The implementation has independent numerical checks and pinned coloc comparisons; these establish numerical agreement, not broad statistical calibration. The gsuite::coloc() ABF route accepts two aligned regional beta/SE tables, explicit phenotype SDs and priors without an LD object. It returns regional probabilities and conditional-H4 marker support, distinct from component-pair colocalisation. See the worked example. GWAS association remains planned; Bayesian fine-mapping and posterior-set interpretation are available as described below.

Native Bayesian inference

gbayes provides single-trait BayesC and BayesR with fixed parameters or explicit learning of residual variance, slab variance and mixture weights. Prepared scores and cross-products can use dense storage, gmat LD operations with explicit marker scaling, or prepared factors with reduced residuals. Factorized execution avoids a dense cross-product matrix. Truncated inputs use explicitly projected scores; residual learning then requires retained-space normalization (dimension and response sum of squares). Results include posterior means, empirical posterior variances, marginal inclusion probabilities and compact per-chain summaries. BayesR also returns marker component probabilities; both methods summarize learned parameters. Residual-variance learning requires compatible phenotype sums of squares and an explicit Gaussian likelihood dimension, not just LD and scores. The gmap() R binding exposes BayesC/BayesR separately across named traits and regions, including optional variance and mixture-weight learning. MCMC learning requires explicit inverse-chi-square or Dirichlet hyperpriors. Residual learning also requires complete in-sample LD, phenotype sum of squares and likelihood dimension; these are never inferred from the reference panel.

The initial checks cover an independent scalar posterior calculation, dense/gmat agreement, an installed native consumer and a tiny matched sblr reference. They do not establish broad calibration or convergence. Supplied cross-products must define a valid positive-semidefinite operator; structural checks do not repair or certify arbitrary thresholded LD. Annotation priors and multivariate inference remain future work.

Native regional Bayesian analysis

gmap’s optional gmap::bayes component fits or summarizes one-region BayesC/BayesR models through installed gbayes. It preserves marker alignment, region coordinates, trait/effect units and the complete native posterior. Results include marker rankings and the posterior expected active-marker count, calculated as the sum of marginal PIPs. Existing gbayes priors and learning controls pass through.

These posterior summaries describe marker support. Separate set helpers below interpret marginal PIPs or component assignments. These summaries do not themselves perform colocalisation or estimate regional heritability. The separate coloc() interface consumes multi-effect evidence. Inputs are already aligned. The experimental gmap() R binding returns regional posterior estimates, native set controls and chain diagnostics for named regions and traits, with regional preparation shared across traits. The standalone colocalisation target acquires no Bayesian dependency. Focused checks cover posterior reuse, metadata/ranking semantics and installed interfaces.

Native single-effect inference

gbayes now provides a deterministic single-effect normal model for one prepared marker set. It reuses the normal conditional calculation and accepts the existing dense, LD-backed and factorized inputs. Outputs include marker assignment probabilities, conditional and averaged effect moments, and model evidence against no effect. Residual and effect-prior variances are fixed; marker prior weights can be specified explicitly.

The model assumes exactly one active marker, so assignments sum to one even when evidence is weak. They are not unconditional association probabilities. This is a reusable building block; the separate multi-effect entry point below adds iteration and convergence handling. gmap now consumes assignments for credible sets; multi-signal colocalisation remains separate. There is no R binding. Focused independent numerical integration and installed-interface checks cover the native calculation.

Native multi-effect inference

gbayes also provides single-trait sum-of-single-effects fitting through sequential IBSS updates. It reuses the existing single-effect calculation and dense, LD or factorized operators. Outputs include component assignments, combined effect means, variational variances/PIPs, and an objective trace with explicit convergence or sweep-limit status.

The objective is an evidence lower bound relative to the null likelihood, not an exact model Bayes factor. The approximation factorizes across components; convergence does not guarantee a global optimum or calibrated uncertainty. The maximum component count is supplied, and components may select the same marker. The default fixed-variance route leaves every component active. Optional EM learning estimates a variance for each component and compares it with zero; inactive components contribute no effects or PIPs. Optional residual-variance learning uses expected residual sums of squares with compatible normalization. Inner learning limits and outer convergence are reported explicitly. gmap supplies credible sets only for active components while retaining inactive indices and all component variances. The gmap() R binding exposes this route separately across regions and traits, with optional residual- and effect-variance learning. Residual learning requires complete in-sample LD and explicit phenotype normalization. Small analytic/evidence and operator checks cover the native calculation; full susieR equivalence is not claimed.

Native posterior sets

The optional gmap Bayesian component supports two explicitly labelled routes. Marginal-PIP sets reuse sblr’s LD-neighborhood and approximate multi-signal selection, including incomplete-set handling and alternative lead/removal rules. Their mass is an expected active-marker count, not a probability that at least one causal variant lies in the set. This route consumes BayesC/BayesR PIPs.

Component-based credible sets consume single-/multi-effect assignment rows. They retain each component, report achieved probability coverage and flag exact duplicate memberships. Shared diagnostics include lead-based and full pairwise LD summaries. Low purity is flagged without trimming away coverage. Sparse LD omissions are explicitly recorded; purity is evaluated on the supplied matrix.

These helpers validate probability domains and exact fit/LD marker order, preserve available convergence/likelihood status, and do not refit or align data. Learned zero-variance components are recorded without sets; the raw assignment route still treats every row as a component. Weak fixed-variance components can produce diffuse sets; a complete credible set does not establish a signal. The R binding exposes these controls through control$sets, with explicit set meanings and component eligibility diagnostics.

Prior-variance learning is empirical Bayes, not posterior uncertainty over model size or a test proving signal existence. The EM search is local; inactive components are reconsidered from a positive starting variance each sweep. The reusable learned single-effect entry is available independently. Existing fixed-variance entry points retain their previous numerical behavior.

Regional Bayesian R workflow

gmap() accepts an aligned LDlist and exact sufficient-statistic columns marker, allele1, allele2, score (\(X^T y\)) and marker_ss (\(\operatorname{diag}(X^T X)\)). It fits each named region/trait separately using BayesC, BayesR or multi-effect inference. It does not convert GWAS z scores or beta/SE automatically. The supplied LD and marker scales define the working cross-products; a reference approximation does not become exact cohort LD.

fit <- gmap(list(height = stat_height, weight = stat_weight), LD,
            regions = list(locus1 = markers_locus1, locus2 = markers_locus2),
            method = "multi_effect",
            prior = list(residual_variance = 1, effect_variance = .02),
            control = list(effects = 4, estimate_effect_variance = TRUE))
summary(fit)
plot(fit, region = "locus1", trait = "height", quantity = "pip")

Prior values above are illustrative and must match the supplied data scale. Controls and seeds are shared across fits; use separate calls for different priors or independent random streams. Matching named LDlist eigenpairs are verified and reused; otherwise each region is decomposed once across traits. Persistent caching remains explicit through ldprep(task="eigen"). control$sets exposes method-specific native set controls. BayesC/BayesR retain pooled and per-chain PIPs, with native between-chain spread summaries; these are not convergence certificates or Monte Carlo standard errors.

For traits analysed in independent samples, the saved fits can be compared:

shared <- gsuite::coloc(fit, fit, trait1 = "height", trait2 = "weight",
                       regions = "locus1",
                       control = list(complete_region_coverage = TRUE,
                                      non_overlapping_samples = TRUE))
summary(shared)
plot(shared)

The two assertions require complete regional coverage and independent trait samples; they must describe the actual analysis. This route requires converged full-likelihood multi-effect fits, uniform marker priors and the same complete LD reference. It consumes stored component evidence without fitting or eigen computation. LD files must remain available for checked purity calculations. H0–H4 probabilities belong to individual component pairs, not the entire region. Inactive, low-purity, incomplete and duplicate components remain labelled; no eligible pairs is not evidence for H0. Summaries and plots of completed results work from saved R objects without accessing LD files.

OLS beta/SE/n preparation is available through gmap_stat(); see below and the worked simulation tutorial. No cross-reference or overlapping-sample colocalisation is exposed.
