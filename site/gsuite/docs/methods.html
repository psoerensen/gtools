Methods

Choose a gsuite analysis, find its interface and check availability and limits.

Start with the scientific task below, then follow its workflow guide. This page is a directory; detailed algorithms, execution routes and evidence remain in the Methods reference.

Capability overview

The experimental direct SumHer workflow adds gbase::gprep(task = "ldscores") and gcorr::gcorr(Glist, stat, method = "sumher") for single- and multiple-trait analyses. Direct scores are accumulated without saving pairwise LD to disk. SumHer returns h2 per trait and rg for every pair; the previous estimator remains available explicitly.

For a guided introduction, use the standalone package tutorials. The connected genomic example shows how selected analyses fit together; it is not a demonstration of every supported combination.

Standalone mixed-model preparation supports sparse fixed-effect certification for large categorical factors, including prepared herd-year levels. See the model guide for the unchanged formula syntax and limits. The development LMT preparation commands separately convert four-trait input data and translate a restricted ssSNPBLUP directive profile. Real-valued exports use scientific notation with bounded mantissas; manifest binding requires the corresponding recorded numeric encoding. LMT comparison is qualified only by the documented tiny four-trait test; the simulation’s independent genomic ridge currently blocks directive generation. Positive pedigree blending with sample-mean centered pedigree-moment adjustment supports an optional stochastic preconditioner diagonal for supplied-covariance ssSNP prediction. It retains exact model operations and original-residual gates; probe count affects setup cost and iteration count rather than the covariance model. The adjusted pedigree blend can be translated; an optional small live-LMT check compares adjustment coefficients and the implied blended genomic matrix against an independent reference.

The development DMU converters translate supported ASCII DIR models into that interface and export its ordinary pedigree/identity linear-model subset back to DMU. Conversion acceptance is separate from fit and live DMU numerical qualification.

Check availability first

The six-interface gbayes contract defines the development R API. All 24 initial method/interface combinations are implemented within their documented route and native limits. Development bayes() and mbayes() expose packed individual BayesC/BayesR with direct controls and common results. These C/R routes require complete outcomes. Development sbayes() and msbayes() expose marginal-summary BayesC/BayesR through the existing scalar/joint samplers and the same fit contract. Scalar LD may be sparse or block-eigen; joint LD is sparse, with explicit independent or shared-LD sampling. Summary prediction, joint block-eigen, dense X and other unqualified input types remain gated. Capture is method-specific. Individual C/R bayes/mbayes supports exact continuation from full native checkpoints on the same qualified bundled build. Global thinning, chain seeds and learned states are preserved; resumed summaries cover the added segment. Input/resource bytes and runtime fingerprints are checked. See the continuation contract. Summary C/R sbayes/msbayes now supports the same exact native continuation semantics on its existing sparse/scalar-eigen and joint sparse likelihoods. Checkpoints bind harmonized summaries, prepared LD bytes and sampling/provider policies; added-segment summaries preserve existing scientific limits. See the summary contract. Cross-product C/R blr/mblr also supports exact same-build continuation using existing native states. Checkpoints bind checked cross-products, labels, n, coding and likelihood dimension. Global thinning and added-segment summaries match the other C/R routes; supplied feature units and prediction gates remain. See the cross-product contract. Individual C/R bayes/mbayes also exposes optional reference genetic covariance, partition activity/covariance and selected genetic-score uncertainty through posterior. These are retained-draw quantities, with explicit reference/coding, bounded storage and separate quantity summaries. Full effect draws, phenotype predictive noise and remaining interface capture routes are not enabled. See the capture contract. Summary C/R sbayes/msbayes also exposes reference genetic covariance/correlation, partition activity/covariance and explicit-denominator h2 through posterior. Reporting uses an explicitly supplied aligned reference, separately from fitting LD/eigen policies. Capture preserves states/RNG and added-segment semantics; summary prediction remains unavailable. See the summary capture contract. Cross-product C/R blr/mblr also captures component covariance/correlation, feature-partition quantities and explicit-denominator variance ratios. The reference=“training” request uses checked XX / likelihoodDimension in supplied feature coordinates, without inferring LD or genetic interpretation. Capture preserves states/RNG and continuation semantics; ordinary feature prediction keeps its saved-coding gates. See the cross-product capture contract. Scalar bayes() and block-eigen sbayes() now support bayesRC, algorithm=“mcmc”, with aligned component annotations and existing native probit-stick updates. Pi-derived starts are separate from Gaussian priors; updatePi learns annotation probabilities without a global Dirichlet update. Summary global updateE stays FALSE, with explicit separate block-scale controls. Joint/cross-product RC and full sblr algorithm/output parity remain unavailable. Sbayes additionally exposes point_normal and continuous_shrinkage, algorithm=“mcmc”, on common-N sparse-LD inputs. Logical chains run serially with shared preparation. Point-normal requires nthin=1 and preserves native conditional means; shrinkage requires verified Glist blocks and exposes local/ global/residual scale means. Unsupported moments and diagnostics remain unavailable. Sbayes variational and mixture_variational, algorithm=“vbayes”, expose the existing fixed-prior summary optimizers. Direct pi/h2 or absolute vb/pi settings, memory/disk LD, ordered windows and common variational effect moments retain their native meanings. Windowed results and relative objective endpoints are labelled explicitly; no chains, learning or absolute likelihood bounds are inferred. Development blr() and mblr() implement exact labelled common-design cross-products for BayesC/BayesR, with feature-scale calibration, full Gram validation and optional saved-transform dense prediction. Residual learning requires exact response scatter and likelihood dimension. The old scalar blr signature is replaced without compatibility aliases. A shared result boundary validates schema, effect axes and chain identities, records software versions and makes unavailable quantities explicit. Native statistical and qualification limits remain unchanged.

Development bayes(), mbayes(), blr() and mblr() accept method="bayesCM", with algorithm="vbayes" and common variational bayesfit results. Packed individual and labelled exact/RSS cross-product inputs reuse existing native methods. Dictionary matrices are fixed; weights and supported diagonal/full residual covariance may be learned. Joint missing outcomes use the published route. Scalar packed complete fits require bounded dense Gram storage; scalar packed missing outcomes and dense X are unqualified. CM uses native n normalization and no MCMC chains/draws. See the workflow for applicable arguments and availability.

Development mbayes() also supports bayesFA and bayesFR, algorithm=“mcmc”, using existing native methods. FA constructs its additive relationship internally from Glist and normalizes mean diagonal to one. FR preserves native marker-factor/ direct effects and per-draw total-effect reconstruction. Both support outcome masks, serial chains and common invariant summaries, with unchanged bounded qualification. Full-model MegaBayesC mixing remains unresolved and paused. New-kernel FA prediction, continuation and parallel factor chain workers are unavailable.

The existing development gbayes() facade accepts method="bayesCM", with algorithm="vbayes" (the method-specific default), for covariance-mixture regression using existing mr.mash numerical routes. Individual phenotype tables with Glist/trait inputs have training-only working covariance defaults; advanced matrices and explicit RSS inputs retain their validation and scientific limits. This is an R interface addition, not a new sampler, learned covariance dictionary or public release. MCMC/EM combinations are rejected; historical methods retain their defaults.

gbayes(method="bayesFA") selects the existing Bayesian factor-analytic mixed model with an explicit relationship kernel. gbayes(method="bayesFR") selects the existing Bayesian marker factor regression with marker-to-factor, loading and direct effects. Both default to algorithm="mcmc" and accept the familiar sampling arguments. Their existing priors/defaults and historical method names remain compatible; these names do not introduce new numerical algorithms.

Native development gbayes includes a bounded one-kernel MegaLMM factor sampler with supplied outcome masks, horseshoe loading shrinkage, variance-grid updates and invariant covariance/prediction diagnostics. It is a separate MCMC backend. A separate native MegaBayesC marker sampler includes marker-to-factor and direct effects, sparse loadings and learned inclusion/slab/order and residual scales. Independent exact small-model posteriors and pinned reference software qualify the bounded dense route. Marker-factor, direct and loading activity remain distinct; total effects are reconstructed per draw before prediction. Multiple kernels and high-dimensional performance/calibration remain unqualified. Both factor samplers are bounded to 256 samples, 128 traits and 16 factors; bayesFR/MegaBayesC also limits markers to 4096. Packed support remains resident, new-kernel bayesFA prediction is unavailable, and full-model MegaBayesC mixing remains unresolved. No arbitrary fixed covariates or continuation are added. There are development R/YAML interfaces in the standalone gbayes package: gbayes_multitrait() and gbayes_yaml() share the same validated dispatcher.

Native development gbayes includes supplied-dictionary mr.mash-rss and complete-data individual mr.mash: common-sample multivariate variational regression with singular covariance-mixture priors, optional weight learning and genetic-score prediction. Complete dense/packed BED data and exact C,S,H support optional full/diagonal residual-covariance empirical Bayes; reference-LD approximations retain fixed V. Individual preprocessing centers both genotypes and outcomes on training samples; an additive missing-outcome route implements the published conditional imputation/intercept schedule with covariance/entropy corrections and an augmented variational bound. Joint arbitrary fixed-covariate estimation remains outside this route; missing-data inference does not use imputed C,S,H as if all outcomes had been observed.

The development R/YAML adapters cover these five native routes with labelled dense matrices, supplied covariance dictionaries, explicit RSS likelihood and saved training coding for prediction. They are absent from the published gbayes 0.1.1 archive. See Bayesian regression for inputs and retained scientific limits. Individual mr.mash and MegaBayesC also accept validated Glist/PLINK references without forming decoded genotype matrices or marker Gram matrices. Training sample/marker subsets and their order remain explicit. mr.mash BED uses HWE coding; MegaBayesC retains sample-SD or centered-raw coding. Missing genotypes and target scores use saved training frequencies. Native dimension and memory limits remain; packed support is not genome-wide performance qualification. Exact sufficient statistics and reference-LD approximations are declared separately. Bounded numerical and reference-software checks do not establish population calibration or biobank performance. Existing BayesC/BayesR methods retain their own contracts.

Development standalone executables disable licence enforcement by default; enforcement can be enabled explicitly at build time. This does not change the statistical methods or qualify a commercial distribution. See installation requirements.

The development standalone runner selects Linux native thread placement from the permitted CPU topology and records its choices. Inherited NUMA policy is preserved by default; optional interleaving is a resource experiment, not a change to the statistical method. See CPU and NUMA placement.

The seven genomic R packages are public source releases, but a guide may also describe newer development interfaces. In particular, the public gbayes/gsea 0.1.1 archives lack the BLR and set-summary additions documented for gbayes 0.1.6 and gsea 0.1.2. Check the release-status table, packageVersion() and installed help before copying an example.

Mixed-model R examples use the development integration. A root gsuite R package release is not planned; greml/gsolve R packaging is deferred. The standalone command has its own installation requirements. For an exact mixed-model combination, the model catalog is authoritative; support in one route does not establish support in another.

What the evidence establishes

A capability implemented in development code is not necessarily a released interface or a broadly qualified analysis. Read each workflow’s supported inputs, assumptions and limits. The validation pages report the checks actually performed; the current qualification limits retain unresolved issues. Numerical agreement does not by itself establish statistical calibration, convergence or performance at your data scale.

Supplied-design Gaussian BOA reference

Native gbayes now provides bounded fixed-covariance Gaussian BOA regression with explicit dense ancestry-specific designs, exact joint posterior moments, same-response marker conditionals and genetic prediction. The caller supplies centred designs and a pre-adjusted response; fixed effects are not jointly fitted. Diagonal and full SPD ancestry priors are supported. This is a native numerical reference (at most 256 effects), with no R interface, packed ancestry operator, ancestry inference, covariance learning, scalable or routine BOA prediction claim. See the component gbayes/docs/boa-gaussian.md contract and development evidence. Implementation and focused numerical validation do not establish population-level scientific calibration, broader qualification or release status.

Ancestry-aware phased genotype operations

Native gbits now provides D, C, D-C*p, forward/transpose products and marker-wise information/residual updates over existing packed H1/H2 and known ancestry labels. Native gmat binds these operations to sample/marker/allele identities, declared phase alignment and training centring frequencies. Inputs use byte ancestry labels; resident labels are now bit-packed; no dense ancestry-expanded matrix or genomic relationship matrix is used by these operations. Missing genotypes, unknown/probabilistic ancestry and unphased dosage are unsupported; no automatic inference, harmonisation or imputation is performed.

Focused explicit genotype arithmetic checks and small gbayes integration examples are distinct from large-scale or scientific qualification. The existing dense BOA fitter remains bounded to 256 effects. Genotype operations alone do not establish a packed fitter, label persistence/streaming, R/YAML interfaces or biobank-scale qualification; the Gibbs route below has separate evidence. See component gbits/docs/design/ancestry_operations.md, gmat/docs/ancestry-panel.md and gbayes/docs/boa-gaussian.md for contracts, resource bounds and method-specific evidence. No release is implied.

Packed fixed-covariance Gaussian BOA sampling

Native gbayes now supplies a systematic marker-block Gaussian Gibbs route over existing gbits/gmat ancestry operations. It maintains one phenotype residual, reuses exact fixed-prior Gaussian conditionals, caches small within-marker covariances, accumulates marginal moments/selected covariance pairs, and supports selected sampling diagnostics, in-memory continuation and ancestry-specific genetic predictions with unchanged training centring. It does not allocate a dense ancestry-expanded design or complete joint marker-effect covariance.

The response is explicitly pre-adjusted and identity-aligned; fixed effects and variances are not learned. Execution remains serial; the initial byte-label storage assessment is superseded by bounded resident bit-packing measurements described below. Small dense-posterior comparisons with Monte Carlo uncertainty and existing regression checks are separate from routine large-panel, mixing/population and scientific qualification. There is no R/YAML interface or release claim. See component gbayes/docs/boa-packed-gibbs.md and its development evidence for contracts, resource bounds and limits. The bounded dense BOA reference remains unchanged.

Gaussian BOA robustness and resident label memory

Controlled native examples now cover ancestry-column aliasing, strong LD, ancestry imbalance and a rare counted allele at frequency .004. Direct conditional and residual checks remain numerically accurate, but LD marker contrasts remain poorly mixed after the tested continuation. Good selected prediction diagnostics do not qualify individual effect covariance estimates or covariance learning. Unsuccessful and inconclusive sampling outcomes are retained in component evidence.

Native gbits now bit-packs resident deterministic labels behind unchanged byte constructor inputs and gmat identity contracts. Bounded measurements show 8x label payload reduction for K=2 and 4x for K=3, with increased CPU cost and unchanged byte-import peak limitations. No new file format, statistical prior, covariance learning, streaming interface or routine biobank-scale qualification is added. See gbayes/docs/boa-robustness.md and gbits/docs/design/ancestry-storage-evidence.md for conditions, measurements, regressions and limits. Earlier validation/release boundaries remain distinct.

Bounded joint-marker Gaussian BOA updates

Native gbayes adds an opt-in fixed marker partition for exact joint Gaussian updates of coupled ancestry effects, using the existing conditional factorization, shared residual, packed marker decoding, summaries, diagnostics and prediction contracts. No more than 64 effects per block or 256 decoded sample rows are used in temporary design calculations. The original sampler and public structure layouts remain available with their established numerical and RNG update branch.

The fixed posterior, input identities and training centring are unchanged. The caller chooses blocks; correlations crossing block boundaries can still limit exploration. Conditional accuracy, Monte Carlo precision, measured resource cost and scientific qualification are recorded separately in gbayes/docs/boa-blocked-gibbs.md. This adds no covariance learning, automatic LD grouping, R/YAML interface, routine large-panel qualification or release claim.

In controlled duplicated-marker examples, keeping that pair together restores the weak contrast variance and substantially increases its effective sample count; splitting the pair remains unsuccessful. Independent Gaussian references and same-build continuation checks support the bounded update. This does not qualify unknown or long-range LD structures, larger partitions or covariance learning. Original unsuccessful evidence remains preserved.

LD-informed Gaussian BOA scheduling

Native gbayes adds fixed bounded partitions derived from an identity-checked gmat sparse LD resource, with optional BOA design scoring for explicitly supplied candidate pairs. Ancestry-specific likelihood-column correlation can differ from ordinary genotype LD. The builder reports strong supplied edges that cross the chosen groups and those left without a scheduled joint visit.

An opt-in route performs fixed cross-boundary Gaussian conditionals at recorded global sweep intervals, reusing the existing posterior and shared-residual calculation. Blocks retain the 64-effect ceiling and bounded sample decoding. The existing manual and single-marker interfaces remain unchanged. Missing graph edges, limited bridge budgets, collective LD and unverified large panels remain explicit limitations. This adds no covariance learning, adaptive priors, R/YAML layer or release qualification. Component contracts and method-specific evidence are in gbayes/docs/boa-ld-partitions.md.

Controlled fixed-covariance examples show improved exploration when a missing minor-ancestry dependence is represented and jointly visited. Collective LD directions still defeat the tested pairwise graphs and limited bridge budgets. Independent Gaussian references and exact continuation support the numerical transition; general partition robustness and covariance learning remain unqualified.

Matrix-free Gaussian BOA inference

Native gbayes now offers an opt-in prior-whitened precision operator over the existing packed ancestry products, deterministic posterior-mean solves and global Gaussian draws using randomized right-hand sides and gsolve PCG. The fixed-covariance, pre-adjusted-response model, sample/marker identities and training centering are unchanged. No genome-wide dense design, cross-product, precision or posterior covariance is formed.

Finite iterative solves produce numerically approximate draws. Independent bounded Gaussian references, tolerance/conditioning checks, selected posterior diagnostics and computational observations remain distinct from scientific or large-panel qualification. Existing single-marker, blocked and boundary routes remain available with their earlier mixing limitations. See component gbayes/docs/boa-packed-global.md for native contracts and evidence. This adds no covariance learning, ancestry inference, R/YAML integration or release claim.

Focused Gaussian reference and posterior comparisons support the selected known-phase LD, ancestry-imbalance and mosaic examples. Extreme-conditioning checks retain rejected covariance solves and inaccurate loose-tolerance draws. A bounded resource observation confirms small operator storage but substantial repeated genotype traversal cost; it does not establish routine large-panel use.

Block preconditioning for global Gaussian BOA inference

Native gbayes provides an opt-in bounded block preconditioner for the same complete prior-whitened Gaussian precision. Supplied disjoint marker blocks reuse installed gsolve factors; cross-block terms remain in every full operator application. The diagonal default, Gibbs routes and training-centering contracts remain available. No automatic block construction or posterior approximation beyond the existing finite solve tolerance is added.

Independent bounded references support means, covariance products, identical-normal draws, prediction, residual reconstruction and tagged continuation. Selected LD/ancestry cases and one 4,096-sample, 2,048-marker resource observation show benefits including setup costs; a poor extended-LD partition instead increased solve time. These observations establish neither universal speedup nor routine large-panel qualification. See component gbayes/docs/boa-block-preconditioning.md for the construction, evidence and costs. Earlier conditioning and partition failures remain applicable; global covariance learning and release remain unqualified.

Hierarchical Gaussian BOA covariance learning

Native gbayes provides an opt-in blocked Gaussian route with a shared inverse-Wishart SNP-effect covariance and fixed residual variance. It reuses packed known-ancestry designs, exact Gaussian conditionals, shared-response residual updates and existing diagnostics. Covariance-dependent factors are rebuilt each sweep; tagged continuation includes the covariance and RNG state. The initial interface supports one to four ancestries and supplied disjoint blocks of at most 64 effects. It has no R/YAML or global-learning interface.

Independent conditional checks and bounded two-ancestry collapsed-posterior references support the implemented route. Prior sensitivity, unobserved ancestry and identical design columns remain identifiability limits. A deliberately poor LD partition failed mixing criteria. The published heavy-tailed prior is supported, with covariance MCSE marked unverified when moment existence is unestablished. Empirical variances and low R-hat do not establish identifiability. See component gbayes/docs/boa-covariance-learning.md for evidence and costs. This bounded capability does not establish routine large-panel qualification, empirical population validation or release; earlier failures remain recorded.

Scientific evidence for Gaussian BOA

A bounded controlled population study compares pooled SNP-BLUP, separate purebred predictions, breed-proportion prediction and native fixed/learned Gaussian BOA. Known ancestry and common supplied centering are retained in future-generation purebred, F2 and backcross targets. Benefits depend on effect heterogeneity and reference composition; pooled prediction is competitive when breed effects are nearly shared. Oracle supplied covariance is distinguished from learned covariance throughout.

The study supports selected synthetic prediction and prior-predictive covariance calibration, while retaining poor boundary/low-variance recovery, prior sensitivity and numerous fits with inadequate Monte Carlo precision. Low R-hat and accurate prediction do not establish covariance identification. Matched-target fixed Gaussian comparisons support bounded blocked, overlapping and global routes; poor LD partitions still fail precision criteria. See component gbayes/docs/boa-scientific-study.md for the frozen design, complete results, costs and qualification decisions. These results establish neither published software parity nor routine large-panel or empirical-population qualification. Production algorithms, native interfaces and public release status are unchanged.

Supplied-tree ARG covariance

An opt-in native gmat adapter provides branch-area covariance products over a supplied dated tree sequence using installed tskit C. Explicit diploid sample-node identities, a fixed training-centering base, a positive normalization and selected training/target actions bind the resource to existing gsolve operators and greml Gaussian inference. Ordinary gmat dependencies and existing estimators are retained.

This bounded native research route has independent local-tree and dense Gaussian references. It adds no genealogy inference, frequency-weighted mutation kernel, R/YAML interface, population prediction calibration, biobank performance qualification or release. See component gmat/docs/arg-covariance.md for the statistical contract, native interfaces, resource costs and executed evidence. A bounded true-genealogy study compares branch-Gaussian, SNP-effect and untyped rare-variant architectures against sparse and denser GBLUP. Prediction differences remain uncertain, combined genetic components are strongly confounded, and fixed finite-probe optimization retains failures. Independent likelihood profiles also expose local or stalled REML solutions. This evidence supports bounded research use, without practical prediction or scaling qualification.

Final ARG status: Implemented and numerically validated for bounded native research use; general predictive advantage, genome-scale performance and routine scientific qualification remain unestablished. Later independent-region references retain 58/192 formally unconverged models despite near-optimal likelihoods; numerical proximity does not replace convergence certification. The research phase is closed, with no R/YAML interface or public release.

Native fixed-score Gaussian environmental moments

The native greml cache computes moments for additive genetic, fixed-score genetic interaction, environmental residual heterogeneity and homogeneous residual components. It retains raw estimates, rank/conditioning and numerical probe diagnostics, without silently repairing deficient systems. It has no R interface or learned-score, interaction-GWAS or prediction workflow. See the owner contract and evidence (unpublished greml contract). Existing longitudinal, factor-analytic and full-package qualification limits remain.

A bounded conditional-Gaussian study (unpublished greml research report) now quantifies fixed-score moment recovery, projected identifiability and sampling variability. Practical sampling uncertainty remains unqualified: oracle references require generating covariance and exploratory plug-in intervals under-cover in selected designs. This adds scientific evidence, with no new R/YAML interface, optimizer or learned-score workflow.

The native cache now also computes Gaussian sampling covariance at an explicitly supplied working state, using packed/matrix-free products. It reports covariance MCSE separately from sampling SE and leaves invalid, unidentified or indefinite trace results unavailable. The bounded uncertainty investigation (unpublished greml research report) compares raw and existing constrained-REML working covariances; numerical success does not establish calibrated applied intervals. Learned-score fitting remains deferred.

The practical uncertainty comparison (unpublished greml research report) reuses frozen reference-derived LD panels at 2,000 and 10,000 individuals. Research-only genomic block jackknife improves availability but undercovers important component and contrast targets; a general practical interval method remains unqualified. The native point estimator and installed interfaces are unchanged; no production jackknife or learned-score capability is added.

Randomized G×E variance-component estimation

This capability implements the GENIE estimator, with original method/software attribution retained. Existing native API names remain unchanged. The separate greml GenieMomentCache supports the genome-wide G+GxE+NxE model with individual supplied exposures, genomic block-jackknife uncertainty and trace-weighted individual/joint fractions. Independent dense and unchanged GENIE comparisons (unpublished greml research report) establish algorithmic agreement on the specified full-rank SPD route. This differs from the earlier fixed-score finite-probe estimator and leaves its behavior/evidence unchanged. GENIE support remains partial: annotations, missing-data parity, original QR rank/failure behavior and exact published p-value-tail provenance remain gaps. Normal-tail diagnostics are explicit rather than asserted published p-values. No R/YAML interface, ENGINE implementation or public release. Further small-scale calibration is stopped; completed diagnostic simulations do not determine the correctness of the original method. See the native contract (unpublished greml contract).
